# Agent 服务化关键决策与未决问题(decisions)

> 决策编号 D* 为已决策(冻结候选,待主对话审查确认);Q* 为未决问题(含倾向与裁决时机)。
> 实现子代理发现约定不可行时,回传 `BLOCKED`(理由 + 证据),由主对话在此裁决并同步更新 docs/design.md。
> 引用核心库决策写作"core D*"(其编号见 docs/6.3 decisions.md,D1–D23)。

## 1. 已决策(冻结候选)

| # | 决策 | 内容 | 理由 |
|---|---|---|---|
| D1 | 文档体系 | 本文档三件套为 7.0 的下游设计与实施文档,与核心库三件套(6.1/6.2/6.3)平行;文件名与内部标题均不带编号 | 6.x 文件内部编号(7.1/7.2/7.3)与外文件名已不一致,不再制造第二层映射混乱 |
| D2 | 模块落位 | `agent/` 独立 Go module(`traincache/agent`),go.mod `replace traincache/core => ../core` | 延续 core D1/D16"独立 module"精神;否决根级 go.work——增加根文件,bench 与 CI 假设保持简单 |
| D3 | 三个可执行产物 | `traincache-agentd`(Go,DaemonSet)、`traincache-ordersrc`(Python sidecar)、`traincache`(Go CLI) | sidecar 的顺序语义必须与真实 loader 的 shuffle 一致(torch / webdataset RNG),Python 直接复用训练生态,Go 复刻 RNG 风险高;共享内存协议语言中立(design §6.2) |
| D4 | 包结构与依赖方向 | design §4 目录树;cmd → svc → 子模块 → core 单向无环;子模块互不依赖;ordersource 不依赖 core | 与 core"单向无环"同风格,子模块可并行派活 |
| D5 | 端口 | gRPC 9410、/metrics 9411(非特权端口,env 可配) | 避免 root 端口;固定默认值保证 CLI / 探针 / 抓取一致 |
| D6 | gRPC 服务划分 | 南向 PreheatService + NodeService;北向 ReportService(ReportBlocks 流)proto 随本设计冻结,服务端实现推迟至 Controller 里程碑 | 7.0 验收只含南向;北向方向性(谁拨号)依赖 Controller 设计(Q1),先冻结契约不阻塞 |
| D7 | 任务寻址与状态机 | 任务引用 =(dataset, snapshot_id, prefixes, chunks);chunk 用 core (path, chunk int64);状态机 QUEUED / RUNNING / DONE / ERROR | 7.0 CLI 状态只列"进行中/等待/错误",补齐 DONE 状态机才完备;复用 core 寻址,不发明第二套 |
| D8 | 节点标识 | env `NODE_NAME`(fieldRef spec.nodeName)权威,启动校验非空;所有状态与指标带 node | 7.0 要求"唯一确定自身所在 K8s 节点并在状态上报中携带节点标识";Downward API 是标准做法 |

| D10 | 阶段切换三源归一 | epoch / shuffle / curriculum 统一为 sidecar 推送新 ConsumeOrder;7.0 留空的 curriculum 事件源 = sidecar 获训练进程通知后重算顺序;Agent 不区分三源 | 归一后 Agent 只剩一种切换语义(design §5.3),curriculum 检测复杂性隔离在 sidecar |
| D11 | 钩子通道 | Unix datagram `/run/traincache/agent.sock`,行分隔 JSON 三帧型(advance / stage_switch / open_report),单向不回复;顺序主源 = sidecar,钩子只报位点与打开块 | 7.0 要求钩子调用 PersistentPrefetcher 方法;单向 datagram 免连接管理,丢帧靠 inotify 旁路兜底 |
| D12 | core 增量(cas Quarantine) | 契约见 design §5.7;由核心库文档流程落地(6.3 新增决策,编号顺延),plan.md M0 引用 | 7.0 明示"需要增加标记位";归属 core 是职责边界——服务化层不重复实现存储逻辑 |

| D14 | 热度参数默认值 | N=24h、M=30min、T=24h(因子 0.5)、k=80%、Δ=5%、M=90%;全部 env 可配;数值待 bench 校准 | 7.0 只给示例值;先取可实现默认,校准留 bench 装置 |

| D17 | 指标清单与命名 | design §5.8 六线 family 表;dataset / node / result / endpoint / priority 进标签;dataset 白名单外记 other;固定 bucket;高基数进日志 | 7.0 基数控制三原则;清单化便于验收 7 逐项核对 |

## 3. 决策变更流程

沿用 core 6.3:

1. 实现子代理发现约定不可行/不合理 → 回传 BLOCKED(理由、证据、建议)→ 不动代码;
2. 主对话裁决:采纳 → 更新 docs/design.md + 本文档(旧编号保留,新决策顺延编号)→ 重新派活;否决 → 说明理由,子代理按原约定继续;
3. Q* 结案时:在本文档 §2 表格中登记结论与日期,必要时升级为 D* 或修改 design.md。
