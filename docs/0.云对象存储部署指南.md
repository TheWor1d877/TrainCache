# TrainCache 云对象存储部署指南

## 0. 为什么要换

TrainCache 的架构从一开始就是 **S3 兼容对象存储上的训练数据预热系统**，core 层只认 `objectstore.Store` 接口，不绑定具体后端。本地开发时用 MinIO 是因为它免费、快、完全可控，适合 kind 集群里做 bench 扫点实验。但真实训练任务的数据本来就躺在云上——腾讯云 COS、阿里云 OSS、AWS S3——不会有人专门把数据迁到自建 MinIO 上再训练。所以从"本地演练"切到"真实测试"时，对象存储后端要跟着换。

这步切换对代码**零侵入**：所有后端差异都被 `Store` 接口和 minio-go SDK 吃掉了，只需要把环境变量换成对应云厂商的值。

## 0.1 前置知识：minio-go SDK 是什么

代码里出现了 `github.com/minio/minio-go/v7` 这个 import 路径，名字里带 minio 很容易让人误以为"TrainCache 跟 MinIO 深度耦合"。这里一次性讲清楚。

### MinIO 公司开源了三样东西

| 项目 | 是什么 | 跟 TrainCache 的关系 |
|---|---|---|
| **MinIO Server** | 对象存储服务本身（Go 写的），Docker 镜像 `minio/minio` | 本地开发演练跑在 kind Pod 里，端口 9000 |
| **minio-go SDK** | Go 语言的 S3 客户端库，GitHub 仓库 `github.com/minio/minio-go` | `core/objectstore/s3.go` 直接 import 它 |
| **mc** | 命令行 S3 客户端，类似 aws-cli 但更轻 | 验证条件写时用 `mc alias set` / `mc ls` |

三个都是 MinIO 公司开发并维护的，但定位完全独立。minio-go SDK 是纯粹的**客户端库**——它只负责发 HTTP 请求，不存数据、不跑服务端。

### minio-go SDK 本质上是什么

S3 API 是一组 REST 接口（GET/PUT/DELETE 带 AWS V4 签名头）。minio-go SDK 做的事情就是把这些 HTTP 请求封装成 Go 方法调用，帮你处理：

- **AWS V4 签名**——每次请求要根据时间戳、SecretKey 算 HMAC 签名头，SDK 自动算
- **path-style vs virtual-hosted-style**——不同 S3 实现的 URL 格式不一样（本地 MinIO 用 `endpoint/bucket/key`，AWS S3 用 `bucket.endpoint/key`），SDK 自动判断 endpoint 域名选对的格式
- **错误码映射**——服务端返回的 XML 错误码（`NoSuchKey`、`PreconditionFailed`、`Conflict`）自动映射成 Go error
- **条件写**——`PutObjectOptions.SetMatchETag()` / `SetMatchETagExcept()` 分别对应 HTTP `If-Match` / `If-None-Match` 头，SDK 帮你拼请求

### 名字里带 minio，但通吃所有 S3 后端

这点最重要。SDK 层完全不知道服务端是谁——它只知道"我发了一个带签名的 HTTP 请求到某个 endpoint"，至于对方是 MinIO、COS、OSS 还是 AWS S3，那是服务端的事。

```go
// 这三行代码，endpoint 换成任何 S3 兼容后端都能用，SDK 行为一致
client, err := minio.New(endpoint, &minio.Options{
    Creds:  credentials.NewStaticV4(accessKey, secretKey, ""),
    Secure: secure,
})
```

| endpoint | 实际连的 | minio-go 发的请求 | 响应方 |
|---|---|---|---|
| `127.0.0.1:9000` | 本地 MinIO Pod | 标准 S3 REST API | MinIO Server |
| `cos.ap-guangzhou.myqcloud.com` | 腾讯云 COS | 标准 S3 REST API | COS 服务端 |
| `oss-cn-hangzhou.aliyuncs.com` | 阿里云 OSS | 标准 S3 REST API | OSS 服务端 |
| `s3.ap-northeast-1.amazonaws.com` | AWS S3 | 标准 S3 REST API | AWS S3 |

minio-go GitHub README 第一行就写着 "MinIO Go Client SDK for Amazon S3 Compatible Cloud Storage"——明确说是 Amazon S3 兼容云存储，不是 MinIO Server。名字里的 minio 是品牌名，不是功能限定。

### 为什么不用 AWS 官方 SDK

| 对比项 | minio-go v7 | AWS SDK v2（S3 模块） |
|---|---|---|
| 体积 | 一个模块，依赖少 | 整个 AWS SDK 很大，S3 模块依赖更多 |
| S3 兼容覆盖 | **最全**——很多边缘 S3 实现（MinIO、SeaweedFS、CDN 网关）AWS SDK 不认 | 只保证 AWS S3 完全兼容，非 AWS 后端覆盖不如 minio-go |
| 条件写支持 | **一级封装**——`SetMatchETag()` 直接调，我们的 `PutIfMatch` 就用这个 | 要手动在 `PutObjectInput` 里拼 `IfMatch` 字符串 |
| 训练缓存场景 | 6 个 Store 方法全覆盖 | 也能覆盖，但写法更啰嗦 |

### 面试说法

> TrainCache 的对象存储层用的是 minio-go——MinIO 公司开源的 Go 语言 S3 客户端库。名字里带 minio 是品牌，但它连任何 S3 兼容后端都通吃。我们本地开发用 MinIO 做 bench 扫点，真实测试直接换 COS 或 AWS S3，endpoint 一改就行，代码零侵入。minio-go 的优势是对 S3 条件写有一级封装（`SetMatchETag`），正好是我们 CAS 提交和孤儿清理用的。

## 1. 六个环境变量逐项解释

Agent 进程启动时从环境变量里读这六个值，代码在 `agent/svc/config.go` 的 `Load()` 函数里解析。全部参数都有默认值，缺省行为是连接本地 MinIO（`127.0.0.1:9000`、空凭证、单桶 `traincache`、HTTP 不加密）。

### 1.1 `TRAINCACHE_OBJSTORE_ENDPOINT` — 对象存储端点

**格式**：`主机:端口` 或云厂商域名，**不要带 `http://` 或 `https://` 前缀**——协议由 `SECURE` 变量单独控制。

minio-go SDK 会根据 endpoint 的域名自动判断 S3 路径风格：本地 MinIO 默认 path-style（`endpoint/bucket/key`），云厂商默认 virtual-hosted-style（`bucket.endpoint/key`）。这个判断你不用管，SDK 自动处理。

| 场景                   | 值示例                                                               |
|------------------------|----------------------------------------------------------------------|
| 本地 MinIO（开发演练） | `127.0.0.1:9000` 或 `minio.internal:9000`（kind 集群内 Service DNS） |
| 腾讯云 COS（广州）     | `cos.ap-guangzhou.myqcloud.com`                                      |
| 阿里云 OSS（杭州）     | `oss-cn-hangzhou.aliyuncs.com`                                       |
| AWS S3（东京）         | `s3.ap-northeast-1.amazonaws.com`                                    |

**默认值**：`127.0.0.1:9000`（本地 MinIO 边车约定，见 D26）

### 1.2 `TRAINCACHE_OBJSTORE_ACCESS_KEY` / `TRAINCACHE_OBJSTORE_SECRET_KEY` — 鉴权凭证

S3 体系里所有操作都是客户端用 AccessKey/SecretKey 签名请求的。腾讯云叫 SecretId/SecretKey，阿里云叫 AccessKeyId/AccessKeySecret，AWS 叫 AccessKey ID/Secret Access Key——本质上都是 S3 AccessKey/SecretKey 二元组。

**默认空串（= 匿名）**：因为默认 endpoint 是本地 MinIO，可以开匿名读；而且 Agent 用到的六个操作（Get/Put/Delete/GetETag/PutIfMatch/List）都是普通客户端 API，不需要管理员权限。

**安全警告**：凭证绝不能明码写在 Pod spec 的 env 里，应该用 K8s Secret 挂载——见第 3 节。

### 1.3 `TRAINCACHE_OBJSTORE_BUCKET` — 使用哪个桶

v1 约定单桶（D26/Q5 裁决），所有数据都放这一个桶里，用对象键前缀隔离不同 dataset：

```
traincache/<dataset>/blocks/<path>#<chunk>           ← 数据块
traincache/<dataset>/snapshots/<id>/manifest.json    ← 索引 manifest
traincache/<dataset>/snapshots/<id>/shard-<fp>.idx   ← 索引分片
traincache/<dataset>/readers/<nodeid>.json            ← 读者心跳声明
traincache/<dataset>/snapshots/CURRENT               ← 当前快照指针
```

**默认值**：`traincache`

**为什么单桶就够**：S3 的 prefix 天然支持逻辑隔离，桶级别隔离带来的运维复杂度（桶数量配额、桶生命周期策略难统一、跨桶枚举麻烦）在 v1 场景下完全没必要。如果将来真要一 dataset 一桶，在上层 Controller 里加 `bucketPerDataset` 映射表就行，`Store` 接口签名不动。

### 1.4 `TRAINCACHE_OBJSTORE_SECURE` — 用 HTTP 还是 HTTPS

true = HTTPS，false = HTTP。走 minio-go SDK 的 `secure` 参数。

**默认假值**：以下取值视为 true（大小写不敏感、带空格也行）：
```
"1"  "true"  "TRUE"  "yes"  "Yes"  " YES "
```
空串、垃圾值、未设置一律 false。

云厂商生产环境**必须开 HTTPS**，否则请求会被云侧 WAF 拒绝。

### 1.5 `TRAINCACHE_OBJSTORE_PROBE_CONDITIONAL_WRITE` — 装配期条件写探测

开关。设为 true 后，Agent 进程启动时会向对象存储发一次探测请求：写一个临时 key，然后用不匹配的 ETag 调 `PutIfMatch`，期望返回 412 冲突。如果返回 nil（后端默默地覆盖了），说明这个 S3 实现不支持条件写，Agent 会**告警但不阻止启动**——条件写是 CAS 提交和孤儿清理的依赖，但不支持时有回退路径（乐观写 + 读回校验 + 冲突重试）。

探测结果写入 Prometheus 指标 `traincache_objectstore_conditional_write_supported`，取值 0（不支持）或 1（支持）。

**默认 false**：本地开发时不需要每次都探测，省下一次额外请求。上公有云建议开。

| 区域 | endpoint                       |

| 上海 | `oss-cn-shanghai.aliyuncs.com` |

## 3. 凭证配置（**重要**：绝不能明码写 env）

### 3.1 坏的做法（不要）

Pod spec 里直接写死密钥——任何能 `kubectl describe pod` 的人都能看到，而且 YAML 提交到 Git 就永远丢不掉了：

```yaml
containers:
- name: traincache-agentd
  env:
  - name: TRAINCACHE_OBJSTORE_ACCESS_KEY
    value: "AKIDxxxxxxxxxxxxxxxxxxxxx"  # ❌ 明码！
  - name: TRAINCACHE_OBJSTORE_SECRET_KEY
    value: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"  # ❌ 明码！
```

### 3.2 好的做法（K8s Secret）

第一步，base64 编码凭证（K8s Secret 的值要求 base64）：

```bash
echo -n "AKIDxxxxxxxxxxxxxxxxxxxxx" | base64
# 输出：QUtJRHh4eHh4eHh4eHh4eHh4eHh4eHh4eHg=
echo -n "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" | base64
# 输出：eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHg=
```

第二步，创建 Secret（写一个文件或者直接命令行）：

```yaml
# secrets.yaml（写完 apply 后建议立即删除，或加到 .gitignore）
apiVersion: v1
kind: Secret
metadata:
  name: traincache-objstore-credentials
  namespace: traincache
type: Opaque
data:
  access-key: QUtJRHh4eHh4eHh4eHh4eHh4eHh4eHh4eHg=
  secret-key: eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHg=
```

```bash
kubectl apply -f secrets.yaml
rm secrets.yaml  # 删文件，别留痕迹
```

**更安全的方式**——直接用 kubectl 创建，避免写文件：

```bash
kubectl create secret generic traincache-objstore-credentials \
  --namespace traincache \
  --from-literal=access-key='AKIDxxxxxxxxxxxxxxxxxxxxx' \
  --from-literal=secret-key='xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx'
```

第三步，Pod spec 里用 `valueFrom.secretKeyRef` 引用：

```yaml
containers:
- name: traincache-agentd
  env:
  - name: TRAINCACHE_OBJSTORE_ACCESS_KEY
    valueFrom:
      secretKeyRef:
        name: traincache-objstore-credentials
        key: access-key
  - name: TRAINCACHE_OBJSTORE_SECRET_KEY
    valueFrom:
      secretKeyRef:
        name: traincache-objstore-credentials
        key: secret-key
  - name: TRAINCACHE_OBJSTORE_ENDPOINT
    value: "cos.ap-guangzhou.myqcloud.com"
  - name: TRAINCACHE_OBJSTORE_BUCKET
    value: "my-train-data"
  - name: TRAINCACHE_OBJSTORE_SECURE
    value: "1"
  - name: TRAINCACHE_OBJSTORE_PROBE_CONDITIONAL_WRITE
    value: "yes"
```

### 3.3 本地开发怎么安全传凭证

本地跑 Agent（不是 K8s Pod）时，环境变量直接写在 shell 里就行——因为进程只在你机器上跑，密钥不会泄露到网络或 Git 里。但**不要把密钥写进 `.bashrc`**：

```bash
# 单次 shell 会话有效
export TRAINCACHE_OBJSTORE_ENDPOINT="cos.ap-guangzhou.myqcloud.com"
export TRAINCACHE_OBJSTORE_ACCESS_KEY="AKIDxxxxxxxxxxxxxxxxxxxxx"
export TRAINCACHE_OBJSTORE_SECRET_KEY="xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
export TRAINCACHE_OBJSTORE_BUCKET="my-train-data"
export TRAINCACHE_OBJSTORE_SECURE="1"
export TRAINCACHE_OBJSTORE_PROBE_CONDITIONAL_WRITE="yes"

# 然后跑 Agent 的 main 函数
go run agent/cmd/traincache-agentd/main.go
```

## 4. 最小部署示例

### 4.1 Kubernetes Deployment（完整）

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: traincache-agentd
  namespace: traincache
spec:
  selector:
    matchLabels:
      app: traincache-agentd
  template:
    metadata:
      labels:
        app: traincache-agentd
    spec:
      serviceAccountName: traincache-agent
      containers:
      - name: agentd
        image: traincache/agentd:latest
        imagePullPolicy: IfNotPresent
        env:
        - name: NODE_NAME
          valueFrom:
            fieldRef:
              fieldPath: spec.nodeName
        - name: TRAINCACHE_OBJSTORE_ENDPOINT
          value: "cos.ap-guangzhou.myqcloud.com"
        - name: TRAINCACHE_OBJSTORE_BUCKET
          value: "my-train-data"
        - name: TRAINCACHE_OBJSTORE_SECURE
          value: "1"
        - name: TRAINCACHE_OBJSTORE_PROBE_CONDITIONAL_WRITE
          value: "yes"
        - name: TRAINCACHE_OBJSTORE_ACCESS_KEY
          valueFrom:
            secretKeyRef:
              name: traincache-objstore-credentials
              key: access-key
        - name: TRAINCACHE_OBJSTORE_SECRET_KEY
          valueFrom:
            secretKeyRef:
              name: traincache-objstore-credentials
              key: secret-key
        ports:
        - name: grpc
          containerPort: 50051
        - name: metrics
          containerPort: 9090
        volumeMounts:
        - name: cache-root
          mountPath: /var/cache/traincache
        - name: orders-dir
          mountPath: /run/traincache/orders
      volumes:
      - name: cache-root
        hostPath:
          path: /var/cache/traincache
          type: DirectoryOrCreate
      - name: orders-dir
        hostPath:
          path: /run/traincache/orders
          type: DirectoryOrCreate
```

### 4.2 Bucket 必须预先创建

Agent 不会自动创建桶——桶创建是云侧一次性操作，需要你在控制台手动建：

- **腾讯云 COS**：控制台 → "存储桶列表" → 创建存储桶，记录桶名和所在地域
- **阿里云 OSS**：控制台 → "Bucket 列表" → 创建 Bucket
- **AWS S3**：控制台 → S3 → Create bucket

桶建好后，把桶名填进 `TRAINCACHE_OBJSTORE_BUCKET`。

## 5. 验证步骤

### 5.1 连通性检查

Agent 启动后看日志，应该看到类似输出：

```
level=info msg="objectstore connected" endpoint=cos.ap-guangzhou.myqcloud.com bucket=my-train-data secure=true
level=info msg="conditional write probe result" supported=yes
```

如果 endpoint 不通或凭证错了，会在启动时立即报错退出：

```
level=fatal msg="failed to create objectstore client" error="The Access Key Id you provided does not exist in our records."
```

### 5.2 条件写探测结果

开启 `TRAINCACHE_OBJSTORE_PROBE_CONDITIONAL_WRITE=yes` 后，等 Agent 起来 10 秒再看：

```bash
curl -s localhost:9090/metrics | grep conditional_write_supported
# 期望输出：traincache_objectstore_conditional_write_supported 1
```

COS / OSS / S3 三者都完整支持 S3 条件写，指标应该为 1。如果为 0，说明这个 endpoint 不是纯 S3 兼容（比如某些 CDN 代理层不支持），CAS 提交会走回退路径（乐观写 + 读回校验 + 冲突重试）。

### 5.3 手动验证（可选）

用 `mc`（MinIO 命令行工具，纯 S3 客户端，COS/OSS/S3 通吃）直接测：

```bash
# 安装 mc
curl https://dl.min.io/client/mc/release/linux-amd64/mc -o ~/.local/bin/mc && chmod +x ~/.local/bin/mc

# 配置别名
mc alias set mycos https://cos.ap-guangzhou.myqcloud.com \
  "你的SecretId" "你的SecretKey"

# 能列出桶就说明通了
mc ls mycos/

# 手动测条件写：先写一个对象，然后用错误 ETag 调 PutIfMatch
mc put mycos/my-train-data/test-key.txt "hello world"
etag=$(mc stat mycos/my-train-data/test-key.txt --json | jq -r .etag)
# 用完全不同的 ETag 去覆盖，应该返回 Precondition Failed（412）
mc --etag="00000000000000000000000000000000" put mycos/my-train-data/test-key.txt "should fail"
# 期望：ERROR ... Server returned HTTP status 412 Precondition Failed
```

## 6. 最小权限原则（强烈推荐）

给云厂商开的凭证**只授权那一个桶的那六个动作**，不要给 Admin 权限。

### 腾讯云 COS 策略示例

在 CAM 控制台为专用 RAM 用户创建策略，内容如下：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "cos:GetObject",
        "cos:PutObject",
        "cos:DeleteObject",
        "cos:ListBucket",
        "cos:GetBucketLocation",
        "cos:PutBucketPolicy",
        "cos:GetBucketPolicy"
      ],
      "resource": [
        "qcs::cos:ap-guangzhou:uid/你的APPID:prefix//你的桶名/*"
      ]
    }
  ]
}
```

## 7. 常见问题排查

### Q1：Agent 报 "endpoint parse error"

endpoint 格式错了——多写了 `https://` 前缀。minio-go SDK 只收 `host:port` 或纯域名，协议由 `SECURE` 控制。

```bash
# ❌ 错的
export TRAINCACHE_OBJSTORE_ENDPOINT="https://cos.ap-guangzhou.myqcloud.com"
# ✅ 对的
export TRAINCACHE_OBJSTORE_ENDPOINT="cos.ap-guangzhou.myqcloud.com"
export TRAINCACHE_OBJSTORE_SECURE="1"
```

### Q2：Agent 报 "signature does not match" 或 "Access Key Id does not exist"

凭证错了。检查三点：
1. AccessKey 和 SecretKey 有没有对调（腾讯云 SecretId 对应 AccessKey，SecretKey 对应 SecretKey，名字容易混淆）
2. SecretKey 有没有漏字符（复制时不要带空格换行）
3. RAM 用户/策略有没有授权那个桶

### Q3：Agent 报 "bucket does not exist"

桶还没建。云厂商不会自动创建桶——手动在控制台建一个，名字和 `TRAINCACHE_OBJSTORE_BUCKET` 一致。

### Q4：条件写探测结果为 0，但 endpoint 是 COS/OSS/S3

极罕见。三种可能性：
1. endpoint 前面有 CDN 或网关代理，它不转发 `If-Match` 头
2. 桶开了跨区域复制或版本控制，部分实现下条件写行为有细微差异
3. 探测逻辑本身有 bug（跑 `go test -C core ./objectstore/... -v` 看单测）

如果 COS/OSS/S3 直接 endpoint 都返回 0，把日志贴到 GitHub issue 里——三种厂商理论上全支持。

### Q5：本地 MinIO 开发时怎么开匿名访问

MinIO 默认需要认证。如果想让本地 bench 装置不用凭证（方便），启动参数加 `--anonymous` 或者把 AccessKey/SecretKey 设成空串试试（minio-go 对空凭证会发匿名请求，前提是桶 policy 设成 public read）。

## 8. 安全 TODO（留给将来）

当前 `agent/svc/config.go` 的 `Config` 结构体里 `ObjstoreSecretKey` 是普通 string，`fmt.Printf("%+v", cfg)` 或 debug dump 会直接把 SecretKey 打出来。应该加一条脱敏规则：重写 `String()` 方法把 `ObjstoreSecretKey` 替换成 `"********"`。

另外，进程里的环境变量可以通过 `/proc/$pid/environ` 读取——这是 Linux 内核行为，代码层挡不住，只能靠容器隔离和最小权限原则来缓解。K8s Secret 的实现里 base64 只是编码不是加密，Secret 本身不应该存敏感内容（如果要加密用 External Secrets Operator 接 Vault）。
