## 记录规则

新版本在表里新起一行，第一格写版本号，其余格留空，再让 `bench/exp.py run` 跑；启动器只回填最后一行，每跑完一族写一次。版本号由人先写，启动器不看 tag 是否存在。

一族算完成的口径：每个点产物里的有效行数达到 COND 的 `sampling.reps`，且点目录里的 `version` 文件等于当前版本。五组对照看每格：TrainCache 组按上面的口径，对照行取只读的 `baselines/<格名>/summary.csv`，行数达到「组数 × 次数」。作废行不计入行数。

点目录没有 `version` 文件时按未完成处理，换版本后旧产物不会被当成新版本的跑分。补跑某个点后，`python3 bench/exp.py record <族>` 按产物重算该族状态并回填，不访问集群。

族 ID 是 `--family`/`--point` 的寻址名，产物目录名是「数据层分区 + 完整 COND 名」，两者的对应表在 `bench/exp.py` 的 `results_root()`：`compare-groups`→`scores/<格名>/`，图系列四族→`figures/<COND 名>/`，倾斜两族→`policy/<COND 名>/<run ID>/`。分区写错的跑分是「跑完了但出不了图」——`plot.py` 按 `figures/fig*-*` 分流曲面样本、`summarize.py` 只读 `scores/`+`baselines/`，所以落位也进自检。点目录名取自 COND 名的短前缀，短前缀与族 ID 不同名（`startup-surface`→`fig1`、`total-makespan`→`fig2`、`switch-recovery`→`fig3`、`pareto-startup`→`pareto1`、`pareto-sustained`→`pareto2`、`evict-policy`→`policy`），所以 `policy-heat` 的点叫 `heat`。这张表在 `bench/exp.py` 的 `FAMILY_COND_PREFIX`：少一个族，那族就认领不到任何 COND、点目录名退化成空串，几个点会写进同一个目录。`python3 bench/exp.py selftest`（已接进 `make -C bench selftest`）校验每个 COND 被唯一一族认领、点名还原得出原 COND 名、且各族的产物分区落位正确。各族的点、次数与测什么见 [4.3 TrainCache启动与实验](<4.3 TrainCache启动与实验.md>)第 5 节，判据见 [9.2 实验协议](<9.2 实验协议.md>)。
