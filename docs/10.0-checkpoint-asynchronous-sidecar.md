# Checkpoint 异步 Sidecar

本文是设计阶段的底稿，口径与 `10.1-design.md` 的实现契约一致，细节以 10.1 为准。

## 目标与定位

训练程序把 checkpoint 写本地目录，checkpointd 异步搬到持久后端。Pod 重建时 checkpointd 先拉回本地，训练容器再启动。训练镜像不改，接入靠 annotation、环境变量和共享卷。

checkpointd 只搬整份目录并管本地版本，不进读缓存路径。agent 是节点级 DaemonSet，管 CAS 块与读缓存；checkpointd 是 Pod 级进程，管整份目录与后端版本。两者不共享索引、进程和镜像。controller 只在准入阶段注入卷与变量。数据直连后端，不经合并回源网关。

## 角色与分层

| 层   | 执行者                            | 决定                               | 不决定                   |
|------|-----------------------------------|------------------------------------|--------------------------|
| 声明 | Pod annotation、ConfigMap、Secret | 用哪个插件、引用哪份配置           | 本地路径、后端参数内容   |
| 注入 | 准入 webhook                      | 挂哪些卷、注入哪些变量、本地路径   | 插件配置内容、搬运方式   |
| 触发 | checkpointd                       | 何时搬、何时清理、重试与失败       | 传输协议、manifest 格式  |
| 执行 | 插件                              | 后端读写、manifest、版本枚举、校验 | 时机、训练框架、本地缓存 |

## 声明与注入

label `traincache.io/checkpoint` 的值是同 namespace 的 ConfigMap 名，没有这个 label 的 Pod 不启用。`objectSelector` 按 `Exists` 匹配该键，`failurePolicy` 是 `Fail`。label 值为空、不是合法 ConfigMap 名，或按它读不到 ConfigMap 时，准入拒绝这个 Pod，响应里写出缺的是哪个。ConfigMap 存插件名、后端参数、分片大小、并发、缓冲上限、NVMe 开关与保留份数、恢复策略；Secret `traincache-checkpoint` 存 `accessKey` 与 `secretKey`。webhook 在 Pod 创建时固化配置，保存与恢复共用，运行中不能换插件。

ConfigMap 的键与默认值：

| 键 | 默认 | 含义 |
|---|---|---|
| `plugin` | `s3` | 插件名 |
| `backendEndpoint` | 必填 | 后端地址 |
| `backendBucket` | 必填 | 桶名 |
| `backendPrefix` | 空 | 后端键前缀 |
| `partSizeBytes` | 8 MiB | 分片大小 |
| `concurrency` | 4 | 在途分片数 |
| `bufferBytes` | 32 MiB | 进程缓冲上限 |
| `nvmeEnabled` | `true` | 缓存开关 |
| `nvmeRetention` | 1 | 缓存保留份数 |
| `requireCheckpoint` | `false` | 后端无完整版本时是否失败 |
| `worldSize` | 0 | 副本数兜底 |
| `secure` | `false` | 后端是否走 TLS |
| `checkpointImage` | 可选 | 注入的 checkpointd 镜像 |

`backendEndpoint` 与 `backendBucket` 缺失时准入拒绝这个 Pod。镜像取值顺序是 Pod annotation `traincache.io/checkpoint-image`、ConfigMap 键 `checkpointImage`、本次发布的默认镜像，三处都空时准入拒绝。准入对凭证只写 `secretKeyRef` 引用，不读 Secret 的值；Secret 缺键时 Pod 停在 `CreateContainerConfigError`。ConfigMap 的值由准入读出后写成字面量 env，不写 `configMapKeyRef`。

annotation `traincache.io/task-id` 指定任务标识，取值优先级从高到低为 Pod 上已有的值、所属 Job 或自定义资源名、`<namespace>-<pod-uid 前 8 位>`。`traincache.io/world-size` 指定世界大小，不写时先读 ConfigMap 的 `worldSize`，再读 Job 的 `parallelism`，都没有时按 1 处理。`traincache.io/rank` 指定本 rank 的编号，不写时读 Pod 的 `batch.kubernetes.io/job-completion-index` label；世界大小大于 1 且 rank 推不出来时准入拒绝，世界大小为 1 时按 rank 0 处理并记一条告警。`traincache.io/checkpoint-step` 可选，取值必须是非负整数，缺省由插件选最新。

webhook 只挂卷、注入变量、定路径。

| 卷                 | 类型                              | 挂载点                    | 读写                                  |
|--------------------|-----------------------------------|---------------------------|---------------------------------------|
| checkpoint-work    | emptyDir，磁盘介质                | `/checkpoints-work`       | 训练程序写，checkpointd 读并删        |
| checkpoint-nvme    | emptyDir，落节点磁盘              | `/checkpoints-nvme`       | 只有 checkpointd                      |
| checkpoint-plugins | emptyDir                          | `/opt/traincache/plugins` | initContainer 从镜像复制，checkpointd 只读 |
| checkpoint-run     | emptyDir                          | `/run/checkpoint`         | checkpointd 与插件进程                |

- 插件二进制由一个 initContainer 从镜像复制到 `/opt/traincache/plugins/<name>/<name>`，内置插件都来自 checkpointd 镜像。
- initContainer `checkpoint` 设 `restartPolicy: Always`，即原生 sidecar。它的 startupProbe 通过前，训练容器不启动。
- Pod 不开 `shareProcessNamespace`，训练容器读不到 checkpointd 的进程环境。没有 `.done` 的目录靠文件数与字节数的稳定性判断就绪。
- 训练容器只挂工作卷，只拿到 `TRAINCACHE_CHECKPOINT_DIR=/checkpoints-work/<task_id>`。checkpointd 另拿 `TASK_ID`、`RANK`、`WORLD_SIZE`、`JOB`、`PLUGIN`、`BACKEND`、`REQUIRE_CHECKPOINT`、`NVME_RETENTION`、`NVME_DIR` 与 Secret 里的两把凭证引用。

## 命名与路径

| 项       | 值                                                            |
|----------|---------------------------------------------------------------|
| 工作卷   | `<work>/<task_id>/step-<step>/`                               |
| 缓存     | `<nvme>/<task_id>/step-<step>/`                               |
| 后端     | `<prefix>/<task_id>/step-<step>/rank-<rank>/files/<相对路径>`，同层 `manifest.json` 是提交标记 |
| 续传状态 | `<state_dir>/<sha256>.jsonl`，`STATE_DIR` 默认 `/run/checkpoint/state` |
| 完成标记 | `.done` 由训练程序写完并 fsync 后创建，`.complete` 由 checkpointd 在复制完成且 fsync 后写，内容都为空 |

`<task_id>` 目录由 checkpointd 在恢复前创建，step 目录由训练程序写，缓存目录与状态目录由 checkpointd 创建。checkpointd 认 `step-<n>` 与 `checkpoint-<n>` 两种前缀，写到后端时统一成 `step-<n>`。epoch 不进命名与排序，只记在 manifest 里。

## 分布式训练

一个 rank 一个 Pod，Pod 内的训练进程共用一个 rank 目录。rank 取 annotation `traincache.io/rank`，不写时读 Pod 的 `batch.kubernetes.io/job-completion-index` label，由 webhook 写进变量。

每个 rank 的 checkpointd 独立触发、独立上传自己的子目录，后端键带 rank。跨 Pod 不做协调，不写全局提交标记。插件枚举 step 时要求 rank 集合恰好等于 `{0 … world_size-1}`，缺份判不完整，多出编号不小于 world_size 的份也判不完整，多余份经 resolve 返回的 `max_extra_rank` 报出，checkpointd 记一条 `reason=rank_beyond_world_size` 的告警。world_size 的取值顺序见声明与注入一节。

某个 rank 保存失败只影响自己。恢复时该 step 不完整，所有 rank 一起退到上一个完整 step。

## 保存

### 触发

- 训练程序写完 step 目录并 fsync 后创建 `.done`。checkpointd 每 200ms 轮询，第一次发现带 `.done` 的目录直接入队，之后每一轮要求目录总字节数与上一轮相同，字节数还在变就等下一轮。
- 没有 `.done` 时每 20s 做一次全量扫描，文件数与总字节数连续 3 次扫描不变才算就绪，中途变化就重新计数并记一条告警。
- 同一 rank 的多个 step 按发现顺序排队，出队按 step 升序串行上传。队列上限 4，满了不再接收并记 `result=skipped`、`reason=queue_full`。

### 执行

1. 调插件 `save`，传本地路径、task_id、step、rank、world_size、后端配置、续传状态目录。上传时排除 `.done` 与 `.complete` 两个标记文件。
2. 插件返回成功，远端副本可用。manifest 是插件写的文件清单，生成、写入顺序与校验都由插件负责，checkpointd 不解析它的内容。
3. checkpointd 把该 step 复制到缓存目录：先复制到同文件系统的临时目录，校验后 rename，最后写 `.complete`。回填失败只记一条告警，不影响保存结论。回填成功后按 `nvmeRetention` 从旧到新淘汰 step，默认留 1 份，被软链引用的目录不删。
4. 最后删掉工作卷里该 step 的数据与 `.done`。没有缓存卷时跳过复制与淘汰，插件返回成功后直接删。

### 失败

- 重试由 checkpointd 统一发起，共 6 次尝试，退避间隔依次是 1s、2s、4s、30s、30s，总时限由 `TRAINCACHE_CHECKPOINT_SAVE_DEADLINE` 封顶，默认 15m。不可重试的错误码立刻结束重试。
- 仍失败：保留工作目录、不再接收新 step，写一条 ERROR。训练程序写下一份时遇到 ENOSPC 退出，Job 重建 Pod 后从上一个完整 step 恢复。
- 正在执行的训练 step 不受影响。

## 恢复

### 时机

checkpointd 是原生 sidecar，startupProbe 通过前训练容器不启动，恢复因此先于训练进程，训练脚本不用轮询文件。探针执行 `checkpointd probe`，读 `PROBE_FILE`，内容是 `ready` 时退出 0，其余退出 1；周期 10s，failureThreshold 360，超时 3s。

### 选版本

- 默认调插件 `resolve`，插件枚举后端，返回最大的完整 step 与 epoch，完整的判据见分布式训练一节。
- annotation 指定 `checkpoint-step` 时只恢复该 step，不完整按失败处理，不回退到更旧的版本。
- 后端没有完整 step 时视为新任务直接放行。`requireCheckpoint` 为 true 时按失败处理，避免续训任务从零开始。

### 写入本地

- 缓存里已有该 step 的 `.complete` 时不下载，checkpointd 在工作卷建只读软链指向缓存目录，先建临时软链再 rename。
- 否则调插件 `restore`，写进工作卷的临时目录，逐文件校验，通过后原子 rename。
- 从后端恢复成功后异步回填缓存，下次重启命中缓存。

### 失败

恢复分三段。第一段在 `TRAINCACHE_CHECKPOINT_RESTORE_DEADLINE`（默认 10m）内密集重试，间隔 5s、10s、15s、20s、25s 循环，每轮写一条 ERROR。插件返回 CORRUPT 且策略为 latest 时，checkpointd 重新 resolve 换一个完整 step，最多换 2 次。

第二段从恢复期限到点开始，每 5 分钟一轮，每轮写一条 ERROR，进程不退出，startupProbe 持续失败，训练容器不启动。第三段到 `TRAINCACHE_CHECKPOINT_RESTORE_GIVE_UP_AFTER`（默认 60m）仍然不成功，写一条带 `reason=restore_give_up` 的 ERROR，以退出码 3 结束，与配置非法的退出码 2 分开。

退出后 kubelet 按 Pod 的重启策略重启 sidecar，`restartPolicy: OnFailure` 下每次重启计入 Job 的 `backoffLimit`，用完后 Job 以 `BackoffLimitExceeded` 判 Failed，Pod 删除并释放占用。checkpointd 不访问 API server，退出码是它唯一能表达的失败信号，`backoffLimit` 是接入方要显式定的值。日志带 task_id、step、rank、plugin、err、err_class。

## 插件契约

### 进程与通信

- 插件是独立可执行文件，放在 `/opt/traincache/plugins/<name>/<name>`，由 initContainer 预置。
- 每次操作起一个子进程，结束退出。插件不常驻，不跨操作保存内存状态。
- 通信走 unix socket `/run/checkpoint/plugin.sock`，编码为 NDJSON，一行一个 JSON 对象。任何语言都能实现，不依赖 protoc 或 gRPC。
- 首帧握手，协议版本 1。版本不符或 10 秒内没有 `hello_ok`，这个插件判为不可用。单行 JSON 的上限是 1 MiB，超长行按解码失败处理。

### 消息

| 帧       | 字段                              |
|----------|-----------------------------------|
| hello    | `protocol`、`plugin`、`version`   |
| hello_ok | `protocol`、`methods`             |
| request  | `id`、`method`、`params`          |
| progress | `id`、`bytes_done`、`bytes_total` |
| result   | `id`、`ok`、`data` 或 `error`     |
| cancel   | `id`                              |

| 方法    | 入参                                                              | 返回                                 |
|---------|-------------------------------------------------------------------|--------------------------------------|
| resolve | task_id、rank、world_size、policy、backend                        | `found`、`step`、`complete`、`epoch`、`max_extra_rank` |
| save    | task_id、step、rank、world_size、local_path、state_path、backend  | `bytes`、`files`                     |
| restore | task_id、step、rank、world_size、target_path、state_path、backend | `bytes`、`files`                     |

`policy` 取 `{"mode":"latest"}` 或 `{"mode":"step","step":N}`。`backend` 是 JSON 对象，checkpointd 原样转给插件，不解析。`state_path` 是目录，只放续传状态。`max_extra_rank` 可选，是枚举里确认已提交的、编号不小于 world_size 的最大 rank，值 0 或字段缺失表示没有多余份。`progress` 的发送节奏由插件定，约定每秒一次或每完成 5% 一次，checkpointd 只用它重置僵死计时。

错误码分两类。NOT_FOUND、INVALID_ARGUMENT、AUTH 不重试；UNAVAILABLE、THROTTLED、CORRUPT、INTERNAL 重试，THROTTLED 带退避。

一次操作不设固定超时。连续 5 分钟既没有 `progress` 也没有 `result`，判插件僵死，终止子进程并按 INTERNAL 处理。

### 取消

收到 SIGTERM 后，checkpointd 停止发起新请求，给在途插件发 cancel 帧并等 5 秒，超时终止子进程，续传状态在退出前刷盘。没有 result 帧的异常退出按 INTERNAL 处理。退出码只用于诊断，成败以 result 为准。

## 插件实现

### S3 兼容

保存时遍历本地目录，排除 `.done` 与 `.complete`，按 `partSizeBytes` 分片、`concurrency` 并发上传，默认 8 MiB 与 4。续传状态按文件拆分，每个待传文件一个 `<sha256>.jsonl`，首行是上传头，带 upload_id、key 与 file，之后一行一个已确认分片，每写一行先 fsync 再传下一片。数据传完后写 manifest，manifest 是提交标记，最后写。最后按 S3 规则算复合 ETag 与远端比对，不一致返回 CORRUPT。保存成功后删除该 step 的状态文件。

恢复时列举 `<prefix>/<task_id>/` 下的 step，读各 rank 的 manifest 并逐文件校验，rank 集合恰好等于 `{0 … world_size-1}` 才下载。下载后逐文件校验，写临时目录再原子 rename。单文件失败只重试该文件，连续失败返回 CORRUPT。

### 共享文件系统

local 插件的后端配置只读 `root`，指向共享文件系统的挂载路径，必须是绝对路径。保存时在 `<root>/<task_id>/step-<step>/rank-<rank>/` 的同文件系统建临时目录，同盘改名有效文件（跨设备时整份复制），生成 manifest 并记逐文件校验值，原子 rename 发布，失败删临时目录。恢复时列版本目录、读 manifest、选最新完整版本，目标路径同文件系统内改名，跨设备时整份复制，逐文件校验后原子 rename。这份挂载若是 RWO 块存储，同一时刻只允许一个节点挂上，已有版本只对同节点的 Pod 可见。

## NVMe 缓存

NVMe 缓存由 checkpointd 管理，所有插件共用，不属于插件契约。

- 插件不感知 NVMe，不实现缓存逻辑。开关与保留份数在 ConfigMap 的 `nvmeEnabled`、`nvmeRetention`。
- 内容只来自 checkpointd 的复制：保存成功后回填，从后端恢复成功后回填。
- 每个 step 目录写 `.complete` 作为缓存索引，与插件 manifest 无关。本期缓存卷是 emptyDir，落在节点磁盘，可跨容器重启但不可跨 Pod 重建。`nvmeEnabled` 为 false 或缓存卷不可写时关闭缓存，降级为工作卷加后端。

## 可观测

可观测出口只有日志与探针文件，不设立指标，不发 Pod 事件，不访问 API server。日志公共字段沿用 `core/logging` 的处理器，`component` 固定为 `checkpointd`，本模块另加 `task_id`、`step`、`rank`、`job`、`plugin`、`bytes`、`bytes_total`、`retry`、`state`、`file`、`err`、`err_class`。`state` 取 `waiting`、`ready`、`restoring`、`uploading`、`cached`、`done`、`failed` 七种，`result` 取 `ok`、`error`、`requeue`、`skipped`、`stale`、`degraded`。

`job` 是跨链路对账键，取 owner Job 名，裸 Pod 时为空串，这类场景按 `task_id` 查询。逐步事件的消息里带 step，探针切换的消息里带状态，避开采样器按 `(component,event,task_id,reason)` 的 60 秒去重。排障先看 init 容器状态与探针失败次数，再按 `job` 过滤日志找最近一条 ERROR，退出码 3 是恢复放弃。

## 信任边界

插件二进制与 checkpointd 在同一容器内执行，权限相同。第三方插件能读到 checkpointd 的全部环境变量，包括凭证，也能读写挂载给 checkpointd 的卷。webhook 只把 Secret 以 `secretKeyRef` 注入 checkpointd，训练容器拿不到凭证；Pod 不开 `shareProcessNamespace`，训练容器读不到 checkpointd 的进程环境。本模块只交付内置的 `s3` 与 `local` 两个插件，不对第三方插件作支持承诺，不为其规定审核流程、镜像仓库与版本约束。

## 训练程序侧

| 接入方式                   | 保存                        | 恢复             |
|----------------------------|-----------------------------|------------------|
| 从环境变量或启动参数读路径 | 可用，写 `.done` 后立即上传 | 可用             |
| 路径硬编码                 | 只能靠 20s 扫描，可靠性下降 | 不可用，从零开始 |

Hugging Face Trainer 的 `save_directory` 与 `resume_from_checkpoint`、PyTorch Lightning 的 `dirpath` 与 `ckpt_path` 直接传 webhook 给的路径。裸 PyTorch 需要自己拼路径，保存结束后创建 `.done`。

加载顺序由训练程序保证：按保存时的结构重建模型、优化器、调度器；加载权重；先建调度器，再加载优化器状态，最后加载调度器状态；恢复 epoch 与 step；可选恢复随机数状态。
