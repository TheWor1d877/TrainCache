# Checkpoint 异步 Sidecar

本文是设计阶段的底稿。落地契约以 `10.1-design.md` 为准，与本文的偏离记在 10.1 §1.5 与 `10.2-decisions.md` 的条目里，本文不逐条跟着改。

## 目标与定位

训练程序把 checkpoint 写本地目录，checkpointd 异步搬到持久后端。Pod 重建时 checkpointd 先拉回本地，训练容器再启动。训练镜像不改，接入靠 annotation、环境变量和共享卷。

checkpointd 只搬整份目录并管本地版本，不进读缓存路径。agent 是节点级 DaemonSet，管 CAS 块与读缓存；checkpointd 是 Pod 级进程，管整份目录与后端版本。两者不共享索引、进程和镜像。controller 只在准入阶段注入卷与变量。数据直连后端，不经合并回源网关。

## 角色与分层

| 层   | 执行者                            | 决定                               | 不决定                   |
|------|-----------------------------------|------------------------------------|--------------------------|
| 声明 | Pod annotation、ConfigMap、Secret | 用哪个插件、引用哪份配置           | 本地路径、后端参数内容   |
| 注入 | 准入 webhook                      | 挂哪些卷、注入哪些变量、本地路径   | 插件配置内容、搬运方式   |
| 触发 | checkpointd                       | 何时搬、何时清理、重试与失败       | 传输协议、manifest 格式  |
| 执行 | 插件                              | 后端读写、manifest、版本枚举、校验 | 时机、训练框架、本地缓存 |

## 声明与注入

annotation `traincache.io/checkpoint` 的值是同 namespace 的 ConfigMap 名，空值不启用。ConfigMap 存插件名、后端地址、前缀、分片大小、并发、内存上限、NVMe 开关与保留份数、恢复策略；Secret 存 accessKey 与 secretKey。webhook 在 Pod 创建时固化配置，保存与恢复共用，运行中不能换插件。

task_id 由 webhook 写进 `traincache.io/task-id`，checkpointd 与插件只读。优先级从高到低为 Pod 上已有值、所属 Job 或自定义资源名、`<namespace>-<pod-uid 前 8 位>`。`traincache.io/checkpoint-step` 可选，缺省由插件选最新。

webhook 只挂卷、注入变量、定路径。

| 卷                 | 类型                              | 挂载点                    | 读写                                  |
|--------------------|-----------------------------------|---------------------------|---------------------------------------|
| checkpoint-mem     | emptyDir，medium 为 Memory        | `/checkpoints-mem`        | 训练程序写，checkpointd 读            |
| checkpoint-nvme    | 节点 NVMe 的 emptyDir 或 local PV | `/checkpoints-nvme`       | 只有 checkpointd                      |
| checkpoint-plugins | emptyDir                          | `/opt/traincache/plugins` | 预置 initContainer 写，checkpointd 读 |
| checkpoint-run     | emptyDir                          | `/run/checkpoint`         | checkpointd 与插件进程                |

- 每个插件一个 initContainer `plugin-<name>`，把二进制复制到 `/opt/traincache/plugins/<name>/`。内置插件用 checkpointd 镜像，第三方用自己的镜像。
- initContainer `checkpoint` 设 `restartPolicy: Always`，即原生 sidecar。它的 startupProbe 通过前，训练容器不启动。
- Pod 设 `shareProcessNamespace: true`。兜底扫描要读训练进程的 `/proc/<pid>/fd`。
- 训练容器只挂内存卷，只拿到 `TRAINCACHE_CHECKPOINT_DIR=/checkpoints-mem/<task_id>`。checkpointd 另拿 `TASK_ID`、`RANK`、`WORLD_SIZE`、`NVME_DIR`、`PLUGIN`、`BACKEND` 与 Secret 里的两把凭证。

## 命名与路径

| 项       | 值                                                            |
|----------|---------------------------------------------------------------|
| 内存     | `/checkpoints-mem/<task_id>/step-<step>/rank-<rank>/`         |
| NVMe     | `/checkpoints-nvme/<task_id>/step-<step>/rank-<rank>/`        |
| 后端     | `<prefix>/<task_id>/step-<step>/rank-<rank>/`                 |
| 续传状态 | `/checkpoints-nvme/.state/<task_id>/step-<step>/rank-<rank>/` |
| 完成标记 | `<step 目录>/.done`                                           |

目录由训练程序创建。checkpointd 认 `step-<n>` 与 `checkpoint-<n>` 两种前缀，写到后端时统一成 `step-<n>`。epoch 不进命名与排序，只记在 manifest 里。

## 分布式训练

一个 rank 一个 Pod，Pod 内的训练进程共用一个 rank 目录。rank 取 Pod 序号，来自 Job ordinal 或 Pod 名后缀，由 webhook 写进变量。

每个 rank 的 checkpointd 独立触发、独立上传自己的子目录，后端键带 rank。跨 Pod 不做协调，不写全局提交标记。插件枚举 step 时要求 world_size 个 rank 的 manifest 齐全且校验通过，该 step 才可恢复。world_size 取 Job 或自定义资源的副本数，取不到读 ConfigMap 的 `worldSize`。

某个 rank 保存失败只影响自己。恢复时该 step 不完整，所有 rank 一起退到上一个完整 step。

## 保存

### 触发

- 训练程序写完 step 目录后创建 `.done`。checkpointd 每 200ms 轮询，看到标记就入队。
- 没有 `.done` 时每 20s 扫描一次，同时满足两个条件才算就绪：目录下没有仍被打开的文件，连续两次扫描的文件大小与 mtime 不变。
- 同一 rank 的多个 step 按发现顺序排队，串行上传。队列上限 4，满了不再接收并上报事件。

### 执行

1. 调插件 `save`，传本地路径、task_id、step、rank、world_size、后端配置、续传状态目录。
2. 插件返回成功，远端副本可用。manifest 是插件写的文件清单，生成、写入顺序与校验都由插件负责，checkpointd 不解析它的内容。
3. checkpointd 把该 step 复制到 NVMe，写缓存索引，按保留份数删掉更旧的 step，默认留 1 份。
4. 复制完成后删内存目录里该 step 的数据。没有 NVMe 卷时，插件返回成功后直接删。

### 失败

- 插件按错误码退避重试，耗尽后返回失败。checkpointd 再重试 5 次，间隔 30s。
- 仍失败：保留数据、不再接收新 step，上报 `CheckpointSaveFailed`。训练程序写下一份时遇到 ENOSPC 退出，Job 重建 Pod 后从上一个完整 step 恢复。
- 正在执行的训练 step 不受影响。

## 恢复

### 时机

checkpointd 是原生 sidecar，startupProbe 通过前训练容器不启动，恢复因此先于训练进程，训练脚本不用轮询文件。

### 选版本

- 默认调插件 `resolve`，插件枚举后端，返回最大的完整 step。
- annotation 指定 `checkpoint-step` 时只恢复该 step，不完整按失败处理，不回退到更旧的版本。
- 后端没有完整 step 时视为新任务直接放行。`requireCheckpoint` 为 true 时按失败处理，避免续训任务从零开始。

### 写入本地

- 调插件 `restore`，目标路径是内存目录下该 step 的 rank 目录。插件写同文件系统的临时目录，逐文件校验，通过后原子 rename。
- NVMe 有完整副本时不复制，checkpointd 在内存路径建软链指向 NVMe 目录，先建临时软链再 rename。
- 从后端恢复成功后异步回填 NVMe，下次重启命中缓存。

### 失败

- 重试 5 次，初始 5s，线性退避 5s、10s、15s、20s、25s。
- 返回 CORRUPT 且策略为 latest 时，checkpointd 重新 resolve 换一个完整 step，最多换 2 次。
- 仍失败：进程不退出，startupProbe 持续失败，训练容器不启动。每 5 分钟再试一轮。startupProbe 每 10s 一次，failureThreshold 360，一小时内 kubelet 不重启容器。
- 上报 `CheckpointRestoreFailed` 与 `traincache_checkpoint_restore_failures_total{reason}`，日志带 task_id、step、rank、plugin、error_code。

## 插件契约

### 进程与通信

- 插件是独立可执行文件，放在 `/opt/traincache/plugins/<name>/<name>`，由 initContainer 预置。
- 每次操作起一个子进程，结束退出。插件不常驻，不跨操作保存内存状态。
- 通信走 unix socket `/run/checkpoint/plugin.sock`，编码为 NDJSON，一行一个 JSON 对象。任何语言都能实现，不依赖 protoc 或 gRPC。
- 首帧握手，协议版本 1。版本不匹配时 checkpointd 拒绝该插件。

### 消息

| 帧       | 字段                              |
|----------|-----------------------------------|
| hello    | `protocol`、`plugin`、`version`   |
| hello_ok | `protocol`、`methods`             |
| request  | `id`、`method`、`params`          |
| progress | `id`、`bytes_done`、`bytes_total` |
| result   | `id`、`ok`、`data` 或 `error`     |
| cancel   | `id`                              |

| 方法    | 入参                                                              | 返回                                 |
|---------|-------------------------------------------------------------------|--------------------------------------|
| resolve | task_id、rank、world_size、policy、backend                        | `found`、`step`、`complete`、`epoch` |
| save    | task_id、step、rank、world_size、local_path、state_path、backend  | `bytes`、`files`                     |
| restore | task_id、step、rank、world_size、target_path、state_path、backend | `bytes`、`files`                     |

`policy` 取 `{"mode":"latest"}` 或 `{"mode":"step","step":N}`。`backend` 是 JSON 对象，checkpointd 原样转给插件，不解析。`state_path` 只放续传状态。`progress` 每 1s 或每完成 5% 发一次。

错误码分两类。NOT_FOUND、INVALID_ARGUMENT、AUTH 不重试；UNAVAILABLE、THROTTLED、CORRUPT、INTERNAL 重试，THROTTLED 带退避。

### 取消

收到 cancel 帧或 SIGTERM 后停止发起新请求，5s 内退出并保留续传状态。没有 result 帧的异常退出按 INTERNAL 处理。退出码只用于诊断，成败以 result 为准。

## 插件实现

### S3 兼容

保存时遍历本地目录，排除 `.done`、`*.tmp` 与锁文件，按 8 MiB 分片、4 并发上传。每传完一片，把分片号与 ETag 写进 `state_path`。数据传完后写 manifest，manifest 是提交标记，最后写。最后按 S3 规则算复合 ETag 与远端比对，不一致返回 CORRUPT。

恢复时列举 `<prefix>/<task_id>/` 下的 step，读 world_size 个 rank 的 manifest 并逐文件校验，齐全才下载。下载后逐文件校验，写临时目录再原子 rename。单文件失败只重试该文件，连续失败返回 CORRUPT。

### PVC

后端配置只有 `root`，指向 PVC 挂载路径。保存时在 `<root>/<task_id>/step-<step>/rank-<rank>/` 的同文件系统建临时目录，复制或硬链接有效文件，生成 manifest 并记逐文件校验值，原子 rename 发布，失败删临时目录。恢复时列版本目录、读 manifest、选最新完整版本，目标路径同文件系统内复制或硬链接，逐文件校验后原子 rename。跨节点能否复用取决于 PVC 访问模式，RWO 块存储只允许同节点 Pod 命中。

## NVMe 缓存

NVMe 缓存由 checkpointd 管理，所有插件共用，不属于插件契约。

- 插件不感知 NVMe，不实现缓存逻辑。开关与保留份数在 ConfigMap 的 `nvmeEnabled`、`nvmeRetention`。
- 内容只来自 checkpointd 的复制：保存成功后回填，从后端恢复成功后回填。
- 每个 step 目录写 `.complete` 作为缓存索引，与插件 manifest 无关。节点没有 NVMe 时降级为内存加后端。

## 可观测

| Pod 事件 | 触发 |
|---|---|
| CheckpointSaved | 保存完成且远端校验通过 |
| CheckpointSaveFailed | 保存重试耗尽 |
| CheckpointRestored | 恢复完成 |
| CheckpointRestoreFailed | 恢复一轮重试耗尽 |
| CheckpointCacheHit | 恢复命中 NVMe |

六个指标共用 `traincache_` 前缀，分别是 `save_bytes_total`、`save_seconds`、`restore_bytes_total`、`restore_seconds`、`restore_failures_total`、`queue_depth`。

## 信任边界

插件二进制与 checkpointd 在同一容器内执行，权限相同。第三方插件能读到 checkpointd 的全部环境变量，包括凭证，也能读写挂载给 checkpointd 的卷。webhook 只把 Secret 注入 checkpointd，训练容器拿不到凭证。接入第三方插件等同于允许它在训练 Pod 内运行任意代码，插件镜像由管理员审核。

## 训练程序侧

| 接入方式                   | 保存                        | 恢复             |
|----------------------------|-----------------------------|------------------|
| 从环境变量或启动参数读路径 | 可用，写 `.done` 后立即上传 | 可用             |
| 路径硬编码                 | 只能靠 20s 扫描，可靠性下降 | 不可用，从零开始 |

Hugging Face Trainer 的 `save_directory` 与 `resume_from_checkpoint`、PyTorch Lightning 的 `dirpath` 与 `ckpt_path` 直接传 webhook 给的路径。裸 PyTorch 需要自己拼路径，保存结束后创建 `.done`。

加载顺序由训练程序保证：按保存时的结构重建模型、优化器、调度器；加载权重；先建调度器，再加载优化器状态，最后加载调度器状态；恢复 epoch 与 step；可选恢复随机数状态。
