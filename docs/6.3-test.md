## 命令

```bash
# agent 模块靠工作区解析核心模块，换过依赖版本后先在仓库根跑一次 go work sync
make verify-agent
make verify-hooklib
make verify
cd agent && go test ./... -race -count=1
cd agent && go test ./svc -run 'TestHookReadMiss|TestR1R2E2E|TestCommitSelfOpen' -v
cd agent && go test ./prefetch -run 'TestDemandBypassesSpeculativeQuota|TestPreheatUsesSpeculativeAdmission|TestEnqueueP0DemandJumpsAheadOfPreheat' -v
bash agent/e2e/run-k8s.sh
```

## 覆盖缺口

| 缺什么 | 优先级 | 怎么补 | 动作类型 |
|---|---|---|---|
| 动态调日志级别的 HTTP 端点没有测试碰到处理函数，现在只覆盖地址解析和纯函数取值。 | 中 | 起内存 HTTP 服务调用该端点，断言改级后新级别生效、非法值退回原值。 | 加测试 |
| 订单通道的 5 秒启动宽限、文件消失满 5 分钟回收、陈旧缓冲文件不建读端三条判定没有测试引用，只有停滞聚合被覆盖。 | 高 | 在读端发现用例里注入假时钟推进这三条边界，断言状态迁移与回收计数。 | 加测试 |
| 日志丢弃计数指标没有断言，注册与描述方法都没被测试调用。 | 中 | 在注册表用例里读回该序列，断言标签集合与初值。 | 加测试 |
| 日志汇总器的周期定时循环与全量收尾两个入口没有测试调用，生产路径也只用到按任务提前收口。 | 中 | 用假时钟跑一轮定时循环断言窗口输出，再在上下文取消路径上断言收尾。 | 加测试 |

## 集群演练脚本

`agent/e2e/run-k8s.sh` 在 kind 集群里演练四段：删掉 Agent 容器重建后缓存与索引自恢复、训练容器经只读挂载直读数据块且写被拒、Python 写端投出订单后 Agent 收到、sidecar 停写 30 秒内降级标志置一并随恢复回零。三个镜像要先加载进集群。

脚本发布四份清单，顺序有约束：先应用控制器侧的配置清单，再应用 Agent 的守护集，已存在的配置清单不重复应用。守护集全部取值靠配置清单的键引用，配置清单缺失时容器卡在创建配置错误；重复应用会把实验改过的源站桶名与缓存容量盖回仓库默认值。集群没接对象存储时，紧随订单投递那条的预取接线失败属于预期，那一段的判据只看订单有没有被接收到。

守护集不改动镜像引用，直接用仓库清单里的 `ghcr.io/thewor1d877/traincache/traincache-agentd:dev`。脚本不改镜像名是硬约束：改过的引用留在集群里，后续任何一次守护集滚动更新都会拉不到镜像而卡在镜像拉取失败；控制面脚本按清单哈希判断是否重新应用清单，哈希没变就不纠正这个残留，于是故障会在下一次跑分时才暴露出来。镜像要先用 `./hack/kind-load.sh <集群> <镜像>` 送进集群，节点里的镜像名与本机 tag 一致。
