## 3. 分里程碑验收与测试

### M1 契约冻结

验收：四份文档存在且编号互相对应；`10.0` 含部署与更新段；交接文件已删除。

测试：`make verify-metadata` 通过（文档链接检查覆盖新文件）。

### M2 Agent 侧接线

验收：

- 未配置 `TRAINCACHE_GATEWAY_ENDPOINT` 时，全部取数与改动前一致。
- 配置后 `Get` 走网关，`Put`/`List`/`GetETag`/`PutIfMatch`/`Delete` 仍走源站。
- 网关失败时同一次 `Get` 在零字节前提下改为走源站；非零字节直接失败。
- 退避序列 10s→20s→40s→80s→120s→120s，恢复后清零。
- 指标族 42 个。
- 网关客户端固定 `Region` 与 `MaxRetries=1`，503 不被 SDK 重试放大。

测试标准：单测（`-race`）；`cd agent && go test ./...`；`cd core && go test ./...` 回归；配置用例覆盖缺省、非法、两 env 独立。

### M3 网关骨架

验收：

- `gatewayd` 用默认配置能起，`/healthz`、`/readyz` 200。
- HEAD 与 `CURRENT` 路径 GET 直通，状态码与 Code 和源站一致。
- 收到 SIGTERM 后 `readyz` 转 503，在途请求写完，30s 上限。
- 非法配置启动失败，退出码 1。

测试标准：单测；契约用例；`drain_test.go` 覆盖在途与超时两种。

### M4 网关核心

验收：

- 同一 key 的 5 个并发 GET，源站只收到 1 次 GET、5 次 HEAD。
- 三订阅者收到字节完全一致。
- 慢订阅者被踢，其他订阅者不受影响。
- 第一个订阅者阻塞时，其他订阅者仍能收完。
- `written > cap` 后到达的请求不加入，走独立回源。
- 三个 dataset 并发时份额符合 6.5；单 dataset 能用满 32。
- 60s 汇总九个字段正确。

测试标准：单测 `-race`；契约测试；并发用例 100 次重复；故障注入（拉取协程中途报错、订阅者停止读取）。

### M5 部署与发布

验收：

- `kubectl kustomize controller/deploy` 无字面量 `value:`。
- ConfigMap 17 项与五份工作负载引用一一对应。
- `render-install.sh` 接受五个 digest。
- `verify-release-metadata.sh` 镜像下限 5。

测试标准：`make verify-metadata`；`bash -n hack/*.sh`；清单渲染比对。

### M6 bench 与联调

验收：

- `TRAINCACHE_GATEWAY=1` 时部署网关、写入 `gatewayEndpoint`、重启 agentd；不带该变量时完全回到原装置。
- `summary.csv` 有 `gateway` 列，汇总脚本能按它分组。
- 删除网关 Deployment 后，Agent 在下一次取数降级并直连。
- 更新网关镜像时，Agent 日志没有 `gateway fallback` 行。
- 4 小时长时运行后堆稳定，goroutine 数不增长。

测试标准：`run_bench.py --selftest`、`summarize_compare.py --selftest`、`make e2e-k8s`、长时运行脚本。

## 5. 沉默腐蚀型核心逻辑专项审查

| 逻辑 | 不变量 | 测试策略 |
|---|---|---|
| 累计计数（`merged`/`owners`/`kicked`/`rejected`） | 每个请求恰好计入一次；窗口切换不重不漏 | 注入时钟；固定序列后断言四数之和等于请求数；窗口边界用例 |
| 降级状态机 | 任一时刻最多一个探测；恢复后旧结果不写状态 | 并发 100 个失败；代际切换后喂旧结果；断言退避序列 |
| 重试退避 | 10s 起、翻倍、120s 封顶、成功清零 | 表驱动断言 6 次失败的时间戳；断言上限不再增长 |
| 幂等与重试边界 | 已写字节非 0 时绝不重试 | 网关在偏移 0 与 1024 处失败，分别断言改为走源站与不再改走 |
| 缓冲游标 | 交付区间恒为 `[0,written)` | 绕回、部分写、复用三种用例；第二个对象的前缀不得含第一个对象的字节 |
| 去重（同一个 key 只发一次源站请求） | 同一 key 同时只有一个拉取协程 | 并发 100 次 `Attach`，断言 `Create` 只调用一次 |
| 限流与公平 | 全局 inflight ≤ L；单 dataset ≤ L/2 除非无他人排队 | 断言任意时刻 `sum(inflight) <= 32`；三 dataset 场景断言每份 ≥1 |
| 资源释放 | 缓冲归零、goroutine 归零、拉取协程 ctx 取消 | 1000 次请求后 `runtime.NumGoroutine` 回到基线；池复用后 `written=0` |
| 并发竞态 | `Attach`、`Finish`、踢出三者互斥 | `-race` 加 100 次并发 `Attach`/`Finish` 交错 |
| 序列化兼容 | 错误码与响应头取值一一对应 | 四种组合断言；常量改动时两处同时失败的用例 |
| 配置加载 | 非法值拒绝启动；缺省不改变行为 | 表驱动覆盖缺省、空串、非法整数、非法布尔 |
| 日志采样与脱敏 | 敏感字段恒被替换 | 构造含 accessKey 的错误消息，断言输出为 `***` |
| 与已有模块的数据一致性 | Agent 收到的字节与源站一致；CURRENT 不合并 | 集成用例比对 1MB 随机数据；5s 跟随用例断言不被旧快照卡住 |
| 时间与时区 | 退避与窗口都用单调时钟 | 注入时钟；断言系统时间回拨不影响 `nextProbe` |

覆盖结论：前六项已覆盖，资源释放与并发竞态已覆盖但要用长时运行加固，网络故障与云端差异缺失。
