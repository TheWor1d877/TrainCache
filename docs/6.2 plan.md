# Agent 服务化实施计划(plan)

> 对应文档:`docs/6.0 Agent服务化.md`(需求)、`docs/design.md`(设计,接口签名与数据格式冻结)、`docs/decisions.md`(决策)。本文档定义实施顺序:每个里程碑是能独立验收的一块,列目标、任务清单与验收命令。实现子代理发现约定不可行 → 回传 `BLOCKED`(理由 + 证据),由主对话裁决并更新 design.md / decisions.md 后再继续。

## 0. 执行方式(固定,沿用 core 6.2 流程)

1. **派活**:子代理任务按七项模板下发(`[TASK] [CONTEXT] [INPUT] [WRITE] [DELIVER] [ACCEPT] [FORBID]`),自包含——贴所需约定片段原文(design.md §5 对应签名、§6 对应格式),不依赖对话历史;
2. **白名单**:`[WRITE]` 精确到文件;同一文件同一时间只有一个写入者;不得动白名单外文件;
3. **约定冻结**:design.md 的接口签名与数据格式不可私改;发现问题 → 回传 `BLOCKED`(理由 + 证据),主对话裁决后再继续;
4. **验收**:主对话在里程碑完成后亲自执行验收命令,不采信子代理自报;失败派修复子代理(贴报错原文 + 复现命令);
5. **回传格式**:固定回传 `STATUS/FILES/SYMBOLS/TESTS/DECISIONS/BLOCKERS/NEXT`,禁止夹带大段代码;
6. **双语言**:Go 与 Python(sidecar)混排;Python 侧契约(design §6.1 / §6.2 格式)同样冻结,派活时自包含——ring 字节布局和 JSON 字段两端共用,一边私改另一边就读错;
7. **bench 装置**:需要真实数字的验收步骤在 bench 装置上执行(`make bench-up` 后跑被测负载),纯单元验收在本机;证据入 `agent/results/`。

**目标**:核心库按 design §5.7 新增坏块标记能力;契约先经核心库文档流程落地(先文档后代码,避免签名改动同时改三份文档),再实现与测试全绿。

**任务清单**:
1. 核心库文档:5.1 design.md §5.2 增补三方法签名与语义;5.2 plan.md 增补里程碑登记;5.3 decisions.md 新增决策条目(签名、quarantine/ 目录布局、幂等语义、Put 对已存在块行为裁决 Q3);


## 10. 里程碑 M8:demand 按需补块与预取去重

补齐读 miss 处理:训练进程读不到块时 Agent 知道并马上补;消除同一块跨队列重复排队。不改数据主路径。

**目标**:钩子第四帧 `read_miss` + svc 异步 demand(absent→P0 入队 reason=`demand`;corrupt→repair:`Quarantine`+`RepairOne`)+ pending 去重表 + read_miss 指标(统计帧,不区分回源路径)。契约见 design §5.2、§5.4、§5.8、§7.1、§7.5 与 6.3 D44/D45,非 7.0 十一条。

**任务清单**:
1. `svc/hooksock.go`:`read_miss` 帧解析与 `HookHandlers.Miss` 分发(字段、丢弃计数按 design §5.4);svc 接线:`resolveRef → Catalog.Lookup → cas.Open` 后 demand/repair 分路,复用同一 Fetcher/single-flight;训练 Pod 只读 hostPath 不变;
2. `metrics/`:新增 `traincache_hook_read_miss_total{reason}`,dataset 不入标签;`prefetch/prefetcher.go`:pending 表与 `enqueueLocked`(键、提升、忽略与计数口径按 design §5.2/D45);
3. 单测:同块 P0/P2 并发只下载一次且 OnDone 一次;P2 未开始遇 P0 提升不新建 task;repair/demand 两条路径;三种 fetch reason 各自打点;帧解析与非法帧丢弃;
4. e2e:`agent/svc` 内直写 Unix datagram 发送 `read_miss`,轮询断言补块后可读、指标增长、reason=`demand`;不新增独立脚本,随 `go test ./svc/...` 可重复执行。

**验收**:
```bash
cd agent && go test ./prefetch/... ./svc/... ./metrics/... -race -count=1  # 全绿
```
判据:全绿;上述单测场景全部通过;`agent/svc` 集成测试直写 socket 触发 demand 补块;`/metrics` 出现 `traincache_hook_read_miss_total{reason="absent|corrupt"}` 且不带 dataset。

## 11. 里程碑 M9:指标补全(stall 实测与归因、分阶段命中率、证据指标)

补"等的时候能不能说清楚为什么等"的观测证据,不改数据路径。

**目标**:补齐 7.0 六条线路的可观测证据——钩子第五帧 `read_stall` 与 Agent 归因、phase/source 标签、8 个新 family;family 总数 26→34。契约见 design §5.4、§5.8 与 6.3 D46/D47/D48,非 7.0 十一条。

**任务清单**:
1. `svc/hooksock.go`:第五帧 `read_stall` 解析(`type,path,chunk,wait_ms,ts`),`HookHandlers` 增 `Stall`;非法/超 4 KiB 帧沿用 D33 丢弃计数;
2. `svc` 归因:按 ts±5s 关联本地存在性与在途 fetch,得 `local_slow`/`origin_slow`/`prefetch_lag`/`unknown`(分别指向本地磁盘、对象存储、预取策略、信息不足);wait < 阈值不上报(默认 100ms,`TRAINCACHE_READ_STALL_MIN_WAIT_MS` 可配);
3. `svc`/`collector`:phase 状态机与命中 source 判定(定义见 design §5.2);`metrics/`:注册 8 个新 family、变更 6 个既有 family(5 个标签变更 + stage_switch_eta 改名与语义澄清),清单见 design §5.8 与下方验收 grep;singleflight 用 Agent 侧调用包装器计数,不改 core/fetch;
4. 单测:帧解析与四种 cause 归因(时间注入)、phase 迁移、source 判定、标签集合断言(26→34)、100 样本窗口、reason 分桶、`dataset="other"` 归并。

**验收**:
```bash
go build ./... && go vet ./... && go test ./agent/... -race -count=1
curl -s localhost:9411/metrics | grep -E 'traincache_(stage_switch_eta_seconds|read_stall_seconds|prefetch_hit_ratio|fetch_singleflight_merged_total|repair_queue_depth|prefetch_task_duration_seconds|prefetch_lead_blocks|consumption_advance_total|fetch_bandwidth_limit_bytes)'
```

## 13. 里程碑 M11:前缀感知快照跟随、读者登记与 GC 安全边界
