# 缓存核心库测试说明

## 命令

```bash
make verify-core
cd core && go test ./... -race -count=1
cd core && go test ./index -run 'TestLocalGC|TestSweep' -v
cd core && go test ./cas -run 'TestConcurrentPutSameBlock|TestVerifyFailure' -v
cd core && go test ./fetch -run 'TestMergeSameKey|TestFetcherSpeculativeYieldsToReading' -v
cd core && go test ./publish -run 'TestMultiTarE2E' -v

# 真实后端集成要这四个环境变量，缺任一个该用例自己跳过；本地起 MinIO 即可
TC_S3_ENDPOINT=127.0.0.1:9000 TC_S3_ACCESS_KEY=... TC_S3_SECRET_KEY=... TC_S3_BUCKET=traincache \
  go test ./objectstore -run TestS3ConditionalWriteIntegration -v
```

## objectstore：对象存储接口面与条件写探测

| 文件 | 测什么 | 覆盖场景 |
|---|---|---|
| `store_test.go` | 内存实现的六个方法逐个走一遍，重点在条件写的两种期望值语义、同内容 ETag 稳定、对象不存在与前置条件不满足两类错误、并发创建只有一个成功、上下文取消。 | 条件写、ETag 语义 |
| `probe_test.go` | 后端真执行前置条件时探测得到冲突错误、忽略前置条件时报不支持错误，探测完把临时键清掉。 | 装配期探测 |
| `blockkey_test.go` | 数据块对象键的拼式，覆盖块序号 0 与最大值、路径含斜杠不转义、数据集名带斜杠这些边界。 | 键布局契约 |
| `range_test.go` | 闭区间读取的取值与长度口径，内存实现逐档校验，假 HTTP 服务端验证真实客户端对越界请求和短读的判定。 | 区间读取 |
| `s3_integration_test.go` | 真实后端上条件写是否真的拒绝不匹配的期望值。 | 真实后端集成 |

## 覆盖缺口

| 缺什么 | 优先级 | 怎么补 | 动作类型 |
|---|---|---|---|
| Put 后置观察者没有核心库用例，装上之后回调是否只触发一次、字节数是否等于数据长度都没断言。 | 中 | 在 cas 包内断言 rename 成功后触发一次、传入长度等于数据字节数、上下文取消的失败路径不触发。 | 加测试 |
| 下载合并钩子没有用例，等待者计数一次、发起者不触发这两条没有断言。 | 中 | 在 fetch 包内并发请求同一键，断言回调次数等于等待者数、发起者那次不计数。 | 加测试 |
| 后端不提供带大小的列举时那条错误分支没有用例。 | 中 | 用不实现该能力的假后端调用列举，断言返回不支持错误且六个基本方法语义不变。 | 加测试 |
| 真实后端只跑条件写一条集成用例，区间读取与带大小列举在真实后端上没跑过。 | 低 | 在同一组环境变量下各补一条，越界区间与短读各断言一次错误类型。 | 加测试 |
| 数据字节数超过块头能表达的长度上限时那条报错没有用例。 | 低 | 构造一个声明超大长度的源，断言写入失败、块头没被写出、临时文件被清掉。 | 加测试 |
