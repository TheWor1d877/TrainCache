# 日志与可观测性 · 测试说明书

## 1. 测试范围

日志与指标测试分布在三处生产代码目录加 M12 里程碑断言：

| 目录 | 测什么 |
|------|--------|
| `core/logging` | `Redact`/`RedactURL` 脱敏（含 S3 签名 URL、URL userinfo、哨兵负向用例）；`NewRedactingHandler` 对消息、字符串、error、group 与预挂属性的处理 |
| `controller/internal/logging`、`agent/internal/logging` | 各进程 slog JSON 初始化、`component/version` 注入、level 解析、`Into/From` context 传递、脱敏 handler 接线（哨兵凭据与签名 URL 不出现在输出里） |
| `agent/metrics`（families/registry/capacity 三份）、`controller/internal/metrics`（metrics/m12_metrics 两份）、`agent/svc` 的 wiring | 指标 family 注册、标签白名单、非法枚举丢弃、高基数标签拒绝、真实业务路径打到指标；`agent_up` / `agent_degraded` / `quarantined_blocks` 的 gauge 值断言 |
| warmup/scheduler/webhook/dataset 四个业务包的 `m12_logs_assert_test.go`；dataset `controller_test.go` | 逐行断言 8.1 §4.1 的十七个控制平面日志点（`msg` + 必带字段 + level），含 dataset reconcile 入口/出口 |
| `controller/internal/controller/warmup/logs_score_deviation_test.go` | GWAA 分配结果、annotation 冲突重试/耗尽与 `pod score detail`、落点偏离 Warn 与 `NodeDeviation` Event 成对断言 |
| `agent/svc/m12_logs_assert_test.go` | preheat 四条 RPC 生命周期、陈旧 generation 拒绝、evictor 淘汰轮次、hooksock 收端就绪与读帧失败 EOF |
| `agent/collector/degrade_logs_test.go`、`agent/svc/backfill_logs_test.go` | Agent 降级/恢复、坏块仅隔离的日志字段断言 |
| warmup/scheduler/dataset 的 `m12_metrics_emit_test.go` | 真实 reconcile/打分路径的指标 emit 断言 |

全部是单元/轻集成测试：没有 K8s APIServer、没有 Prometheus 真实 HTTP 抓取，用 `prometheus.NewRegistry()` 或内存 `slog.Handler` 做替身。依赖生产代码补齐的日志项（DataLoader、采样限流、动态级别）登记在 `TODO.md` 第 8 章。

## 2. 运行方式

所有命令都在仓库根目录执行，模块路径见 `go.work`：

```bash
# 日志核心三包
go test ./core/logging/... -v -count=1
go test ./controller/internal/logging/... -v -count=1
go test ./agent/internal/logging/... -v -count=1

# 指标核心
go test ./agent/metrics/... -v -count=1
go test ./controller/internal/metrics/... -v -count=1
go test ./agent/svc/... -run Metrics -v -count=1

# M12 日志断言（四个业务包各一份 + Agent 端一份）
go test ./controller/internal/controller/warmup/... -run M12 -v -count=1
go test ./controller/internal/scheduler/... -run M12 -v -count=1
go test ./controller/internal/webhook/... -run M12 -v -count=1
go test ./controller/internal/controller/dataset/... -run M12 -v -count=1
go test ./agent/svc/... -run M12 -v -count=1

# M12 指标 emit
go test ./controller/internal/controller/warmup/... -run "Metrics|Emits" -v -count=1
go test ./controller/internal/scheduler/... -run "ScoreNodeEmits" -v -count=1
go test ./controller/internal/controller/dataset/... -run "ReconcileNotFoundEmits" -v -count=1
```

- `-count=1` 禁止缓存，改了被测代码都应该加。
- 业务包测试里除了 `m12_*` 还会跑各自的其它测试，要只跑 9.x 相关的必须用 `-run M12` 或按函数名过滤。
