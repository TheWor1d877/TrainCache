# Agent 服务化实施计划(plan)

> 对应文档:`docs/7.0 Agent服务化.md`(需求)、`docs/design.md`(设计,接口签名与数据格式冻结)、`docs/decisions.md`(决策)。
> 实现子代理发现约定不可行 → 回传 `BLOCKED`(理由 + 证据),由主对话裁决并更新 design.md / decisions.md 后再继续。

## 0. 执行方式(固定,沿用 core 6.2 流程)

1. **派活**:子代理任务按七项模板下发(`[TASK] [CONTEXT] [INPUT] [WRITE] [DELIVER] [ACCEPT] [FORBID]`),自包含——贴所需约定片段原文(design.md §5 对应签名、§6 对应格式),不依赖对话历史;
2. **白名单**:`[WRITE]` 精确到文件;同一文件同一时间只有一个写入者;不得动白名单外文件;
3. **约定冻结**:design.md 的接口签名与数据格式不可私改;实现中发现问题 → 回传 `BLOCKED`(理由 + 证据),由主对话裁决并更新 design.md / decisions.md 后再继续;
4. **验收**:主对话在里程碑完成后亲自执行验收命令(不信任子代理自报),失败则派修复子代理(贴报错原文 + 复现命令),不亲自上手改;
5. **回传格式**:子代理固定回传 `STATUS/FILES/SYMBOLS/TESTS/DECISIONS/BLOCKERS/NEXT`,禁止夹带大段代码。

Agent 项目特有补充:

6. **双语言**:Go 与 Python(sidecar)混排;Python 侧契约(design §6.1 / §6.2 格式)同样冻结,派活时自包含;
7. **bench 装置**:需要真实数字的验收步骤在 bench 装置上执行(`make bench-up` 后跑被测负载),纯单元验收在本机;证据入 `agent/results/`。

## 10. 里程碑 M8:demand 按需补块与预取去重(debug)

**目标**:补齐读 miss 的可观测与 demand 链路:钩子新增第四帧 `read_miss`,svc 接线触发 Agent 侧异步 demand 补块(absent → demand 的 P0 入队、reason=`demand`;corrupt → repair:`Quarantine` + `RepairOne`);PersistentPrefetcher 增加 pending 去重表,消除同一块跨队列重复下载;新增 read_miss 指标(统计帧,不区分回源路径)。补充覆盖 design §5.2、§5.4、§5.8、§7.1、§7.5,非 7.0 十一条。契约见 7.3 D44/D45。

**任务清单**:
1. `svc/hooksock.go`:第四帧 `read_miss` 解析(path/chunk/reason/ts;reason∈{absent,corrupt},无法区分时按 absent),非法/超 4 KiB 帧沿用丢弃计数;`HookHandlers` 增 `Miss func(ordersource.ChunkRef, string)` 并分发;
2. svc 接线:`resolveRef → Catalog.Lookup → cas.Open`;ErrNotFound → demand(最高优先级 P0 入队,reason=`demand`),ErrCorrupt → repair(`Quarantine` + `RepairOne`);demand 复用同一 Fetcher/single-flight;训练 Pod 保持只读 hostPath,不接对象存储、不持凭证;
3. `metrics/`:新增 `traincache_hook_read_miss_total{reason}`,dataset 不入标签;
4. `prefetch/prefetcher.go`:pending 表(键 `blockKey(dataset,ChunkRef)=<dataset>/blocks/<path>#<chunk>`,覆盖 P0–P3 与运行中 task);`enqueueLocked` 实现入队 / 优先级提升 / 运行中忽略;完成或终止移除键,失败重试保留;OnDone/OnP0Done 每 task 恰好一次;QueueDepth 与 SubmitPreheat total/completed 按去重后计数;
5. 单测:同块 P0/P2 并发只下载一次且 OnDone 一次;P2 未开始遇 P0 提升且不新建 task;repair(Quarantine+RepairOne)与 demand(缺失→P0 入队)两条路径;三种 fetch reason(prefetch/demand/repair)各自打点;read_miss 帧解析与非法帧丢弃;
6. e2e:`agent/svc` 内直接写 Unix datagram socket(真实 HookSock + 最小可用 Agent 装配)发送 `read_miss`,轮询断言 demand 补块后块可读、`traincache_hook_read_miss_total{reason}` 增长、fetch reason=`demand`;不新增独立脚本,随 `go test ./svc/...` 可重复执行。

**验收**:
