**交付物**：门控纯函数、放行编排、时钟注入测试、整数门控边界矩阵测试。

**验收**

```bash

```

**判据**：① `required_i=floor(threshold*K_i)`，`threshold>0` 且结果为 0 时取 1，恒 `0<=required_i<=K_i`；K=8/threshold=0.8 → 6；`rate` 仅观测，不参与放行判定；② K=1/7/8/9 × threshold=0/0.8/0.9 矩阵全部有断言（threshold=0 时 `required_i=0`，条件①恒真）；③ 条件①/②/③ 各有正反用例；`t >= TMax` 必 Degraded；④ slope 采样不足不触发条件②；⑤ 边际收益场景：首个 Pod 达标后其余 `slope >= slope_min` 继续 Hold，`gap > gap_min && slope < slope_min` 才放行，接近阈值时不误放行；⑥ 摘 gate 幂等；⑦ annotation 写失败不摘 gate。

⑥ 亲和合并：`unitMin=max(各成员 min)`、`unitMax=min(各成员 max)`；`unitMin > unitMax` 返回冲突错误；合并单元共享目标集合。
⑦ `min > max` 被 CRD 或 webhook 拒绝；`min > 可行节点数` 时 `MinUnmet=true` 且 `target=可行节点数`。
⑧ `fanout=1, min=1` 与 M13 回归一致：目标集合、门控、status、annotation 均无行为差异。
⑨ status 明细条数 = 实际 `Assignment`；正常每 Pod 在 `[min,max]`，冲突/容量/兜底低于 min 时 `MinUnmet=true`，任何情况 ≤max，总数 ≤ P×max；无可行节点只有一条空 `NodeName` 汇总；P=64、N=256、max=3 时序列化 <1 MiB；日志断言覆盖全部新增字段；`pods_per_node` 按实际配对计数。
⑩ 8.1 与 8.2 对 `0.25`、`0.5`、clamp、信号下限的描述一致；8.0 未被修改。

## 22. M16 K 自动计算与启动窗口配置
**目标**：`PodDetail.K` 可省略（CRD 下限 0），Controller 按 `K_i = clamp(min(W_i, K_window, K_cache), 1, W_i)` 计算并写回 spec；`K_window = ceil(startupWindowBytes / chunkSize)`，`K_cache = floor(cacheCapacityBytes × maxFillFraction / (podCount × chunkSize))`，`cacheCapacityBytes=0` 时跳过 `K_cache`。显式 K 取 1..W_i，`K>W_i` 置 `InvalidSpec`；全部 Pod 实际请求块数合计超 `cacheCapacityBytes × maxFillFraction` 发 Warning `KExceedsFillLimit`，任务照常。配置入口为 ConfigMap `traincache-config` 的 `startupWindowBytes`（默认 512MiB）与 `maxFillFraction`（默认 0.125）。裁决见 D43。
