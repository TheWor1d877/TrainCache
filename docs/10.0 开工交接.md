## 二、10.0 交付内容

| 块 | 交付 | 落点 |
|---|---|---|
| 网关进程 | 全代理：GET / PUT / LIST 三类请求都转发；只有 `<dataset>/blocks/` 前缀的 GET 进在途合并表，`CURRENT`、`manifest`、PUT、LIST 直接转发（基线 `10.0:83`） | `gateway/` |
| 网关合并 | 按对象键合并在途整对象 GET，`io.Pipe` 边拉边分发，`sync.Pool` 复用 5MB 环形缓冲，落后超缓冲的订阅者被踢后自己直连（基线 `10.0:95-107`） | `gateway/` |
| 网关 QoS | 到桶并发额度默认 32、可调；按活跃 dataset 均分份额，保底 1、封顶总额度 1/2；缓冲区按块配（默认 5MB），不做总容量配置 | `gateway/` |
| Agent 降级 | 进程内两个量：当前后端、下次重试时刻（初始 10s，退避上限 2min）。判据：连不上 / TLS 握手失败 / 超时 / 带 `x-traincache-gateway: unavailable` 的 5xx；403、429 与容量拒回不算（基线 `10.0:51-54`）。状态不写回 CRD，重启回到配置默认 | `agent/svc/`（选择器）+ `core/objectstore/`（判据） |
| 部署 | 一个 Deployment + 一个 Service，不是 DaemonSet；可与 MinIO 同节点但必须两个 Pod（基线 `10.0:19-21`） | `controller/deploy/gateway/` |
| bench | 新实验臂：网关挂在 Agent 与 MinIO 之间；网关到桶额度取 64，高于被测档位与集群 Agent 合计下载并发（基线 `10.0:78`） | `bench/compare/traincache/`、`bench/compare/run_compare.sh`、`docs/4 bench装置说明.md` |

## 三、待实测

minio-go 小对象 PUT 是否带 `aws-chunked` 流式签名。带的话网关转发 PUT 要先解框再重签，否则会 400。测法：本地 MinIO 边车 + 一次真实 `trainpublish` 灌数据，抓 Agent 到源站的请求头看 `Content-Encoding` 与 `x-amz-content-sha256`。这项在写 10.1 的转发契约前做完。
