# eBPF 观测可行性验证结论

块 I/O 延迟、major fault、filemap 预读、时钟对齐四类观测点都能在内核 7.0.0-43 上出数，观测选型可行。验证在宿主进程挂载 bpftrace，负载是同一块 nvme 上现写现读的受控冷文件；kind 节点与宿主共享内核，从宿主挂与从节点内挂看到的块 I/O 和缺页事件相同。

## 块 I/O 延迟

`block:block_rq_issue` 与 `block:block_rq_complete` 按（设备、起始扇区）配对，128MB 冷读一轮配出 1017 对，延迟集中在 16µs 到 128µs、尾部到 2ms，是 NVMe 的合理量级。issue 出去没有对应 complete 的请求会滞留在配对表里，bpftrace 脚本没有淘汰表项的手段，这一轮靠探针退出时清空；正式工具要给配对表一个不再只增不减的上界，bpf 侧最省事的做法是把表设成带上限的 LRU，靠淘汰最旧项兜住泄漏。

## major fault

kretprobe 挂 `handle_mm_fault`，读返回值的 `VM_FAULT_MAJOR` 位（`0x4`）。关掉 fault-around（对映射调用 `madvise MADV_RANDOM`）后，128MB 冷 mmap 每页各自阻塞取盘，探针计数 32768，与同窗口 `/proc/vmstat` 的 `pgmajfault` 增量 32768、以及 128MB 除以 4KB 的页数三者完全一致，热态复读两边都是 0，标志位读取正确。

fault-around 开着时，同样一次 128MB 冷 mmap 只报个位数 major fault：内核处理一次缺页顺带映射一批相邻页，后续对这批页的访问落在缓存里、算 minor fault 不计 major。工具的 major fault 计数强依赖被观测进程有没有关预读，只看这个计数容易把预读摊薄后的结果当成没发生冷读，报数要连同这个前提一起给。

## filemap 预读配对

三个 filemap tracepoint 都带 `s_dev`、`i_ino`、`index`，按 inode 过滤能稳定把某个文件的进缓存事件与消费事件各自挑出来，（设备、inode、页索引）三元组配对成立。

这台内核用多页 folio，`mm_filemap_add_to_page_cache` 带一个 `order` 字段，一个事件代表从 `index` 起连续 `2^order` 个页。128MB 冷读的进缓存事件只有 1063 个，但 `Σ2^order` 等于 32768，正好是全量页数，`order` 大多落在 4 到 8（即 16 到 256 页的 folio，以 32 页、64 页为主）。所以指标「预读进缓存页数」必须按 `Σ2^order` 算，直接数事件条数会把页数低估约 30 倍。

消费侧 `mm_filemap_get_pages` 带 `last_index`，一条事件覆盖 `index` 到 `last_index` 一段页，消费页数按 `last_index − index + 1` 求和；这一轮 578 条事件合计 21952 页。read() 路径只触发 `get_pages`，不触发 `mm_filemap_fault`（后者属缺页路径，本轮 read 侧计数为 0），两个消费事件按访问方式二选一。进缓存 32768 页与消费 21952 页相差 10816 页，是顺序读到文件尾时预读窗口越界、没被消费的部分，即无效预读，比值算得出来。

## 时钟对齐

bpftrace 的 `nsecs` 是单调时钟，跨进程对齐要换成 epoch。同一瞬间采一对 `/proc/uptime` 与 `date +%s%N`，取 `offset = epoch_ns − uptime_ns`，事件时间戳 `nsecs + offset` 即换算成 epoch。实测换算出的 epoch 与对表用的 epoch 差 34ms，这个残差全部来自两步采样之间的人工间隔；正式工具把这对偏移在每轮开始背靠背写进 run 目录，对齐精度受这一对采样自身间隔的限制，与内核侧时钟无关。

## 工具链就绪

`clang`、`bpftool`、`gcc`、`python3` 都在，`/sys/kernel/btf/vmlinux` 齐备，能生成 CO-RE 骨架。交付用的 libbpf 加 C 静态二进制不需要再装工具链。宿主 bpftrace 版本 v0.25.0，与官方静态分发目标版本一致。

## 阶段二实现里程碑

`traintrace` 的正式实现按六程推进。每程结束时都能构建出可跑的二进制，验收对着本章前面的实测数，数字对不上不进下一程。M2、M3、M4 三类探针互不依赖，可在 M1 之后并行，M5 把探针接到完整命令行与落盘，M6 补归因与异常兜底。

1. 构建骨架打通。`ebpfobs/` 建目录，libbpf 以 submodule 引入，Makefile 四步跑通：生成 `vmlinux.h`、编 `.bpf.o`、出 skeleton、静态链成 `build/traintrace`。交付一个只 open/load/attach 空程序、写出一份空 `metrics.json` 的二进制。验收是构建机 `make` 一步出 ELF、`ldd` 无依赖、目标机能装载。
2. 块 I/O 延迟族。装 `do_blk_issue` 与 `do_blk_complete`，建 `rq_start`（LRU，键 `{dev, sector}`）与 `blk_hist`（per-CPU hash，log2 桶），`watch_dev` 入口过滤、`rw` 定读写维度，用户态跨 CPU 求和后清零。交付 `block_io` 段的 `by_dev_rw` 直方图。验收对这一章冷读工件复现约 1017 对、主峰 16–128µs、尾部 2ms。
3. major fault 族。kprobe/kretprobe 挂 `handle_mm_fault`，建 `mmf_ts`（task storage）与 `fault_agg`（`{cgroup,pid}` 到 `{cnt,ns}`），按返回值的 `VM_FAULT_MAJOR` 位累加，comm 按 pid 从 `/proc` 补。交付 `major_fault` 段的 `count` 与 `mean_us`。验收在 `MADV_RANDOM` 关预读下探针计数等于 `/proc/vmstat` 的 `pgmajfault` 增量、等于 32768，热态两边为 0。
4. filemap 预读族与配对。装 `do_add_to_cache`、`do_filemap_fault`、`do_get_pages`，建 32MB `rb` 与 `rb_drop`，`watch_cgroup` 过滤，用户态收事件后跑区间集合配对。交付 `readahead` 段的 `added_pages`（按 `Σ2^order`）、`consumed_pages`、`invalid_pages` 与 `invalid_ratio_pct`。验收复现 added 32768、consumed 21952、invalid 10816、无效比约 33%。
5. 命令行、时钟、落盘、摘要。补齐全部 flag，`--cgroup` 用 `stat` 取 inode、`--pid` 反推 cgroup id，`sample_clock_offset` 背靠背取 `epoch_ns − uptime_ns`，写 `metrics.json` 与 manifest，打终端摘要，`--verbose` 每轮快照，`--duration` 到点或 SIGINT 退出时做一次全量拉取。交付一次完整运行在 `--out-dir` 下落两个文件。验收事件 `nsecs + offset` 落进采集窗，残差在采样间隔量级（约 34ms）。
6. 归因、异常兜底、门禁。`attribute_faults` 把 fault 与其 I/O 发起者不符的标为疑似预读归因偏移、只标不改记，`rb_drop` 非零时把 filemap 段标不完整，`rq_start` 的 LRU 淘汰差值进 manifest，单个程序 attach 失败记录程序名后继续。交付归因偏移计数进 `major_fault`、异常计数进 manifest。验收注入丢事件与 attach 失败两类异常，摘要与 manifest 如实标注，主流程不崩。

bench 里的测量与接入方式在 M4、M5 出数之后写进 11.3。
