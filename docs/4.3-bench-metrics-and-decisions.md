# bench 指标与决策

## 术语

| 术语 | 含义 |
|---|---|
| COND | 一个实验格的全部条件写成一个 JSON 文件，`python3 bench/run.py compare --rho 2 --rate 300 --group traincache-cold` 对应一份。`bench/run.py` 只读 COND 的字段决定这一格怎么跑。 |
| 预热 | 训练 Pod 调度之前，controller 建 WarmupTask 把数据拉进节点缓存。Pod 还没落到节点，覆盖哪些节点由 `preheatFanout` 决定，取 2 时预热两个节点。 |
| 预取 | 训练 Pod 调度到节点之后，agentd 按训练的消费顺序持续往后拉块。窗口大小由 `TRAINCACHE_PREFETCH_LOOKAHEAD` 控制，默认 32 块，等于一个分片的块数。 |
| 启动窗口 K | 训练开始之前必须就绪的块数。`startupWindowBytes` 取 536870912 字节，按 8 MiB 块折算 K 为 64 块。缓存容量折算出的块数记作 `K_cache`。 |
| ρ | 数据集字节除以缓存容量。数据集固定 4294967296 字节，ρ=4 时缓存容量 1073741824 字节。 |
| 负载形态 | COND 的 `load` 字段，取 `dataset`、`tilt`、`train` 三值，分别读主数据集 tar、倾斜清单、训练负载。 |
| 组态 | 一次跑分的独立运行形态，共七种：`direct`、`juicefs-cold`、`juicefs-warm`、`fluid-cold`、`fluid-warm`、`traincache-cold`、`traincache-warm`。组态名对应 `bench/compare/` 下的起停脚本，例如 `traincache-warm` 由 `bench/compare/traincache/up.sh` 加调度闸门起。 |
| 淘汰策略 | 缓存写满后按什么顺序删块。`TRAINCACHE_EVICT_POLICY` 取 `heat`、`lru`、`lfu`。 |
| 基线格与被测格 | 缓存基线格是 `juicefs-cold`、`juicefs-warm`、`fluid-cold`、`fluid-warm` 四种，每个 ρ 各一格，配额随 ρ 变；`direct` 没有缓存，只跑 ρ=4 一个代表格。被测格是 `traincache-cold` 与 `traincache-warm`，每个 ρ 各一格。 |

## 启动与全程 makespan

makespan 是从提交训练任务到训练结束的墙钟时长，单位 s。四个时刻都以 epoch 秒记录。

| 符号 | 含义 | 采集方式 |
|---|---|---|
| `t_submit` | 训练 Job 创建时刻 | runner 在 `kubectl apply` 之前取 `time.time()`，注入 Job 环境变量 `TRAINCACHE_JOB_CREATED_AT` |
| `t_pod_ready` | 训练 Pod Ready 时刻 | runner 读 Pod condition `Ready=True` 的 `lastTransitionTime` |
| `t_first_step` | 第一步开始时刻 | 第一个 batch 就绪之后、算力开始之前打点 |
| `t_last_step` | 最后一步结束时刻 | 最后一个 epoch 的最后一个 step 返回之后打点 |

```text
启动 makespan = t_first_step − t_submit
全程 makespan = t_last_step − t_submit
就绪后阶段   = t_last_step − t_pod_ready
```

measure 脚本在 stdout 写一行 `RESULT key=value ...`，每个 epoch 边界写一行 `[EPOCH_BOUNDARY] epoch=<n> ts=<epoch秒>`。runner 解析这两类标记，不读 Pod 内文件。`metadata.creationTimestamp` 只作交叉核对，不作 `t_submit`。

epoch 0 的前 10 步标为 warmup，不进 stall 聚合，仍计入 makespan。

## stall

每一步记两个时长，单位 s。

| 符号 | 含义 |
|---|---|
| `wait_s` | 从本步开始等待 batch 到 batch 就绪的时长 |
| `step_s` | batch 就绪到本步计算结束的时长 |

```text
stall = wait_s ÷ step_s
```

`stall` 是无量纲比率。聚合报 `mean` 与 `p90`，中位数只用于判断是否处于 stall 形态。warmup 的 10 步不参与聚合。中位数对带宽档不敏感，预取吸收了档间差异，所以它只能判形态。

## 命中率

命中率的定义是该块打开时有没有触达源站。三阶段边界如下。

| 阶段 | 起点 | 终点 |
|---|---|---|
| startup | `t_submit` | `t_first_step` |
| steady | `t_first_step` | 第一次切换事件 |
| switch | 切换事件时刻 | 新窗口 K 块全部就绪；未就绪时截到该 epoch 结束 |

每个 epoch 边界算一次切换事件，三种 shuffle 策略相同。curriculum 的 stage 边界额外算一次。两个窗口同时活跃时按 switch 记。阶段切分与 agentd 的 `phase` 标签同口径。

```text
hit_rate_<phase> = 1 − demand_miss_bytes_<phase> ÷ read_bytes_<phase>
source_saving_ratio = 1 − fetch_bytes_run ÷ read_bytes
```

`read_bytes_<phase>` 是训练侧按阶段累计的打开字节（B），`demand_miss_bytes_<phase>` 是打开时本地不存在、需要等预取或回源的字节（B）。`hit_rate` 无量纲。`fetch_bytes_run` 是 `traincache_fetch_bytes_total` 在 run 窗口内的增量（B），`source_saving_ratio` 衡量省下的源站流量，与命中率分列。

组态口径不同，产物列 `hit_rate_basis` 写明来源。

| 组态 | 命中率口径 |
|---|---|
| `traincache-cold`、`traincache-warm` | 训练侧块打开时记账的字节账，精确到块 |
| `direct` | 按 0 记，无缓存层 |
| `juicefs-*`、`fluid-*` | warm 近似全命中，cold 近似全回源，按分片粒度 |

agentd 侧 `traincache_cache_hits_total`、`traincache_cache_misses_total` 按 `phase` 折成 `hit_ratio_agent_*` 作交叉校验。两侧差异超过 5% 时，以训练侧字节账为准。

## 三笔字节成本

三笔账都从 run 窗口的计数器增量取，单位 B。

| 账目 | 符号 | 范围 | 算法 |
|---|---|---|---|
| 启动预热 | `warmup_bytes` | 预热阶段 | `WARMUP_K`（预热块数）× 8388608 × 实际 fanout；juicefs-warm 与 fluid-warm 按整份数据集计 1 份；冷组与 `direct` 记 0 |
| 持续预取 | `sustained_prefetch_bytes` | 训练开始到结束 | `reason=prefetch` 的增量中落在非切换窗口的部分 |
| 切换重预取 | `switch_reprefetch_bytes` | 每个 switch 窗口 | `reason=prefetch` 的增量中落在切换窗口的部分 |

两笔预取之和应等于窗口总量，对不上时按实际值报告并在行内标注。

```text
sustained_prefetch_bytes + switch_reprefetch_bytes = prefetch_bytes_run
```

三笔账之和就是该格的字节成本；fanout 造成的重复字节计入成本，不折算成有效字节。做收益对比时，横轴取字节成本，纵轴取 makespan 改善。源站出站字节取 MinIO 的 `minio_s3_traffic_sent_bytes` 窗口增量，与训练侧 fetch 字节的差异记 `origin_reconcile_diff`，差异超过 5% 时以源站为准。

## K_cache

`K_cache` 是缓存容量折算出的块数，由 controller 计算，随产物落盘。

```text
K_cache = floor(cacheCapacityBytes × maxFillFraction ÷ (podCount × chunkSize))
```

| 符号 | 含义 | 单位与取值 |
|---|---|---|
| `cacheCapacityBytes` | 该格的缓存容量，等于 4294967296 ÷ ρ | B |
| `maxFillFraction` | 缓存可填充比例 | 0.125，无量纲 |
| `podCount` | 预热覆盖的 Pod 数 | 本装置取 1 |
| `chunkSize` | 块大小 | 8388608 B |

ρ=8 时缓存容量 536870912 B，`K_cache` = floor(536870912 × 0.125 ÷ 8388608) = 8 块。ρ=0.5 时 `K_cache` 为 128 块，ρ=1 为 64 块，ρ=2 为 32 块，ρ=4 为 16 块。`K_cache` 是派生量，不作独立实验轴，每格的实际值写进 `lock.json`。

上式只覆盖 controller 自动算 K 的路径。COND 里显式写 `k` 时按填写的值执行，`maxFillFraction` 超限只发 Warning 不拒绝。对照族与并行下载族的 warm 组走显式 K。

## 缓存峰值与声明容量

`cache_dir_peak_bytes` 是 run 窗口内单节点 `/var/cache/traincache/blocks` 下已完成块文件的字节和的最大值，单位 B。预取在途的 `tmp-*` 半成品不计入。

```text
r_peak = cache_dir_peak_bytes ÷ cache_bytes
```

`cache_bytes` 是该格 COND 的声明容量（B）。`capacity_bytes_final` 是 agentd 训练结束时的在用字节。`r_peak` 无量纲，判定按淘汰生效这条判据执行，倍率只记不判。

倍率同时以 `cache_peak_ratio` 列落在 `summary.csv` 里，读数直接取这一列，不靠两列相除。

`capacity_bytes_final` 取各 agentd `traincache_cache_capacity_bytes_total` 的最大值。它与同节点目录末次采样的比值落在 0.5 到 1.5 之外时，该轮的字节维度读数只作诊断。

## 全体判据

全体判据适用于所有族，族内特有的阈值在按族的判据里。

| 判据名 | 阈值 | 判定方式 |
|---|---|---|
| 采样与统计 | 每格 3 次采样；区间用 10000 次 bootstrap 重采样 | 报平均数与 95% 置信区间 |
| 赢 | 相对比较对象的改善 ≥ 5% 且差值 CI 上界 < 0 | makespan 越低越好，命中率越高越好 |
| 输 | 恶化 ≥ 5% 且差值 CI 下界 > 0 | makespan 越高越差，命中率越低越差 |
| 相近 | 差值 CI 含 0 | 只写分不出快慢 |
| 可忽略 | CI 不含 0 且均值差 < 5% | 与相近分开记 |
| 字节账自洽 | `sustained + switch_reprefetch` 等于 `prefetch_bytes_run` | 差值为 0 记通过，否则按实际值报告 |
| 淘汰生效 | `evict_blocks_run` > 0 | 等于 0 且 `r_peak` > 1.05 时整轮作废，记 `evict_not_engaged` |
| 峰值倍率 | `cache_peak_ratio` = `cache_dir_peak_bytes ÷ cache_bytes` | 只记录，不判定 |
| 作废 | 整轮作废，保留现场 | 作废轮不进汇总，不挑点删除 |

声明容量在当前实现下是软上限，峰值可以超过声明值，所以没有「上限压住」这条判定，倍率只记不判。成因在 agent 侧：`agent/collector` 的 `ListForEviction()` 只返回被 `Open` 或 `Touch` 过的指纹，预取写入但还没被训练消费掉的块不在候选集里，按目录 mtime 删的兜底只在候选集为空时启用；预取因此能在两次淘汰之间把远超 418 MB 的字节写进缓存。要恢复按上界判定，得先把预取写入的块纳入淘汰候选集，或给写入侧加硬限，这属于 agent 线的改动。

「淘汰生效」那条不受影响：峰值超过容量本身不作废，只有淘汰计数不动时才作废，这正是 `bench/compare/run_bench.py` 里 `evict_not_engaged` 的判定。

## 按族的判据

| 族 | 判据名 | 阈值 | 判定方式 |
|---|---|---|---|
| `compare` | 组间胜负 | 5% | 逐 ρ 判定；`direct` 只有 ρ=4 一个代表点，ρ≠4 的格子回退对照同带宽的 ρ=4 格 |
| `gateway` | 网关缓存 | G2 对 G0 的源站字节比落在 12 ± 5%。G2 侧取网关记的源站字节，G0 侧取 MinIO 出站，两边都只算 Get 路径的流量 | 越界说明片段缓存没接住重复回源，整轮作废 |
| `gateway` | 臂间比较 | 5% | 同格 3 次，两两比 makespan 与源站字节 |
| `evict` | 策略可分辨 | 两两相对差 ≥ 5% | 命中率、`total_makespan`、`b_evictions_of_hot` 任一项越界即记可分辨 |
| `evict` | 策略不可分辨 | 三项相对差都 < 5% | 只写三档无差异 |
| `prefetch` | 转平 | 相邻 lookahead 档改善 < 5% | 记转平点，不判胜负 |
| `prefetch` | 重复字节 | fanout 每加 1，预热字节按份数增加 | 从三笔账直接读，不进百分比判据 |
| `warmup` | 门控有效 | 启动 makespan 改善 ≥ 10% | ρ > 1 的格子 |
| `warmup` | 门控无价值 | 差值在 ±5% 内 | 1000 mbit 的格子 |
| `warmup` | 门控负收益 | 恶化 ≥ 5% | 在图上标出 |
| `switch` | 回落 | 阈值 = max(1.1 × 基线, 基线 + 5pp) | 10 步滚动均值首次 ≤ 阈值且之后连续 10 步保持 |
| `switch` | 差异 | 20% | 单次测量不判胜负 |
| `switch` | 右删失 | 到 epoch 末仍未回落 | 回落时间按 epoch 末计，单独报删失率 |
| `multiconsumer` | 热比例效应 | 5% | 比命中率与 makespan |
| `e2e` | 恢复成功 | 两阶段都跑完，且恢复窗口 `fetch_requests{result="error"}` 增量为 0 | 二值判定 |
| `rangepar` | 并行收益 | l0 的开臂关臂 makespan 比落在 0.9 到 1.1；l1 与 l2 的比值不小于 1.8；l3 的比值不小于 1.5 | 同档两臂各 3 次，比 `total_makespan` 的中位数 |
| `rangepar` | 字节守恒 | 两臂的 `origin_egress_bytes` 与 `fetch_bytes_run` 差异小于 2% | 并行不得靠多打字节换时间 |
| `rangepar` | 命中不退化 | 开臂 `hit_rate` 不低于关臂 2 个百分点 | 同一数据集同一容量，命中不应因并行而变 |

`e2e` 每场景 2 次采样，共 6 跑，不受每格 3 次采样的约束；该族只做二值判定，不报 CI。

`switch` 的回落基线取切换前 20 步的 stall 均值。基线不足 20 步的事件标 `insufficient_baseline`，不进回落曲线。

`rangepar` 的两臂只差 Range 并行开关，比较在同档内做。开臂每块发 4 条 Range GET，连接数是关臂的四倍，所以「并行收益」那条读的是端到端效果，含「单块内并发提高」这一项。

## 混沌族判据

混沌族的判据是二值，按故障逐条判定。

| 故障 | PASS 判据 |
|---|---|
| `kill_agent` | 替代 Pod Ready 且 UID 与旧 Pod 不同；RESCAN_PHASE 离开 SAMPLING；隔离块数为 0；观察窗口内 fetch 字节增量不超过单块字节 |
| `netem_degrade` | `traincache_read_stall_seconds_bucket{le="60"}` 的计数等于 `traincache_read_stall_seconds_count`；训练 Pod 不退出 |
| `netem_degrade_rate` | qdisc 回读里有 tbf 与 netem；读等待全部落在 60 s 桶内；训练 Pod 不退出 |
| `minio_down` | WarmupTask `status.phase` 出现 Degraded；训练 Pod 进入 Failed 或 Succeeded，或 Job 的 `status.failed` 非 0；源站恢复后训练 Pod 重建为 Running，恢复窗口内 error 增量为 0 |
| `tamper_block` | RESCAN_PHASE 走完 FULL_SCAN；`traincache_fetch_requests_total{reason="repair"}` 增量 ≥ 1；隔离块数与修复队列取窗口峰值 |
| `stop_ordersrc` | `traincache_agent_ordersources{state="stalled"}` ≥ 1；`traincache_agent_degraded` 走 0 到 1 再到 0 |
| `node_loss` | 节点 NotReady；WarmupTask `status.phase` 为 Degraded；容器启动回来后节点 Ready，`phase` 仍是 Degraded（门控决策是本代终态，不退回） |

混沌族取 kill_agent、tamper_block、minio_down 三类故障作轴。每档取三个时点：注入前基线、注入窗口内的周期采样、注入后终值。counter 判据取窗口差分，gauge 判据取终值。

## D2 makespan 起止

结论：起点是 runner 在 `kubectl apply` 前取的时刻，注入 `TRAINCACHE_JOB_CREATED_AT`；终点分首步与末步两个口径，由训练脚本自报；`metadata.creationTimestamp` 只作交叉核对。
原因：七组态共用同一把计时尺，API server 落盘延迟不进启动时间。

## D5 字节成本三笔全记

结论：启动预热、持续预取、切换重预取三笔都记，fanout 造成的重复字节计入成本。
原因：预热成本不能靠隐藏重复字节变小。

## D6 缓存欠配用显式容量上限

结论：agentd 淘汰侧设显式容量上限，不用容器内存限制。
原因：对照组是缓存目录语义，内存限制对不齐。

## D11 对照组公平性

结论：同一轨迹、同一 tc 档、同一份数据；预热在 `group_up` 内完成并等待，超时 15 分钟整轮作废，预热时长单列不计入 makespan。
原因：热读组不能靠预热时间占便宜。

## D12 正式跑分前预注册

结论：正式跑分前冻结族的轴、ρ 取值与判据，此后不回改。
原因：防止看到结果再调参。

## D14 异常轮整轮作废

结论：整轮作废并保留现场，作废轮不进汇总。
原因：避免选择性报告。

## D15 集群规模

结论：kind 4 个 worker，共 5 个节点，每个节点 32 核 / 31 GB；对照与被测同集群。
原因：读数与装置在同一集群，不引入跨集群差异。

## D16 对照层负载形态

结论：标准库脚本按轨迹读完整分片后丢弃，每步 `matmul` 跑满 `COMPUTE_MS=200` ms，不依赖训练框架。
原因：七组态同形，镜像轻，去掉训练框架这个变量。

## D20 实验块大小取 8 MiB

结论：`trainpublish -chunk-size` 取 8 MiB，随产物归档；生产默认 64 MiB 不动。
原因：ρ=8 时缓存 0.5 GiB，64 MiB 块只有 8 块，32 块预取窗口是缓存的四倍；8 MiB 得 64 块，窗口占一半。

## D21 限速与块大小解耦

结论：带宽是链路属性，块大小只改请求数与单请求时长；tc 对七组态透明。
原因：两者混在一起，跨档结果无法解释。

## D24 缓存跨 Pod 持久

结论：JuiceFS 缓存用 hostPath，不用 emptyDir。
原因：预热成果不能随测量 Pod 销毁。

## D25 命中率口径

结论：主口径是 `1 − demand_miss ÷ 读字节`，分阶段落列；`source_saving_ratio` 另列不混用；JuiceFS 与 Fluid 按 warm 全命中、cold 全回源近似，标 `hit_rate_basis`。
原因：对照组不编造块级指标，自家数字能自证。

## D30 基线与被测格分离

结论：`direct` 只跑一次，代表点 ρ=4；四个缓存基线 `juicefs-cold`、`juicefs-warm`、`fluid-cold`、`fluid-warm` 随 ρ 一起跑，配额跟着 ρ 变；被测格 `traincache-cold` 与 `traincache-warm` 跑满五个 ρ。
原因：`direct` 没有缓存，五个 ρ 的读数相同，重复跑只填同一批数字；四个缓存基线的容量是实验变量，不跟着 ρ 变就没有同配额对照，跨组比较的容量口径对不上。

## D31 带宽是自变量

结论：rate 取 100、300、1000 mbit，随 COND 落盘；burst 按 0.1 秒传输量推导为 1250k、3750k、12500k；netem 只挂固定 `delay 20ms`。
原因：随机时延打乱包序，300 mbit 档实测从 35.6 MB/s 跌到 0.6 MB/s 以下，档间差异被装置掩盖。

## D32 机时结构

结论：rep 之间只清缓存，不 down/up 组件；warm 组每个 rep 重新预热；各族串行跑，不并行。
原因：rep 复用省约 2 分钟；tc 是全组共享出口，并行等于均分带宽。

## D36 Fluid 可行性冒烟

结论：开跑前做只验可行性的冒烟，通过条件三条：控制面与 Runtime 全 Ready 且缓存目录可写；整份数据集读完、400 步无 OOM 驱逐重启；Fluid 额外占用不超过 6 CPU / 6 GiB。两次环境性失败记 `fluid-unavailable-on-kind`，该格标 `unavailable`，不补跑。
原因：先确认 Fluid 能跑完，再拿它当参照。

## D40 切换回落判据

结论：基线取切换前 20 步 stall 均值；阈值取 `max(1.1 × 基线, 基线 + 5pp)`；切换后 10 步滚动均值首次不超过阈值、且之后连续 10 步保持，记为回落点；到 epoch 末未满足记右删失并报删失率；缺 20 步基线的事件标 `insufficient_baseline`。
原因：判据先冻结，回落时间才有可比性。

## D41 快照与源数据

结论：MinIO 的 `bench-b/shard-*.tar` 是唯一源数据；正式读数用 8 MiB 块的 `compare-data-8m` 快照，DataSet CRD 指向它；数据集取前 16 片。
原因：源数据不复制，块大小由快照固定。

## D54 Range 并行判定改用开关

结论：取消块大小阈值，改用开关 `fetchRangeParallel` 且默认打开：每个块一律拆成 4 条 Range GET 并行取，块大小不参与判定。
原因：阈值只对生产默认块大小（64MiB）生效，实验用的 8MiB 块要另调一个键；开关默认打开后所有块走同一条取数路径，实验与生产可比。
