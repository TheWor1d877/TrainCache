# 6.1 缓存核心库设计（design）

> 需求来源：`6.0 缓存核心库设计方法.md`。本文档是核心库的冻结约定：
> 接口签名、数据格式、包结构。任何实现子代理不得私自修改，变更需回传 BLOCKED 由主对话裁决。
> 配套文档：`6.2 plan.md`（里程碑与验收）、`6.3 decisions.md`（决策与未决问题）。

## 1. 库的定位

一个**无服务形态的 Go 库**（代码 + 单元测试），供层2 Agent（及未来 Controller 侧组件）内嵌使用。职责三条：

1. **记录有哪些数据块**——路径索引层：`(path, chunkIndex) → 块指纹` 的映射，以快照形式存对象存储；
2. **按内容落盘**——CAS 存储层：以 xxh3-128 指纹为键，内容去重、读回校验；
3. **按需下载**——抓取编排层：限流下载、指令合并、校验失败重下。

**非目标**：不是服务进程、不含网络协议/调度逻辑（那是 Agent/Controller 的职责）、不做跨路径索引去重（去重发生在 CAS 层）。

## 2. 需求 → 设计落点映射

| doc/7 需求条目                                                    | 设计落点                                                                          |
|-------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| 索引表记录 (path, chunkIndex) → 块存储节点                        | `index.Entry`（含 `Node` 字段）                                                   |
| 表太大放对象存储、切分片、每片 ≤10 万条                           | `index` 分片格式与构建规则（§6.2、§8）                                            |
| 原子提交 + 快照（写新块→新分片→上传→验证→条件提交→读侧刷新→清理） | `index.Writer.Commit`（§7.1）、`index.Catalog`（§7.2）、`index.Collector`（§7.3） |
| 写盘原子性：临时文件 + rename()，不做逐块 fsync                   | `cas.Store.Put`（§7.4）                                                           |
| 对象存储结构 dataset/snapshots/CURRENT                            | §6.1                                                                              |
| CAS：下载时算 xxh3、指纹命名存盘、读回校验、跨路径去重            | `cas` 包（§5.2）、块文件布局（§6.3）                                              |
| 引用计数 = 已提交快照的逻辑引用；读操作生命周期单独管理           | `cas.Acquire/Release` + pin 语义（§7.3）                                          |
| sha256 可选校验，verify_level 开关，只影响新写块                  | 块头 flags bit0 + `cas.VerifyLevel`（§6.3）                                       |
| 并发抓取：按在途字节数限流 + 单主机连接数 + 最大任务数            | `fetch.Limiter`（§5.3）                                                           |
| 相同指令合并、缓存命中不触及数据源                                | `fetch.Fetcher` in-flight map                                                     |
| 单测四场景：并发写同块 / 写半崩溃 / 去重 / 校验失败重下           | §9 验收标准                                                                       |

## 3. 总体架构与依赖方向

```
                ┌──────────── index ────────────┐
                │ Writer / Catalog / Collector  │   记录块→节点映射、快照、提交、刷新、回收
                └──────┬───────────────┬────────┘
                       │               │
            ┌──────────▼──┐      ┌─────▼──────────┐
            │    cas      │      │  objectstore   │   对 S3 兼容对象存储的抽象（含条件写入）
            │  本地块存储   │      └─────▲──────────┘
            └──────▲──────┘            │
                   │            ┌──────┴──────────┐
            ┌──────┴───────────┐│      fetch       │   下载编排：限流、合并、重试
            │  fetch（下载编排） │└──────▲──────────┘
            └──────▲──────────┘       │
                   │        ┌─────────┴──────────┐
                   │        │  internal/digest   │   xxh3-128 / sha256 封装
                   └───────►└────────────────────┘
```

依赖方向**单向无环**：`index → cas、objectstore`；`fetch → objectstore、cas`；`cas → internal/digest`（仅本地文件系统，**不依赖 objectstore**——下载字节流由 fetch 喂给 cas.Put，两层解耦）。

## 5. 核心接口（冻结约定）

### 5.1 objectstore

```go
package objectstore

var (
    ErrNotFound = errors.New("objectstore: object not found")
    ErrConflict = errors.New("objectstore: conditional write conflict")
)

// Store 是对 S3 兼容对象存储的最小抽象。
type Store interface {
    // Get 将对象内容完整写入 w；不存在返回 ErrNotFound。
    Get(ctx context.Context, key string, w io.Writer) error
    // Put 上传对象，返回服务端 ETag。对相同内容 ETag 必须稳定（S3 简单上传语义）。
    Put(ctx context.Context, key string, r io.Reader, size int64) (etag string, err error)
    // Delete 删除对象；对象不存在不算错误。
    Delete(ctx context.Context, key string) error
    // GetETag 返回对象当前 ETag；不存在返回 ErrNotFound。
    GetETag(ctx context.Context, key string) (string, error)
    // PutIfMatch 条件写入：expectedETag 为空串时要求 key 不存在（If-None-Match: *），
    // 否则要求当前 ETag == expectedETag（If-Match）。冲突返回 ErrConflict，不写入。
    PutIfMatch(ctx context.Context, key string, r io.Reader, size int64, expectedETag string) (newETag string, err error)
    // List 返回匹配 prefix 的全部对象键（字典序升序）；无匹配返回空切片（D19）。
    // 供 index.Collector.Sweep 枚举快照对象用。
    List(ctx context.Context, prefix string) ([]string, error)
}

// 构造器（M1 冻结）：
func NewMock() *Mock
func NewMinIOStore(endpoint, accessKey, secretKey, bucket string, secure bool) (*MinIOStore, error)
```

### 5.2 cas

```go
package cas

// 块头（header.go，M2 实现；字节布局见 §6.3）：
const (
    HeaderSize    = 128    // 块头字节数
    FlagHasSHA256 = 1 << 0 // flags bit0：块头含有效 sha256
)

const Magic = "TCBK" // 块头 magic（4 字节）

type Header struct {
    Version   uint16   // = 1
    Flags     uint16   // FlagHasSHA256 置位时 SHA256 字段有效
    BlockSize uint32   // 数据字节数（不含块头）
    XXH3      [16]byte // 数据指纹 = 存储键
    SHA256    [32]byte
}

func ParseHeader(b []byte) (Header, error) // 校验 magic/version/reserved 区；长度不足报错
func (h Header) Encode() [HeaderSize]byte  // 编码为 128 字节（reserved 区置 0）

type Fingerprint [16]byte // xxh3-128，作为存储键

func (f Fingerprint) String() string                    // 32 字符小写 hex
func FingerprintFromHex(s string) (Fingerprint, error)  // 解析 32 字符 hex（长度/字符不符报错）

type VerifyLevel int
const (
    VerifyXXH3        VerifyLevel = iota // 默认：只验 xxh3
    VerifyXXH3SHA256                     // 新写块时同时算 sha256 写入块头，读时双重校验
)

var (
    ErrCorrupt  = errors.New("cas: block verification failed")
    ErrNotFound = errors.New("cas: block not found")
    ErrInUse    = errors.New("cas: block is referenced or being read")
)

type Store struct { /* dir、verify、refcount 表（内部） */ }

func New(dir string, verify VerifyLevel) (*Store, error)

// Put 流式写入：边读边算指纹，写临时文件，完成后 rename 到 blocks/<fp[0:2]hex>/<fp hex>.blk。
// 同指纹并发写安全（rename 原子，最终文件完整）；返回指纹与数据字节数。
// 不做 fsync（丢失代价 = 重拉）。
func (s *Store) Put(ctx context.Context, r io.Reader) (Fingerprint, int64, error)

// Open 打开块并校验：读块头验证 magic/version，流式重算数据 xxh3（及 sha256，按块头
// flags 与 Store.verify 决定）比对；不符返回 ErrCorrupt（调用方负责 Remove 后重拉）。
// 校验通过后返回从数据区起读的句柄。
func (s *Store) Open(fp Fingerprint) (*BlockReader, error)

// Remove 删除块；仍有引用或读者（pin）时返回 ErrInUse。
func (s *Store) Remove(fp Fingerprint) error

// Evict 只删除块的本地副本，供 Agent 层磁盘淘汰用（D28）：refcount 不拦
// （引用是快照级逻辑簿记，与副本是否在本地无关），pin>0 返回 ErrInUse；
// 已不存在返回 ErrNotFound（与 Remove/Sweep 并发安全）。索引条目不受影响，
// 后续读取经 Catalog.Lookup 命中 + Open 得 ErrNotFound 后由 fetch 重下。
func (s *Store) Evict(fp Fingerprint) error

// Acquire/Release 引用计数：Acquire +1（引用计数 = 已提交快照对该 CAS 块的逻辑引用）；
// Release -1，归零后块进入可回收状态。读操作不占引用计数，用 Pin/Unpin 单独管理生命周期。
func (s *Store) Acquire(fp Fingerprint) error
func (s *Store) Release(fp Fingerprint)

// Pin/Unpin 读操作生命周期：Pin 计数 >0 时 Remove 必须返回 ErrInUse。
func (s *Store) Pin(fp Fingerprint) error
func (s *Store) Unpin(fp Fingerprint)

// List 枚举 blocks/ 下全部块指纹（D20）：忽略临时文件与非法文件名；供 GC 枚举用。
func (s *Store) List() ([]Fingerprint, error)

// Quarantine 把 Open 校验失败的坏块物理移入 cas 根下 quarantine/ 目录（与 blocks/ 并列），
// 不再出现在 List() 中。幂等：源块不在 blocks/（已在 quarantine 或从未存在）返回 nil；
// 目标已存在时 rename 原子覆盖。不检查 refs/pins（坏块隔离是正确性动作，引用计数是
// 索引层的逻辑关系，修复后同指纹块回原位、引用不变）；持 s.mu 与 Remove/其他 Quarantine
// 串行。仅真实 I/O 错误报错。
func (s *Store) Quarantine(fp Fingerprint) error

// ListQuarantined 枚举 quarantine/ 下全部块指纹（与 List 同规则：忽略临时文件与非法
// 文件名，按指纹字节序升序，无块返回空切片）。供修复队列与重扫描枚举隔离块用。
func (s *Store) ListQuarantined() ([]Fingerprint, error)

// RemoveQuarantined 删除 quarantine/ 下的块（修复成功后清理）；目标不存在返回 nil
// （同 objectstore.Delete“不存在不算错误”语义）。仅真实 I/O 错误报错。
func (s *Store) RemoveQuarantined(fp Fingerprint) error

type BlockReader struct { /* 包装 *os.File，从块头之后开始读 */ }
func (r *BlockReader) Read(p []byte) (int, error)
func (r *BlockReader) Close() error
func (r *BlockReader) Size() int64 // 数据字节数（块头 block_size）
```

### 5.3 fetch

```go
package fetch

type Options struct {
    MaxInflightBytes int64 // 在途下载字节上限（信号量口径，非 goroutine 数），默认 1 GiB
    MaxConnsPerHost  int   // 单主机连接数上限，默认 64
    MaxTasks         int   // 最大并发下载任务数，默认 8
    MaxRetries       int   // 校验失败重下次数，默认 3
}

var ErrTooManyRetries = errors.New("fetch: verification failed after max retries")

type Fetcher struct { /* objectstore.Store、*cas.Store、limiter、in-flight map（内部） */ }

func New(store objectstore.Store, cs *cas.Store, opts Options) *Fetcher

// Fetch 下载对象：Acquire(expectSize) 字节信号量 → store.Get 流经 cas.Put 落盘 →
// Open 读回校验 → 失败则 Remove 后重试（≤ MaxRetries）→ Release 信号量。
// 相同 key 的并发 Fetch 合并为一次实际下载（in-flight map，等待者共享结果）。
// 返回块指纹。命中检查是调用方职责：先经 index.Catalog.Lookup 取指纹、cas.Open
// 验存在，未命中才调用本方法（对应 docs/7 "缓存命中就不触及数据源"）。
// 簿记契约：Fetch 不做 Acquire；调用方在首次写入时 Acquire 一次即可。Evict（D28）
// 只删本地副本不动引用，故副本被 Evict 后经本方法重下时不得重复 Acquire（D28）。
func (f *Fetcher) Fetch(ctx context.Context, key string, expectSize int64) (cas.Fingerprint, error)
```

### 5.4 index

```go
package index

// Config 是 index 包的全局配置（默认值见 DefaultConfig；design.md §8 配置项表）。
type Config struct {
    ChunkSize          int64         // 块切分粒度，默认 64 MiB（decisions D4）
    MaxEntriesPerShard int           // 分片条目上限，默认 100_000（doc/7 硬约束）
    CommitMaxAttempts  int           // 条件提交冲突重试上限，默认 5
    RetainSnapshots    int           // GC 保留窗口，默认 3（CURRENT + 2，decisions D14）
    RefreshInterval    time.Duration // Catalog 后台刷新周期，默认 5 s
}

func DefaultConfig() Config

// 构造器（M1/M4 冻结）：
func NewWriter(store objectstore.Store, cs *cas.Store, cfg Config) *Writer
func NewCatalog(store objectstore.Store, dataset string, cfg Config) *Catalog // 绑定单个数据集（D17）
func NewCollector(store objectstore.Store, cs *cas.Store, cfg Config) *Collector

// Entry 是索引表的一条记录：路径下第 chunk 块。
type Entry struct {
    Path        string          `json:"path"`
    Chunk       int64           `json:"chunk"`   // 块序号；块字节范围 = [chunk*ChunkSize, +Size)
    Size        int64           `json:"size"`    // 数据字节数（末块可不足）
    Fingerprint cas.Fingerprint `json:"fp"`      // CAS 指纹，JSON 编码为 hex
    Node        string          `json:"node,omitempty"` // 块实际落盘的节点名
}

type ShardRef struct {
    Key         string `json:"key"`     // 分片对象完整键：dataset/<name>/snapshots/<id>/shard-<fp8>.idx；
                                        // 未变更分片跨快照复用保留首次创建时的完整键（D18）
    MinPath     string `json:"min_path"` // 分片内首条 Entry 的 Path（条目按 (path,chunk) 字典序；D22）
    MaxPath     string `json:"max_path"` // 分片内末条 Entry 的 Path（D22）
    Entries     int64  `json:"entries"` // 该分片条目数
    Fingerprint string `json:"fp"`      // 分片内容 xxh3-128（hex），下载后完整性验证用
}

type Manifest struct {
    SnapshotID string     `json:"snapshot_id"`
    CreatedAt  time.Time  `json:"created_at"`
    Shards     []ShardRef `json:"shards"`
}

// 对象存储键函数（布局见 §6.1）：
func SnapshotPrefix(dataset string, snapID string) string // dataset/<name>/snapshots/<id>/
func ManifestKey(dataset string, snapID string) string
func ShardKey(dataset string, snapID string, fp8 string) string
func CurrentKey(dataset string) string                   // dataset/<name>/CURRENT

// ChunkSize 全局块切分粒度在 Config 中（默认值见 DefaultConfig；decisions.md D4/Q2）。

var (
    ErrInvalidShard = errors.New("index: shard fingerprint mismatch")
    ErrNoCurrent    = errors.New("index: CURRENT not found")
)

// Writer 是写入方 + 分片构建任务 + 提交方（docs/7 步骤 2–5）。
type Writer struct { /* objectstore.Store、*cas.Store、分片参数（内部） */ }

// Commit 将 entries（本次变更的增量 upsert）与当前快照合并，构建新快照并原子提交：
// 读 CURRENT → 读当前 manifest+受影响分片 → 合并重排（分片 ≤ MaxEntriesPerShard 条，
// 未变更分片物理复用同一对象键）→ 上传新分片与新 manifest（独立键，未提交不可见）→
// 验证（分片指纹、manifest 完整）→ PutIfMatch 更新 CURRENT（内容 "<snapID> <manifestFP8>"，
// expectedETag = MD5(期望的旧 CURRENT 内容)）→ 冲突则重读最新快照重试。
// 新块本身（步骤 1）由调用方先行经 cas.Put / fetch.Fetch 落盘，Commit 负责索引侧。
func (w *Writer) Commit(ctx context.Context, dataset string, entries []Entry) (snapID string, err error)

// Catalog 是清单管理方（读侧）：内存维护 块→位置 映射，定时刷新，原子切换。
type Catalog struct { /* objectstore.Store、refresh 间隔、atomic.Pointer[snapshotState]（内部） */ }

// Start 启动后台刷新循环（每 refreshInterval 读一次 CURRENT）；ctx 取消即停止。
func (c *Catalog) Start(ctx context.Context)
// Refresh 手动执行一次刷新：CURRENT 未变则跳过；变了则下载 manifest → 逐分片下载并
// 验证指纹 → 构建新映射 → atomic.Pointer 一次性切换（绝不边加载边改旧映射）。
func (c *Catalog) Refresh(ctx context.Context) error
// Lookup 查询块→位置映射；false = 当前快照中无该条目；ErrNoCurrent = 尚无任何快照。
func (c *Catalog) Lookup(ctx context.Context, path string, chunk int64) (Entry, bool, error)

// LoadPrefixes 按前缀加载索引分片（D23）：读 CURRENT → 下载 manifest（仅 ShardRef 列表，
// 体积小，全量）→ 仅下载、校验、加载与任一 prefix 路径前缀匹配相关的分片（D22 范围判定：
// 分片相关 ⟺ MaxPath ≥ prefix 且 (MinPath ≤ prefix 或 MinPath 以 prefix 开头)）→
// 构建局部内存映射 → atomic.Pointer 原子切换。空 prefixes = 不加载任何分片（映射为空）；
// 含空串元素 = 匹配一切（全量）。失败不动旧映射。与 Refresh/Start 为互斥使用模式
// （宿主二选一；本方法不做后台循环，前缀集变化由宿主再次调用）。
func (c *Catalog) LoadPrefixes(ctx context.Context, prefixes []string) error

// Collector 回收：旧快照/分片/块（docs/7 步骤 7）。
type Collector struct { /* objectstore.Store、*cas.Store（内部） */ }

// Sweep ① 计算活块集合 = 保留快照（CURRENT + 最近 2 个已提交快照）引用的指纹 ∪ 在途读者 pin；
// ② 扫描 cas 目录，删除不在活块集合且 refcount=0、pin=0 的块；③ 删除不在保留窗口内、
// 且不被保留快照引用的旧快照清单与分片对象。
func (c *Collector) Sweep(ctx context.Context, dataset string) (removedBlocks int, removedObjects int, err error)
```

## 6. 数据格式

### 6.1 对象存储键布局

```text
<bucket>/
└── dataset/<name>/
    ├── snapshots/<snapID>/manifest.json
    ├── snapshots/<snapID>/shard-<fp8>.idx      # fp8 = 分片内容 xxh3 前 8 字节 hex
    └── CURRENT                                 # 内容："<snapID> <manifestFP8>"（空格分隔，无换行）
```

- 快照**逻辑上是完整快照，物理上复用旧分片**：未变更分片的对象键（含内容指纹）不变，无需重传；
- `CURRENT` 携带 manifest 指纹 → 校验链完整：CURRENT → manifest → 各分片。

### 6.2 索引分片（shard-<fp8>.idx）

- 格式：**JSON 数组 of Entry**（字段名全称，见 §5.4）；fp 为 32 字符 hex；
- 分片构建规则：条目按 `(path, chunk)` 字典序排序后**按条目数切分**（range-based），每片 ≤ `MaxEntriesPerShard`（默认 100_000，doc/7 上限）；
- 完整性：分片内容 xxh3-128 记入 manifest 的 `ShardRef.Fingerprint`，读侧下载后重算比对，不符报 `ErrInvalidShard`；
- 路径范围：分片内首末条 Entry 的 Path 记入 manifest 的 `ShardRef.MinPath/MaxPath`（D22），供读侧按前缀过滤相关分片（不下载无关分片）。

### 6.3 CAS 块文件（blocks/<fp[0:2]hex>/<fp hex>.blk）

统一 **128 字节块头**（v1 即最终格式，不再做 64B 变体）：

```text
offset  size  field
0       4     magic  "TCBK"（0x54 43 42 4B）
4       2     version = 1
6       2     flags   bit0 = 块头含有效 sha256
8       4     block_size   uint32 LE（数据字节数，不含块头）
12      16    xxh3_128     数据指纹 = 存储键 = 文件名
28      32    sha256       flags bit0 置位时有效，否则全 0
60      68    reserved     全 0（对齐到 128B）
128     n     数据
```

- 存储键恒为 xxh3-128，去重逻辑不因 sha256 开关改变；
- `VerifyXXH3SHA256` 只影响**新写入**的块（老块 flags bit0=0 保持原样，读时按各自 flags 校验），不做全量重算；
- 坏块隔离（Quarantine，7.1 design §5.7）：坏块 rename 移入 cas 根下 `quarantine/<fp[0:2]hex>/<fp hex>.blk`（与 blocks/ 并列、同两级布局），不再被 `List()` 枚举，`ListQuarantined()` 枚举之。

### 6.4 manifest.json

`{"snapshot_id":"...","created_at":"...","shards":[{"key":"dataset/<name>/snapshots/<snapID>/shard-<fp8>.idx","min_path":"/a/...","max_path":"/b/...","entries":N,"fp":"<完整hex>"}]}`
（`ShardRef.Key` 为完整对象键（D18）：新分片位于本次快照目录；未变更分片跨快照复用保留首次创建时的完整键。
`ShardRef.Fingerprint` 存完整 16 字节 hex；文件名部分用其前 8 字节。`MinPath/MaxPath` 为分片路径范围（D22）。）

## 7. 关键流程

### 7.1 提交事务（`Writer.Commit`，对应 doc/7 步骤 1–5）

1. **写新块**（Commit 之前）：调用方经 `fetch.Fetch`/`cas.Put` 把新块写入 CAS——写新位置，不覆盖旧块（CAS 键 = 内容指纹，天然不覆盖）；`cas.Acquire` 引用 +1；
2. **写新分片**：读当前快照 S1 与受影响分片，合并本次 entries，重排生成新分片文件（本地临时文件 + rename），未变更分片复用旧键；
3. **上传对象**：上传新分片与新 manifest（独立对象键，提交前对读侧不可见——读侧只看 CURRENT）；
4. **验证完整性**：提交前确认 ① 新 manifest 已上传成功 ② manifest 引用的所有分片已写入且指纹一致 ③ 分片条目数符合上限 ④ 被引用的新块已在 CAS 发布且 `Open` 校验通过；
5. **原子提交**：`PutIfMatch(CURRENT, "<newSnapID> <newManifestFP8>", expectedETag=MD5("<oldSnapID> <oldManifestFP8>"))`；
   - 成功 → 新快照生效；
   - `ErrConflict` → 重读最新快照，基于它重新合并构建再提交（自动重试，上限 5 次后报错）。

### 7.2 读侧刷新（`Catalog`，对应 doc/7 步骤 6）

定时（默认 5s）读 CURRENT → 内容未变则跳过；变了：下载新 manifest → 逐分片下载并验证指纹 → 构建新内存映射 → `atomic.Pointer` 一次性切换。**加载新分片过程中绝不逐个修改正在服务的旧映射**；下载的分片与 manifest 均需验证完整性。

按前缀加载（`LoadPrefixes`，doc/7「索引分片按前缀目录加载」）：manifest 全量下载（仅 ShardRef 列表，体积小；GB 级索引主体在分片内），按 `ShardRef.MinPath/MaxPath` 与各 prefix 的范围交叠过滤相关分片（D22），只下载、校验、加载相关分片，构建局部映射后原子切换；失败不动旧映射。加载哪些前缀由 Agent 服务（宿主）决定，库只提供能力（D23）。

### 7.3 回收（`Collector.Sweep`，对应 doc/7 步骤 7）

- **旧快照/分片**：CURRENT 指向的快照不删；保留窗口 = CURRENT + 最近 2 个已提交快照；窗口外的快照若仍被 pin 的读者使用则跳过，否则删 manifest 及不被其他保留快照复用的分片对象；
- **旧数据块**：活块集合 = 保留快照索引可达的指纹 ∪ 读者 pin；只有 refcount=0、pin=0 且不在活块集合中的块才删除；仍被引用或正在被读的跳过，留待下次；
- 引用计数 = 已提交索引快照对 CAS 块的**逻辑引用**（不统计读操作），读操作生命周期由 pin 单独管理。

### 7.4 CAS 写入与并发（`cas.Store.Put`）

- 写盘原子性：先写 `tmp-<random>` 临时文件（指纹须读完整个流才能得到，故不以 `<fp>.tmp-*` 命名），完成（含块头编码）后 `rename()` 到 `blocks/<fp[0:2]hex>/<fp hex>.blk`——其他进程/goroutine 永远看不到写了一半的块；孤儿临时文件不影响 Open/后续 Put（M2 测试锁定）；
- **不做逐块 fsync**：掉电丢块代价 = 重新下载；
- 多 goroutine 并发写同一指纹：各写临时文件，rename 原子覆盖，最终文件必为完整块；同指纹内容必同（xxh3 碰撞概率视为 0，见 decisions.md D9）。

### 7.5 校验失败重下（`fetch.Fetcher.Fetch`）

下载 → `cas.Put` → `cas.Open` 读回校验 → `ErrCorrupt` 则 `cas.Remove`（无引用无 pin 前提成立：引用在 Fetch 成功后由上层 Acquire）→ 重试 ≤ MaxRetries → 仍失败报 `ErrTooManyRetries`。

## 8. 配置项

| `MaxRetries`         | 3       | 校验失败重下次数                                           |
| `RefreshInterval`    | 5 s     | Catalog 后台刷新周期                                       |

| `CommitMaxAttempts`  | 5       | 条件提交冲突重试上限                                       |

## 9. 验收标准（总闸）

`cd core && go build ./... && go vet ./... && go test ./...` 全绿，且单测**重点覆盖四场景**（doc/7 硬性要求）：

1. **多个 goroutine 同时写同一个块**——最终文件完整、指纹正确、无临时文件泄漏；
2. **写一半进程崩溃**——模拟：注入失败点使 Put 中途终止 / 预置孤儿临时文件，重开后 Put 同内容可正常完成、孤儿临时文件可被清理、Open 不受影响；
3. **相同内容去重**——同内容两次 Put 得到同一指纹、磁盘仅一份；
4. **校验失败后重新下载**——篡改块内容后 Open 报 ErrCorrupt，Fetch 路径自动 Remove + 重下后恢复。

（分里程碑的逐条验收见 7.2 plan.md。）
