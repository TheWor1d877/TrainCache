# agent 测试说明书

> 配套 design.md `7.1`、plan.md `7.2`、decisions.md `7.3`。

## 测试范围

agent(`traincache-agentd`)是缓存节点上的常驻服务,把 core 库包装成带 gRPC 接口和自治能力的进程。当前共 **52 个 `*_test.go` 文件**、**16,886 行测试代码**、**344 个 `Test` 函数**,覆盖 10 个包:api/agentpb、svc、prefetch、collector、evictor、rescan、ordersource、metrics、nodeid、internal/logging。

测试框架同 core:只有 Go 标准库 `testing`,不引第三方断言库、不打桩。指标断言用 `prometheus/client_golang/prometheus/testutil` 从 registry 取值;gRPC 层用 bufconn 做内存连接(不启动真实端口);对象存储和 CAS 沿用 core 的 mock/临时目录;Prefetcher 直接注入 mock Fetcher。

## 运行方式

```bash
# 全量（含竞态检测）
cd agent && go test ./... -race -count=1
# 示例输出摘要
# ok   traincache/agent/api/agentpb    0.3s
# ok   traincache/agent/svc            4.7s
# ok   traincache/agent/prefetch       2.8s
# ok   traincache/agent/collector      1.1s
# ok   traincache/agent/evictor        1.6s
# ok   traincache/agent/rescan         0.8s
# ok   traincache/agent/ordersource    0.9s
# ok   traincache/agent/metrics        0.4s
# ok   traincache/agent/nodeid         0.2s
# ok   traincache/agent/internal/logging 0.3s

# 只跑 gRPC server 相关
go test ./svc -run 'TestServer' -v

# 跑端到端场景（selfopen、e2e 结尾的文件名）
go test ./svc -run 'TestSelfopen|TestReadMiss|TestR1R3' -v
```

agent 的测试依赖 core 包,靠根 `go.work`(`use ./agent ./core ./controller`)解析,`agent/go.mod` 不写 replace(6.3 D2),跑之前要在仓库根 `go work sync` 过一次。
