| D1  | 库形态与位置                                        | 无服务 Go 库，独立 module `traincache/core`，代码放新目录 `core/`                                                                                                                                                                                                                                                                                                              | doc/7 明确"没有任何服务形态，现在就是一组代码加单元测试"；独立 module 与 bench 装置解耦                                                                                                                                                                                     |

| D8  | CURRENT 内容含 manifest 指纹                        | `"<snapID> <fp8>"`（空格分隔、无换行）                                                                                                                                                                                                                                                                                                                                         | 校验链闭环：CURRENT→manifest→分片，manifest 损坏可检出，成本仅一个字段                                                                                                                                                                                                      |
| D9  | 引用计数不持久化                                    | `Acquire/Release` 内存表；GC 判定以"保留快照可达 ∪ 读者 pin"为准，refcount 作快速过滤与冗余校验                                                                                                                                                                                                                                                                                | 持久化 refcount 有崩溃一致性难题（掉电丢失）；从快照重算可达集最可靠；doc/7 明确"引用计数是逻辑引用、读操作单独管理"（即 pin）                                                                                                                                              |
| D10 | 哈希实现                                            | xxh3-128 用 `github.com/zeebo/xxh3`（纯 Go）；sha256 用标准库；不自己实现                                                                                                                                                                                                                                                                                                      | doc/7 引用 xxh3 的 10GB/s 指标；zeebo/xxh3 是社区主流纯 Go 实现；xxh3 非密码学、碰撞概率视为 0，sha256 开关提供强校验兜底                                                                                                                                                   |

| D23 | Catalog 增 LoadPrefixes                             | `LoadPrefixes(ctx context.Context, prefixes []string) error`：读 CURRENT → 下载 manifest → 仅下载、校验、加载相关分片（D22 范围交叠判定）→ 局部映射原子切换；空 prefixes = 不加载任何分片（映射为空），含空串元素 = 全量；失败不动旧映射；与 Refresh/Start 互斥使用模式（宿主二选一，前缀集变化由宿主再次调用）                                                                | doc/7 建议 `Load(prefixes) 或 LoadShards(refs)`：裁决选 LoadPrefixes（语义明确；YAGNI 不提供 LoadShards）；前缀集决策属 Agent 服务职责（doc/7 明示"Agent 服务决定加载哪些前缀"）（2026-10-12 裁决）                                                                         |
| D24 | cas 增 Quarantine/ListQuarantined/RemoveQuarantined | 签名与 7.1 design §5.7 逐字一致，落入 6.1 §5.2。Quarantine 无条件移走坏块：不检查 refs/pins（坏块隔离是正确性动作，引用计数是索引层逻辑关系；修复后同指纹块回原位、引用不变），但持 s.mu 与 Remove/其他 Quarantine 串行（与 Remove 同模式）。ListQuarantined 与 List 同规则（字节序升序、空切片、忽略临时/非法名）。RemoveQuarantined 目标不存在返回 nil。新导出符号仅此三方法 | 7.0 要求“将块标记为坏块”；坏块留在 blocks/ 会让后续读持续失败，且被 List 枚举进入 Sweep 判定；引用计数不因隔离清零（修复后块回原位，索引引用天然恢复）                                                                                                                      |
| D25 | quarantine/ 目录布局                                | Store 增私有字段 rootDir 保存用户传入根路径；New 时 MkdirAll 根下 quarantine/；布局沿用 `<quarantineDir>/<fp[0:2]hex>/<fp hex>.blk`（与 blocks/ 同两级分片）；移动用 os.Rename（quarantine 与 blocks 同在根下，同文件系统，原子、无 EXDEV）                                                                                                                                    | §5.7 冻结“与 blocks/ 并列”；并列布局使 List() 与 index.Sweep 天然不枚举坏块，gc.go 零改动；两级分片沿用既有布局知识                                                                                                                                                         |

| D27 | Put 对已存在同指纹块行为（7.3 Q3 结案引用）         | cas.Put 对已存在同指纹块：先写临时文件再 rename 原子覆盖；指纹=内容，覆盖内容必相同，等价幂等跳过、不报错，实现无需修改。Agent 修复路径：坏块已被 Quarantine 移出 blocks/，重下 Put 直接落在空位                                                                                                                                                                               | 7.3 Q3（2026-10-14 查 core 结案）在 core 文档侧登记，使 6.x 决策链自洽                                                                                                                                                                                                      |
| D28 | cas 增 Evict（本地副本淘汰）                        | `Evict(fp Fingerprint) error`：只删块的本地副本；refcount 不拦（引用是快照级逻辑簿记，与副本是否在本地无关），pin>0 返回 ErrInUse；已不存在返回 ErrNotFound（幂等，与 Remove/Sweep 并发安全）。簿记契约：Evict 不动 refs；副本被 Evict 后经 fetch 重下时不重复 Acquire。新导出符号仅此一方法                                                                                   | Agent 层磁盘淘汰要删的是仍被快照引用的活块的本地副本（7.0「活数据淘汰」），现有 Remove 见 refcount>0 即 ErrInUse 删不掉；Sweep 的引用回收语义（6.0 §7）不动，淘汰单开入口。归属 core 是职责边界：块文件布局与 pin 互斥锁都在 cas 内部（同 D24/D20 先例）（2026-10-14 裁决） |
| D29 | index.Catalog 增 List                               | `List(ctx context.Context, prefix string) ([]Entry, error)`：复用 D22 分片相关性判定只下载相关分片，返回 path 以 prefix 开头的条目（prefix 空 = 全量），按 (path, chunk) 字典序排序；无 CURRENT 返回 ErrNoCurrent；失败不动旧映射。新导出符号仅此一方法                                                                                                                        | agent ListSnapshot RPC（7.1 §5.1）需按 prefix 枚举 (path, chunk, size)，Catalog 现无枚举导出面（2026-10-15 M3 前置主对话裁决）                                                                                                                                              |
| D30 | index.Catalog 增 ShardsLoaded                       | `ShardsLoaded() int`：返回当前生效索引快照的 Manifest 分片数（Shards 长度），尚无快照（未 Start/Refresh/LoadPrefixes 成功）返回 0；纯读、不长持锁；新导出符号仅此一方法                                                                                                                                                                                                        | agent 指标 traincache_index_shards_loaded 需要“已加载分片数”，Catalog 无导出面致恒 0（M6 遗留）；M7 总闸前裁决（2026-10-15）                                                                                                                                                |
| D31 | 多 tar 发布器（publish）职责与契约                  | 新增 `core/publish`：`Source{Path, ReaderAt, Size}`、`Options{Dataset, ChunkSize, Concurrency}`、`Result{SnapID, Entries, Bytes, UniqueBlocks}`、`Publish(ctx, store, cs, w, sources, opt)`；CLI `core/cmd/trainpublish` 接收多个 tar，每个 tar 对应一个 `Entry.Path`，块默认 64 MiB，全部条目合并后只调用一次 `Writer.Commit`。① 发布编排归发布器，`Writer` 只负责索引提交；② 多 tar 合并为**单快照**，任一失败不 `Commit`；③ `Entry.Node` v1 reserved、固定留空，发布器不填（覆盖 Q1 的 v1“写入方填写”结论）；④ 块键单点 `objectstore.BlockKey(dataset, path, chunk)` = `<dataset>/blocks/<path>#<chunk>`，替换 `agent/prefetch/pending.go` 与 `agent/rescan/repair.go` 的未导出副本；⑤ 任一块上传失败不 `Commit`，`Commit` 失败只清理本次分片/manifest、远端块不自动删除；`Path` 不可变（tar 名带版本/哈希），`Commit` 只校验本地 CAS，故必须先上传块再 `Commit` | 写侧编排跨 objectstore/cas/index 三者，放进任一既有包都会造成职责倒挂或依赖环；单快照保证读侧不会看到逐 tar 发布的中间态；`Node` 的跨节点块放置语义尚未定义，先保留字段避免错误语义固化；块键在 core 与 agent 两处重复实现易漂移；远端孤儿块删除需先有跨快照可达性/复用判定，发布器不做破坏性清理 |
| D32 | 日志脱敏归属 core                                   | 新增 `core/logging`，冻结 `Redact(s string) string` 与 `RedactURL(raw string) string` 两函数（6.1 §5.6）；仅标准库，不依赖 core 其他包，core 其他包也不依赖本包；controller 与 agent 各自在日志落盘前调用，不各自维护实现 | `traincache/controller` 与 `traincache/agent` 是两个独立 module、互不引用，core 是共同依赖；两端各写一份会产生语义漂移与重复维护。代价：core 纯库新增一个无状态工具包，两端调用点需后续接入（本轮不改调用点） |

## 3. 决策变更流程

1. 实现子代理发现约定不可行/不合理 → 回传 `BLOCKED`（理由、证据、建议）→ 不动代码；
2. 主对话裁决：采纳 → 更新 design.md + 本文档（旧编号保留，新决策顺延编号）→ 重新派活；
   否决 → 说明理由，子代理按原约定继续；
3. Q* 结案时：在本文档 §2 表格中登记结论与日期，必要时升级为 D* 或修改 design.md。
