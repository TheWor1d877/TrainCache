# 核心能力验收与测试 plan

本文承接 `docs/9.0 核心能力验收与测试.md` 的口径，只排任务、记决策。装置细节见 `docs/4 bench装置说明.md`，本文不重复。

## 0. 术语

| 术语 | 含义 |
|---|---|
| COND | 一个实验点的全部条件（数据规模、缓存容量、带宽档、策略名、种子）写成一个 JSON。跑分脚本只读它。一个 COND = 一个可复现的实验点 |
| 预热 | 训练 Pod 调度之前，Controller 驱动 WarmupTask 把数据拉进节点缓存。此时 Pod 还没落地，不知道会落在哪个节点，所以是盲热。Fluid DataLoad、`juicefs warmup` 是同一语义 |
| 预取 | Pod 落地之后，Agent 跟着训练的消费顺序持续往后拉数据。epoch 或 shuffle 切换时按新顺序重预取 |
| makespan | 任务从提交到跑完的总时长。启动 makespan 指提交到第一个 step 开始 |
| stall | DataLoader 在等数据的时段，训练算力空转。判据是等待时间占该步时间的比例 |
| 启动窗口 K | 决定训练能不能立刻跑起来的前 K 个块 |
| fanout | 预热时把同一份数据同时复制到几个节点。复制 3 份，字节成本就是 3 倍 |
| lookahead | Agent 持续预取的提前量。默认 16 块；淘汰实验扫 8/16/32 |
| 容量档位 S/M/L | 缓存固定 1 GiB，数据集取 2/8/32 GiB，数据/缓存比 1:2、1:8、1:32 |
| 块 | 缓存与预取的最小单位。实验取 8 MiB，生产默认 64 MiB |
| 淘汰策略 | 缓存满了先踢哪些块。三档：`heat`（本项目现有热度）、`lru`、`lfu` |
| A/B/C/D 轨 | 四类合成负载。A 小文件元数据，B 8 GiB webdataset tar 分片，C 两 Job 倾斜（一个循环读 10% 热子集，一个顺序扫全量），D 单 Job 连续 epoch |
| 预注册 | 正式跑分前，把三张图、三档容量比、两张 Pareto 的假设、自变量取值、预期区间、阴性结论接受条件写成文件并冻结。此后只允许追加偏离说明 |
| 组态 | 跑分里的独立运行形态。五个受试者展开为七个组态：direct、juicefs-cold、juicefs-warm、fluid-cold、fluid-warm、traincache-cold、traincache-warm。五组是按受试者归并后的清单名，凡计数一律用七组态 |

预热和预取是两件事，全文严格区分：一个发生在 Pod 落地前、由 Controller 驱动；一个发生在落地后、由 Agent 自治。

## 2. M0 实验口径冻结与预注册

目标：把「量什么、怎么量、什么算赢」写成不可回头的文字。本里程碑不写代码。

| # | 任务 | 落点 |
|---|---|---|
| 0.1 | makespan 三条边界：起点 = runner 创建 train-job 之前取的时刻（注入 `TRAINCACHE_JOB_CREATED_AT`）；启动终点 = 第一个 step 开始；全程终点 = 最后一个 epoch 的最后一步结束。五组共用 | §13 D2 |
| 0.2 | stall 口径：每步 `wait_s / step_s`；聚合报 mean 与 p90，中位数只用来判形态 | §13 D3 |
| 0.3 | 命中率三阶段切分：启动窗口 = 首个 step 之前；稳态 = 首步到第一次切换；切换期 = 切换事件到新窗口就绪 | §13 D4 |
| 0.4 | 字节成本三笔账：启动预热（× 实际 fanout）、持续预取、切换重预取，全部进收益分母 | §13 D5 |
| 0.5 | 预注册文件：三张图 + 三档容量比的假设、自变量取值、预期区间、阴性结论接受条件 | `bench/experiments/preregister.md` |
| 0.6 | COND 字段补全：`capacity_ratio`（S/M/L）、`chunk_size_bytes`（实验取 8MiB）、`warmup_seconds`（预热单列） | `bench/experiments/cond.schema.md` |
| 0.7 | 机时估算：每档点数 × 单点时长 × 该档次数，给出总机时与可压缩项 | 本文 §12 |

判据与验收：三张图和三档容量比的假设各自写成「自变量 → 预期正负区间 → 反例长什么样」，每个自变量有取值清单，COND 契约里没有「待定」；预注册文件在第一次正式跑分前提交并记录 hash，每个指标都能指到一个具体采集点。

目标：把「跑一次实验」和「跑 N 次算置信区间」都变成一条命令。

## 12. 机时预算

### 12.1 口径

单 run 时长 = max(源站传输时长, 计算下限) + 冷态与采集。

- 源站传输时长 = 数据集字节 × epoch 数 ÷ 有效带宽。有效带宽 = min(名义 rate, 源站实测上限 C)。
- 计算下限 = 400 步 × 200 ms × epoch 数。这是负载本身要花的 CPU 时间，限速再快也压不下去。
- 单 epoch 消费速率 r = 数据集字节 ÷ (400 × 200 ms)。BW/r 用来判断这一格受不受链路限制：BW/r < 1 传输主导，> 2 计算主导，落在 [1,2] 是关键档位切换点唯一的区间，只有它开抖动。

### 12.2 参数

| 带宽档 | 链路 | 单 epoch 的 r（S/M） | BW/r（S） | BW/r（M） | 判定 |
|---|---|---|---|---|---|
| 100 mbit | 12.5 MB/s | 26.8 / 107.4 MB/s | 0.47 | 0.12 | 链路受限 |
| 300 mbit | 37.5 MB/s | 同上 | 1.40 | 0.35 | S 落临界区，开抖动 |
| 1000 mbit | 125 MB/s | 同上 | 4.66 | 1.16 | S 计算主导，M 落临界区开抖动 |

L 档跑 1 个 epoch，r = 429.5 MB/s，@1000 的 BW/r = 0.29，仍在链路受限区。

| 容量档 | 数据集 | 缓存 | 比 | 块数（8MiB） | epoch | 参跑组 |
|---|---|---|---|---|---|---|
| S | 2 GiB | 1 GiB | 1:2 | 数据 256 / 缓存 128 | 3 | 全部七组态 |
| M | 8 GiB | 1 GiB | 1:8 | 数据 1024 | 1 | direct、fluid-cold、traincache-cold |
| L | 32 GiB | 1 GiB | 1:32 | 数据 4096 | 1 | traincache-cold、fluid-cold |

源站吞吐上限 C ≈ 674 MB/s 为实测值（preregister §8.4），@1000 档链路能吃满，封顶塌缩分支不触发。

### 12.3 对照实验分项

| 格 | 组数 | 每点次数 | 单 run | 合计机时 |
|---|---|---|---|---|
| S @100 | 7 | 3 | 9 min | 3.2 h |
| S @1000 | 7 | 3 | 4.5 min | 1.6 h |
| S @300 + 抖动 | 3 | 3 | 4.5 min | 0.7 h |
| M @1000 + 抖动 | 3 | 3 | 4.5 min | 0.7 h |
| L @1000 | 2 | 1 | 6 min | 0.2 h |
| 合计 | | 62 run | | ≈ 6.3 h |

单 run 时长的来路：S @100 是 6 GiB ÷ 12.5 MB/s ≈ 490 s 传输主导，加冷态与采集取 9 min；S @1000 传输只要 49 s，时长被 3 × 80 s = 4 min 的计算下限盖住，取 4.5 min；M @1000 传输 8 GiB ÷ 125 MB/s ≈ 66 s，计算下限 80 s，加冷态与采集取 4.5 min；L @1000 传输 32 GiB ÷ 125 MB/s ≈ 4.4 min，加冷态与采集取 6 min。netem 抖动只加方差、不改均值延时（仍是 20 ms，多了 10 ms 标准差），所以开抖动的格单 run 时长不变。

| D41 | 快照与源数据的关系 | MinIO 里三类对象各司其职：`bench-b/shard-*.tar` 是五组共同的源数据，只此一份，不删不动；旧 `compare-data/`（64 MiB 块）保留供历史产物复现；正式实验一律用新快照 `compare-data-8m`（`-chunk-size 8388608`），DataSet CRD 指向它 | 新旧并存，历史轮次仍可解释 |
| D42 | tar 体积与声明值的偏差 | 分片按「tar ≈ 256 MiB」校准，但 tar 内是不可压缩的 JPEG 样本，实测每份约 252.6 MiB，于是 L 档 128 份实际约 31 GiB，比声明的 32 GiB 小约 3%，容量比实际约 1:31；S/M 档偏差在 1% 量级。三档都用声明值参与缓存容量计算 | 偏差方向一致、不影响组间可比性，出表时注明即可 |
