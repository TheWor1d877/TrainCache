# Checkpoint 异步 Sidecar 实现契约

## 定位

checkpointd 在训练 Pod 内搬整份 checkpoint 目录。它做两件事：训练容器启动前把最新一份完整 checkpoint 从后端拉回本地；训练期间盯住本地目录，把写好的整份目录搬到后端，并在本地留一份可复用副本。它只搬整份目录，不解析文件格式，不改文件名。

checkpointd 是 Pod 级进程，agent 是节点级 DaemonSet。agent 管 CAS 块与读缓存，checkpointd 管整份目录与后端版本，两者不共享索引、进程和镜像。checkpointd 不进训练读路径，checkpoint 流量直连后端，不经合并回源网关。controller 只在准入阶段注入卷与变量。

训练镜像不改。接入方在 Pod 上写启用 label 与必要的 annotation，准入据此注入共享卷与环境变量；没有启用 label 的 Pod 不被注入任何容器与卷。

信任边界：

- 后端凭证以 `secretKeyRef` 只出现在 checkpointd 容器，训练容器读不到这两个变量。
- Pod 不开 `shareProcessNamespace`，训练容器读不到 checkpointd 的进程环境。
- 插件与 checkpointd 同容器同权限，一个第三方插件能读到 checkpointd 的全部环境变量（含两把凭证）并读写挂载给它的卷，接入它等同于在训练 Pod 内执行任意代码。

## 架构与依赖方向

三部分：准入侧的 webhook、Pod 内的 checkpointd、插件子进程。数据只在本地卷与后端之间流动。保存方向是训练程序写目录、插件上传、checkpointd 回填缓存；恢复方向是插件取版本、checkpointd 落本地、探针放行训练容器。对象存储走 S3 API，插件内实现；共享文件系统后端在同文件系统内改名，跨设备时整份复制；kubelet 通过 startupProbe 与 SIGTERM 交互。

分工按四层拆开：

| 层 | 执行者 | 决定 |
|---|---|---|
| 声明 | Pod annotation、ConfigMap、Secret | 用哪个插件、引用哪份配置 |
| 注入 | 准入 webhook | 挂哪些卷、注入哪些变量、本地路径 |
| 触发 | checkpointd | 何时搬、何时清理、重试与失败 |
| 执行 | 插件 | 后端读写、manifest、版本枚举、校验 |

`checkpoint/` 是第五个 Go 模块，module path `traincache/checkpoint`，加入 `go.work`。目录职责：

- `cmd/checkpointd` 是入口，负责配置、日志、信号与探针，依赖全部 internal 包。
- `cmd/plugin-s3` 与 `cmd/plugin-local` 是两个插件进程入口，各依赖自己的插件包。
- `internal/config` 解析并校验环境变量，只依赖标准库。
- `internal/logging` 构造 slog 处理器，`component` 固定为 `checkpointd`，依赖 `core/logging`。
- `internal/sidecar` 做生命周期、保存队列、恢复、缓存与探针状态，依赖 `plugin`、`manifest`、`config`、`obs`。
- `internal/plugin` 管契约、子进程、NDJSON 编解码、后端键布局与续传记录，依赖标准库与 `manifest`。
- `internal/plugin/s3` 与 `internal/plugin/local` 是两个后端实现，依赖 minio-go 与标准库。
- `internal/manifest` 与 `internal/obs` 分别做 manifest 校验与日志字段封装，只依赖标准库与 `log/slog`。
- `e2e` 是 kind 上的保存与恢复演练，不被其它包引用。

依赖方向是 `cmd` 到 `sidecar` 到 `plugin`、`manifest`、`config`、`obs`，`plugin` 到 `manifest`。`checkpoint` 不 import `controller`、`agent`、`gateway`；`sidecar` 不 import 具体插件包，插件按注册表取；`plugin` 不 import `sidecar`，回调只走帧。

## 插件进程契约

每次保存或恢复启动一个插件子进程，操作结束即退出，插件不常驻，不跨操作保存内存状态。通信走 `/run/checkpoint/plugin.sock` 的 UNIX 域套接字，NDJSON 编码，一行一个对象。首帧握手，协议版本 1；版本不符或 10 秒内没有 `hello_ok`，这个插件判为不可用。单行 JSON 的上限是 1 MiB，插件写出没有换行的超长内容时按解码失败处理，不允许读取时无限涨内存。

| 帧 | 字段 | 方向 |
|---|---|---|
| `hello` | `protocol`、`plugin`、`version` | 插件到 checkpointd |
| `hello_ok` | `protocol`、`methods` | checkpointd 到插件 |
| `request` | `id`、`method`、`params` | checkpointd 到插件 |
| `progress` | `id`、`bytes_done`、`bytes_total` | 插件到 checkpointd |
| `result` | `id`、`ok`、`data` 或 `error` | 插件到 checkpointd |
| `cancel` | `id` | checkpointd 到插件 |

| 方法 | 入参 | 返回 |
|---|---|---|
| `resolve` | `task_id`、`rank`、`world_size`、`policy`、`backend` | `found`、`step`、`complete`、`epoch`、`max_extra_rank` |
| `save` | `task_id`、`step`、`rank`、`world_size`、`local_path`、`state_path`、`backend` | `bytes`、`files` |
| `restore` | `task_id`、`step`、`rank`、`world_size`、`target_path`、`state_path`、`backend` | `bytes`、`files` |

`policy` 取 `{"mode":"latest"}` 或 `{"mode":"step","step":N}`。`backend` 是 JSON 对象，checkpointd 原样转交插件，不解析；准入注入的那一份按 S3 后端生成，键是 `endpoint`、`bucket`、`prefix`、`part_size`、`concurrency`、`secure`，插件按自己的后端约定读，`local` 插件读 `root`，它指向共享文件系统的挂载路径且必须是绝对路径。这份挂载若是 RWO 块存储，同一时刻只允许一个节点挂上，已有版本只对同节点的 Pod 可见，跨节点的恢复读不到它。`state_path` 是目录，只放续传状态。`max_extra_rank` 可选，是本次枚举里确认已提交的、编号不小于 `world_size` 的最大 rank；值 0 或字段缺失表示没有多余份，第三方插件不实现这个字段时照样可用，只是多余 rank 不触发告警。

`progress` 帧的发送节奏由插件定，约定是每秒一次或每完成 5% 一次；checkpointd 只用它重置僵死计时。

错误码分两类。`NOT_FOUND`、`INVALID_ARGUMENT`、`AUTH` 不重试；`UNAVAILABLE`、`THROTTLED`、`CORRUPT`、`INTERNAL` 重试，`THROTTLED` 带退避。

一次操作不设固定超时。连续 5 分钟既没有 `progress` 也没有 `result`，判插件僵死，终止子进程并按 `INTERNAL` 处理。退出码只用于诊断，成败以 `result` 帧为准；子进程没给出 `result` 就异常退出，同样按 `INTERNAL` 处理。

收到 `cancel` 帧或 SIGTERM 后，checkpointd 停止发起新请求，把续传状态刷盘，5 秒内退出。

## 准入契约

label `traincache.io/checkpoint` 的值是同 namespace 的 ConfigMap 名，没有这个 label 的 Pod 不启用。`objectSelector` 用 `matchExpressions` 按 `Exists` 匹配该键，不限定取值；`failurePolicy` 是 `Fail`，`rules` 与 `matchPolicy` 不动。annotation `traincache.io/checkpoint` 已删除，不参与启用与配置选择。

label 值为空、不是合法 ConfigMap 名，或按它读不到 ConfigMap 时，准入拒绝这个 Pod，响应里写出缺的是哪个。配置在 Pod 创建时固化，保存与恢复共用同一份，运行中不能换插件。

其余 annotation 的作用：

- `traincache.io/task-id` 指定任务标识。取值优先级从高到低是 Pod 上已有的值、所属 Job 或自定义资源名、`<namespace>-<pod-uid 前 8 位>`。
- `traincache.io/world-size` 指定世界大小，不写时先读 ConfigMap 的 `worldSize`，再读 Job 的 `parallelism`，都没有时按 1 处理。
- `traincache.io/rank` 指定本 rank 的编号，不写时读 Pod 的 `batch.kubernetes.io/job-completion-index` label。世界大小大于 1 且 rank 推不出来时准入拒绝这个 Pod，世界大小为 1 时按 rank 0 处理并记一条告警。
- `traincache.io/checkpoint-step` 指定要恢复的 step，取值必须是非负整数，不写时由插件选最新。
- `traincache.io/checkpoint-image` 指定注入的 checkpointd 镜像。

ConfigMap 的键与默认值：

| 键 | 默认 | 含义 |
|---|---|---|
| `plugin` | `s3` | 插件名，对应 `/opt/traincache/plugins/<name>/<name>` |
| `backendEndpoint` | 必填 | 后端地址 |
| `backendBucket` | 必填 | 桶名 |
| `backendPrefix` | 空 | 后端键前缀 |
| `partSizeBytes` | 8 MiB | 分片大小 |
| `concurrency` | 4 | 在途分片数 |
| `bufferBytes` | 32 MiB | 进程缓冲上限 |
| `nvmeEnabled` | `true` | 节点无 NVMe 时降级 |
| `nvmeRetention` | 1 | 缓存保留份数 |
| `requireCheckpoint` | `false` | 后端无完整版本时是否失败 |
| `worldSize` | 0 | 副本数兜底 |
| `secure` | `false` | 后端是否走 TLS |
| `checkpointImage` | 可选 | 注入的 checkpointd 镜像 |

`backendEndpoint` 与 `backendBucket` 缺失时准入拒绝这个 Pod。Secret `traincache-checkpoint` 存两把凭证，键是 `accessKey` 与 `secretKey`。

镜像取值顺序是 Pod annotation `traincache.io/checkpoint-image`、ConfigMap 键 `checkpointImage`、本次发布的默认镜像，前面的覆盖后面的。三处都空时准入拒绝这个 Pod。发布默认来自安装清单里的 `traincache-checkpoint-image` ConfigMap，webhook Deployment 用 `CHECKPOINT_IMAGE` 环境变量读它。

准入对凭证只写引用不写值，用 `secretKeyRef` 指向 Secret。Secret 缺键时 Pod 停在 `CreateContainerConfigError`，不静默回退。

ConfigMap 的值由准入读出后写成字面量 env。`configMapKeyRef` 在键缺失时会让 Pod 停在 `CreateContainerConfigError`，与「可选键」的语义冲突，因此不写成 `configMapKeyRef`。

准入读 ConfigMap 与 Job 走直连 API 的 reader，不建 informer，所以 webhook 的 RBAC 只要 `get`。

checkpointd 以 initContainer 形式注入，`restartPolicy` 是 `Always`，即原生 sidecar。插件二进制由一个 initContainer 从镜像复制到 `/opt/traincache/plugins/<name>/<name>`，内置插件都来自 checkpointd 镜像。注入的卷：

| 卷 | 类型 | 挂载点 | 使用方 |
|---|---|---|---|
| `checkpoint-work` | emptyDir，磁盘介质 | `/checkpoints-work` | 训练程序写，checkpointd 读并删 |
| `checkpoint-nvme` | emptyDir | `/checkpoints-nvme` | 只有 checkpointd |
| `checkpoint-plugins` | emptyDir | `/opt/traincache/plugins` | initContainer 从镜像复制，checkpointd 只读 |
| `checkpoint-run` | emptyDir | `/run/checkpoint` | checkpointd 与插件进程 |

`nvmeEnabled` 为 false 时不注入 `checkpoint-nvme` 卷，也不注入 `NVME_DIR`。

checkpointd 容器拿到的变量里，`TASK_ID`、`RANK`、`WORLD_SIZE`、`JOB`、`TRAINCACHE_CHECKPOINT_DIR`、`PLUGIN`、`BACKEND`、`REQUIRE_CHECKPOINT`、`NVME_RETENTION` 由准入写成字面量，`STATE_DIR`、`PROBE_FILE`、`SOCKET_PATH` 写成固定路径字面量，两把凭证走 `secretKeyRef`。`JOB` 取 Pod 的 `batch.kubernetes.io/job-name` label，其次取 `job-name` label，都没有时写空串。

startupProbe 执行 `checkpointd probe`，周期 10s，`failureThreshold` 是 360，超时 3s。探针读 `PROBE_FILE`，内容是 `ready` 时退出 0，其余情况退出 1。恢复完成前探针持续失败，训练容器不启动。

## 本地目录契约

| 项 | 规则 |
|---|---|
| 归属 | `<task_id>` 目录由 checkpointd 在恢复前创建，训练容器此时还没启动；step 目录由训练程序写；缓存目录与状态目录由 checkpointd 创建 |
| 完成标记 | `.done` 由训练程序写完并 fsync 后创建，内容为空，放在 step 目录这一层 |
| 缓存索引 | `.complete` 由 checkpointd 在复制完成且 fsync 后写，内容为空 |
| 原子性 | 恢复先写同文件系统的临时目录，逐文件校验后 rename；软链先建临时名再 rename |
| 权限 | 卷设 `fsGroup` 65532，checkpointd 以 65532 非 root 运行；`<task_id>` 目录由 checkpointd 按 0775 建出，训练程序按组可写方式创建 step 目录，checkpointd 才能删掉工作卷上的副本，删不掉时记一条告警 |

路径布局：

- 工作卷：`<work>/<task_id>/step-<step>/`，训练程序在这里写数据文件并在同一层创建 `.done`。
- 缓存：`<nvme>/<task_id>/step-<step>/`，目录里的 `.complete` 表示复制已落盘。
- 后端：`<prefix>/<task_id>/step-<step>/rank-<rank>/files/<相对路径>`，同一 rank 目录下的 `manifest.json` 是提交标记。
- 续传状态：`<state_dir>/<sha256>.jsonl`。

训练侧目录名可以是 `step-<n>` 或 `checkpoint-<n>`，checkpointd 把两者认作同一个 step，写到后端时统一成 `step-<n>`。epoch 不进目录命名与排序，只记在 manifest 里。

一个 Pod 一个 rank，一个 rank 的 checkpointd 独立触发、独立上传自己的子目录，后端键带 rank。跨 Pod 不做协调，也没有全局提交标记：某个 rank 保存失败只影响它自己，恢复时该 step 判不完整，所有 rank 一起退到上一个完整 step。

### 非 root 运行的五条前提

checkpointd 的镜像写死 `USER 65532:65532`，插件与它同 uid。保存成功后它要删掉工作卷上的副本，删除需要「目录可写 + 可进入」，下面五条要同时成立：

1. 卷上 fsGroup 生效。准入给 Pod 注入 `fsGroup=65532` 与 `fsGroupChangePolicy=OnRootMismatch`；业务 Pod 自己写了别的 fsGroup 时准入不改，权限契约随之失效。emptyDir 与声明了 `fsGroupPolicy: File` 的 PVC 都适用，`fsGroupPolicy: None` 的存储类不应用 fsGroup，要另行安排。
2. 训练程序落在同一个组里。fsGroup 生效时 kubelet 把 65532 加进训练容器的补充组，训练程序建出的目录组主就是 65532。训练程序自己就是 uid 65532 时这一条自然成立。
3. step 目录组可写。训练程序用 `umask 0002` 或 `mkdir -m 0775` 建 step 目录；默认 umask 022 建出的是 0755，checkpointd 能删目录项却删不掉目录里的文件。
4. `<task_id>` 目录由 checkpointd 建。checkpointd 在恢复前按 0775 建出这个目录，训练程序不用自己建，也不该改它的模式。
5. 工作卷是同一个。训练容器与 checkpointd 挂的是同一个 `checkpoint-work` 卷；换成 hostPath 或 local PV 时，上面前两条要自己保证。

任一条不成立的后果：checkpointd 删不掉副本，记一条告警并重试，工作卷随 step 数增长；数据不丢，但卷会写满。改用 root 能一次解决删除，代价是同时放大后端凭证的暴露面，这条路不采纳。

## 数据格式

manifest 由插件写，checkpointd 不解析。字段结构：

```json
{"version":1,"task_id":"llm-7b-job-0","step":1200,"rank":3,"world_size":8,"epoch":2,
 "created_at":"2026-11-04T10:00:00Z",
 "files":[{"path":"model.safetensors","size":1073741824,"sha256":"…"}]}
```

`version` 从 1 起只增不改，字段只增可空。`files` 按 `path` 排序后写入，顺序不承载语义。`path` 是相对路径且不含 `..`，`sha256` 是 64 位小写十六进制。manifest 是后端的提交标记，最后写；它存在且校验通过，该 rank 的该 step 才算完整。

续传状态是目录，每个待传文件一个 JSON Lines 文件，名为 `<sha256>.jsonl`；首行是上传头，之后一行一个已确认分片：

```json
{"kind":"upload","upload_id":"…","key":"…","file":"model.bin"}
{"part":0,"etag":"9b2cf5…","bytes":8388608}
```

多头记录让 S3 的多分片上传能跨进程续传，local 插件不写这些文件。每写一行先 fsync 再传下一片，末行不完整时丢弃，中间行损坏时按文件不可信报错而不是猜。保存成功后删除该 step 的状态文件。

缓存索引是 step 目录里的 `.complete` 文件，内容为空，存在即表示该目录的复制已落盘。缓存由 checkpointd 管理，所有插件共用：插件不感知缓存，也不实现缓存逻辑，缓存内容只来自 checkpointd 的复制。

## 关键流程

### 启动与配置加载

checkpointd 启动后按顺序做四件事。

1. 解析环境变量，非法时写一条 ERROR 并以退出码 2 结束，容器进入 CrashLoop，训练容器不启动。
2. 构造日志器，写入 `component`、`version`、`log_schema_version`。
3. 创建 `<task_id>` 目录并校验工作卷与缓存卷可写。缓存卷不可写时关闭缓存并记一条告警，不阻断启动。
4. 扫描缓存目录登记带 `.complete` 的 step，探针置 `restoring`，进入恢复。恢复完成后探针置 `ready`，转入保存监听。

### 保存

checkpointd 每 200ms 轮询工作卷一次，每 20s 做一次全量扫描。

轮询看到带 `.done` 的 step 目录就入队。`.done` 的契约是训练程序写完并 fsync 后创建的，所以第一次发现直接入队，之后每一轮都要求该目录的总字节数与上一轮相同，字节数还在变就等下一轮。

全量扫描处理没有 `.done` 的目录：文件数与总字节数连续 3 次扫描不变才算就绪，中途变化就重新计数并记一条告警。带 `.done` 的目录在全量扫描里仍然只看字节数是否变化，变化就记一条告警并等下一轮。

出队后按 step 升序串行处理。调插件 `save`，传本地路径、后端配置与续传状态目录。插件返回成功后，checkpointd 把该 step 复制到缓存目录：先复制到同文件系统的临时目录，校验后 rename，最后写 `.complete`。回填失败只记一条告警，不影响保存结论。回填成功后再按 `nvmeRetention` 从旧到新淘汰 step，被软链引用的目录不删。最后删掉工作卷里该 step 的数据与 `.done`。没有缓存卷时跳过复制与淘汰，插件返回成功后直接删工作卷数据。

上传时排除 `.done` 与 `.complete` 两个标记文件，训练数据的其余层级照原样上传。

### 保存失败

保存重试由 checkpointd 统一发起，共 6 次尝试，退避间隔依次是 1s、2s、4s、30s、30s，总时限由 `TRAINCACHE_CHECKPOINT_SAVE_DEADLINE` 封顶，超时即失败。不可重试的错误码立刻结束重试。

失败后保留工作目录，不再接收新 step，写一条 ERROR，带 `task_id`、`step`、`retry`、`err`、`err_class`。训练程序写下一份时遇到 ENOSPC 会退出，Job 重建 Pod 后从上一个完整 step 恢复；正在执行的训练 step 不受影响。

### 恢复

1. Pod annotation 带了 `traincache.io/checkpoint-step` 时用 `{"mode":"step"}` 策略，只恢复该 step，不完整按失败处理，不回退到更旧的版本；没有这个 annotation 时用 `latest`。
2. 调插件 `resolve`，插件枚举后端并返回最大的完整 step 与 epoch。完整指该 step 的 rank 集合恰好等于 `{0 … world_size-1}`：缺份判不完整，多出编号不小于 `world_size` 的份也判不完整。多余份由插件在 `max_extra_rank` 里报出，checkpointd 记一条告警，字段是 `reason=rank_beyond_world_size`、`max_rank`、`world_size`。插件的 stderr 不接进日志，协议里也没有日志帧，这条告警只能由 checkpointd 发出。后端没有完整 step 时，`requireCheckpoint` 为 false 直接放行，为 true 按失败处理。
3. 缓存里已有该 step 的 `.complete` 时，在工作卷建只读软链指向缓存目录。
4. 否则调插件 `restore`，写进工作卷的临时目录，逐文件校验后原子 rename。
5. 从后端恢复成功后异步回填缓存。最后把探针置为通过。

### 恢复失败

恢复分三段。第一段在 `TRAINCACHE_CHECKPOINT_RESTORE_DEADLINE` 内密集重试，间隔 5s、10s、15s、20s、25s 循环，每轮写一条 ERROR。插件返回 `CORRUPT` 且策略是 `latest` 时重新 `resolve` 换一个 step，最多换 2 次。

第二段从恢复期限到点开始，每 5 分钟一轮，每轮写一条 ERROR，进程不退出，探针持续失败，训练容器不启动。第三段到 `TRAINCACHE_CHECKPOINT_RESTORE_GIVE_UP_AFTER` 仍然不成功，写一条带 `reason=restore_give_up` 的 ERROR，以退出码 3 结束。

退出码 3 表示恢复放弃，与配置非法的 2 分开。init 容器非零退出后 kubelet 按 Pod 的重启策略重启，`restartPolicy: OnFailure` 下容器在同一个 Pod 里重启，每次重启算一次失败、计入 Job 的 `backoffLimit`；用完 `backoffLimit` 后 Job 以 `BackoffLimitExceeded` 判 Failed，Pod 删除并释放占用。`status.failed` 记的是失败的 Pod 数，这种形态下是 1，不是重启次数。退出码是 checkpointd 唯一能表达的失败信号，所以 `backoffLimit` 是接入方要显式定的值：设 0 时一次放弃即判失败。

### 取消与退出

收到 SIGTERM 后停止接收新 step，给在途插件发 `cancel` 帧并等 5 秒，超时终止子进程。续传状态在退出前刷盘，退出码 0。Pod 删除时工作卷随之删除，缓存副本保留。

### 幂等与并发

同一 rank 的 step 串行上传，队列上限 4，满时不接收并记 `result=skipped`、`reason=queue_full`，同一条告警 5 秒内不重复写。去重看「已出队集合」与「缓存里已有的 `.complete`」两层，重启后从目录重建。准入重复执行时已存在的容器、卷与变量不重复追加。

## 训练程序接入

训练程序从环境变量或启动参数读路径时可用：写完 step 目录并创建 `.done` 后立即上传，恢复也可用。路径硬编码时只能靠 20 秒一次的扫描，可靠性下降，恢复不可用，任务从零开始。

Hugging Face Trainer 的 `save_directory` 与 `resume_from_checkpoint`、PyTorch Lightning 的 `dirpath` 与 `ckpt_path` 直接用准入给的路径。裸 PyTorch 要自己拼路径，保存结束后创建 `.done`。

加载顺序由训练程序保证：按保存时的结构重建模型、优化器、调度器；加载权重；先建调度器，再加载优化器状态，最后加载调度器状态；恢复 epoch 与 step；可选恢复随机数状态。

## 可观测出口

checkpointd 的可观测出口是日志与探针文件。日志公共字段与错误归因沿用 `core/logging` 的处理器，`component` 固定为 `checkpointd`。本模块另加的字段是 `task_id`、`step`、`rank`、`job`、`plugin`、`bytes`、`bytes_total`、`retry`、`state`、`file`、`err`、`err_class`。`state` 取 `waiting`、`ready`、`restoring`、`uploading`、`cached`、`done`、`failed` 七种。`file` 只在单文件校验失败时出现，且只在 Debug 级。`result` 取 `ok`、`error`、`requeue`、`skipped`、`stale`、`degraded`。

`job` 是跨链路对账键，取值来自准入注入的 `JOB`。它与 `task_id` 可以不同：`task_id` 是后端键空间的一部分，允许被 annotation 覆盖，改了会让已上传的 checkpoint 找不到；`job` 只回答「这条日志属于哪场训练」。裸 Pod 或不由 Job 建出的 Pod，`job` 是空串，这类场景按 `task_id` 查询。

日志点：

| 位置 | 级别 | 字段 |
|---|---|---|
| 配置加载完成 | Info | `plugin`、桶名、`nvme`，值来自默认时也写 |
| 配置校验失败 | Error | `err`、`err_class=invalid_spec` |
| 发现 `.done` 并入队 | Info | `task_id`、`step`、`state=ready`、`queue_depth`；队满改 Warn |
| 上传开始、进度、完成 | Info 与 Debug | `step`、`bytes_done`、`bytes_total`、`retry`、`duration_ms`、`result`；进度只记 Debug，默认 1/100 采样 |
| 保存或恢复失败 | Error | `err`、`err_class`、`retry`，两者成对 |
| 扫描参数不一致 | Warn | `path`、`reason=size_mismatch` |
| 恢复选版本与完成 | Info | `step`、`epoch`、`bytes`、`duration_ms`；未找到时 `result=skipped` |
| step 存在多余 rank | Warn | `task_id`、`reason=rank_beyond_world_size`、`max_rank`、`world_size` |
| 恢复放弃 | Error | `task_id`、`step`、`retry`、`err`、`reason=restore_give_up`；这条之后进程以退出码 3 结束 |
| 软链命中、缓存回填、探针切换、收到信号 | Info | `step`、`state`、`bytes`、`reason`、`signal`、`inflight` |

逐步事件的消息里带 step，探针切换的消息里带状态。采样器按 `(component,event,task_id,reason)` 去重 60 秒，同名消息会把下一个 step 的记录吞掉，所以变化维度要放进消息文本而不是只改字段。脱敏交给 `core/logging` 的处理器，业务代码不逐处调用脱敏函数。

要回答上传总量，按 `step` 汇总 `bytes`。要回答恢复耗时，看 `duration_ms` 与阶段字段。要回答重试趋势，数 `retry` 大于 0 的行。

排障路径：

1. 训练容器没起来，先看 Pod 的 init 容器状态与探针失败次数，再看 checkpointd 最近一条 `state`。Pod 已不在或 Job 已判 Failed 时看 init 容器的上一次终止原因，退出码 3 是恢复放弃。
2. 按 `job` 过滤日志找最近一条 ERROR，再按 `task_id` 与 `step` 定位到具体一份 checkpoint，到后端核对 manifest 与文件数。`job` 由准入注入，裸 Pod 时为空串，此时按 `task_id` 查。

## 部署与配置

checkpointd 自己读的环境变量：

- `TRAINCACHE_CHECKPOINT_LOG_LEVEL` 默认 `info`，可取 `debug`、`info`、`warn`、`error`，非法值在启动时报配置错误并以退出码 2 结束。
- `TRAINCACHE_CHECKPOINT_SAVE_DEADLINE` 默认 `15m`，保存重试的总时限，必须是正时长。
- `TRAINCACHE_CHECKPOINT_RESTORE_DEADLINE` 默认 `10m`，恢复密集重试的时限，必须是正时长。
- `TRAINCACHE_CHECKPOINT_RESTORE_GIVE_UP_AFTER` 默认 `60m`，恢复放弃期限，必须是正时长且大于 `TRAINCACHE_CHECKPOINT_RESTORE_DEADLINE`，不满足判配置非法并以退出码 2 结束。
- `TRAINCACHE_CHECKPOINT_POLL_INTERVAL` 默认 `200ms`，工作卷轮询周期，必须是正时长。
- `TRAINCACHE_CHECKPOINT_SCAN_INTERVAL` 默认 `20s`，全量扫描周期，必须是正时长。
- `TRAINCACHE_CHECKPOINT_SCAN_STABLE` 默认 `3`，没有 `.done` 的目录就绪所需的连续稳定次数，必须是不小于 2 的整数。

准入注入的运行参数：

- `TASK_ID` 必填，任务标识，同时是后端键空间的一段，不能含路径分隔符。
- `RANK` 必填，本 rank 的编号，必须小于 `WORLD_SIZE`。
- `WORLD_SIZE` 必填，本任务的世界大小，至少为 1。
- `TRAINCACHE_CHECKPOINT_DIR` 必填，工作卷上的本任务目录，`<task_id>` 子目录由 checkpointd 创建。
- `JOB` 缺省空串，owner Job 名，用于跨链路对账。
- `NVME_DIR` 缺省空串，缓存根目录；为空表示关闭缓存。
- `STATE_DIR` 默认 `/run/checkpoint/state`，续传状态根目录。
- `PROBE_FILE` 默认 `/run/checkpoint/ready`，探针标记文件。
- `SOCKET_PATH` 默认 `/run/checkpoint/plugin.sock`，插件套接字路径。
- `PLUGIN` 默认 `s3`，插件名，不能含路径分隔符。
- `PLUGIN_PATH` 默认 `/opt/traincache/plugins/<plugin>/<plugin>`，插件可执行文件路径。
- `BACKEND` 默认 `{}`，后端 JSON 对象，必须是 JSON 对象，原样转交插件。
- `REQUIRE_CHECKPOINT` 默认 `false`，后端没有完整版本时是否判失败。
- `NVME_RETENTION` 默认 `1`，缓存保留份数，至少为 1。
- `CHECKPOINT_STEP` 未设置时不注入；设置时是恢复指定的 step，必须是非负整数。
