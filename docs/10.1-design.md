# Checkpoint 异步 Sidecar 实现契约

## 1. 定位与边界

### 1.1 职责

checkpointd 在训练 Pod 内做两件事：训练容器启动前把最新一份完整 checkpoint 放到本地；训练期间盯住本地目录，把写好的整份目录搬到后端，并在本地留一份可复用副本。它只搬整份目录，不解析文件格式，不改文件名。

### 1.2 不做的部分

不做 GCS 与 Azure Blob 插件、跨 Pod 缓存、内容裁剪与格式转换、训练框架格式解析（10.0）。单 Pod 多 rank 不在本期（D7）。指标、Event、API server 访问都不做（D4、D5）；第三方插件本期不交付（Q5）。

### 1.3 与已完成模块的关系

| 模块 | 关系 |
|---|---|
| `controller/internal/webhook` | 新增第二条准入规则，现有 warmup 规则不动，两条按不同 label 选 Pod |
| `agent` | 无代码关系。agent 管 `/var/cache/traincache` 的块，checkpointd 管 `/checkpoints-*` 的整目录 |
| `gateway` | 无关系，checkpoint 流量直连后端 |
| `core` | 只复用 `core/logging` 的采样、脱敏与级别控制 |
| `bench`、发布链 | 新增一组 checkpoint 实验，不改现有指标口径；发布物加一个镜像（D9） |

### 1.4 信任边界

- 凭证以 `secretKeyRef` 只出现在 checkpointd 容器，训练容器没有这两个变量。
- Pod 不开 `shareProcessNamespace`（D3），训练容器读不到 checkpointd 的进程环境。
- 插件与 checkpointd 同容器同权限，第三方插件等同在训练 Pod 内执行任意代码，镜像由管理员审核；checkpointd 不访问 API server，不挂 ServiceAccount token。

### 1.5 兼容性

| 对象 | 要求 |
|---|---|
| 训练容器 | 只多一个 `TRAINCACHE_CHECKPOINT_DIR`。没有该 annotation 的 Pod 与改动前一致 |
| 现有 webhook | 规则、选择器、失败策略不动，只加一条独立规则 |
| agent、gateway、core | 不修改 |
| 10.0 的 `checkpoint-mem` 卷 | 改名为 `checkpoint-work`，介质为磁盘（D1、D15） |
| 10.0 的指标与事件 | 本期不实现（D4、D5） |
| 重启 | 从本地目录与续传状态重建队列，不重传已完成的 step |

## 2. 架构概览

三部分：准入侧、Pod 内的 checkpointd、插件子进程。数据只在本地卷与后端之间流动，checkpointd 不参与训练读路径。保存方向为训练写目录、插件上传、checkpointd 回填；恢复方向为插件取版本、checkpointd 落本地、探针放行。逐阶段步骤见 §6。

对象存储走 S3 API，插件内实现；PVC 走同文件系统的复制或硬链接；kubelet 通过 startupProbe 与 SIGTERM 交互；API server 不参与。

## 3. 包结构与依赖方向

新增第五个 Go 模块 `checkpoint/`，module path `traincache/checkpoint`，加入 `go.work`。

| 路径 | 职责 | 允许依赖 |
|---|---|---|
| `cmd/checkpointd` | 入口：配置、日志、信号、探针 | 全部 internal |
| `internal/config` | 环境变量解析与校验 | 标准库 |
| `internal/logging` | 构造 slog 处理器，`component=checkpointd` | `core/logging` |
| `internal/sidecar` | 生命周期、保存队列、恢复、缓存、探针状态 | `plugin`、`manifest`、`config`、`obs` |
| `internal/plugin` | 契约、子进程、NDJSON 编解码、键布局、续传记录 | 标准库、`manifest` |
| `internal/plugin/{s3,local}` | S3 兼容后端与本地目录后端 | minio-go、标准库 |
| `internal/manifest`、`internal/obs` | manifest 校验与日志字段封装 | 标准库、`log/slog` |
| `cmd/plugin-{s3,local}` | 两个插件进程入口 | `internal/plugin/{s3,local}` |
| `e2e` | kind 保存与恢复演练 | 无 |

依赖方向：`cmd → sidecar → {plugin, manifest, config, obs}`，`plugin → manifest`。

禁止：`checkpoint` 不 import `controller`、`agent`、`gateway`；`sidecar` 不 import 具体插件包，按注册表取；`plugin` 不 import `sidecar`，回调只走帧。

## 4. 核心接口

### 4.1 插件进程契约

每次保存或恢复启动一个子进程，结束后退出。通信走 `/run/checkpoint/plugin.sock` 的 UNIX 域套接字，NDJSON 编码，一行一个对象。首帧握手，协议版本 1；版本不符或 10 秒内无 `hello_ok` 即判该插件不可用。

| 帧 | 字段 | 方向 |
|---|---|---|
| `hello` | `protocol`、`plugin`、`version` | 插件 → checkpointd |
| `hello_ok` | `protocol`、`methods` | checkpointd → 插件 |
| `request` | `id`、`method`、`params` | checkpointd → 插件 |
| `progress` | `id`、`bytes_done`、`bytes_total` | 插件 → checkpointd |
| `result` | `id`、`ok`、`data` 或 `error` | 插件 → checkpointd |
| `cancel` | `id` | checkpointd → 插件 |

| 方法 | 入参 | 返回 |
|---|---|---|
| `resolve` | `task_id`、`rank`、`world_size`、`policy`、`backend` | `found`、`step`、`complete`、`epoch` |
| `save` | 上述前四项加 `step`、`local_path`、`state_path`、`backend` | `bytes`、`files` |
| `restore` | 同 `save`，`target_path` 代替 `local_path` | `bytes`、`files` |

`policy` 取 `{"mode":"latest"}` 或 `{"mode":"step","step":N}`。`backend` 原样转交，checkpointd 不解析。`state_path` 是目录，只放续传状态。

错误码两类：`NOT_FOUND`、`INVALID_ARGUMENT`、`AUTH` 不重试；`UNAVAILABLE`、`THROTTLED`、`CORRUPT`、`INTERNAL` 重试，`THROTTLED` 带退避。操作不设固定超时；连续 5 分钟无 `progress` 也无 `result` 判僵死，终止子进程并按 `INTERNAL` 处理。退出码只用于诊断，成败以 `result` 为准。

收到 `cancel` 或 SIGTERM 后停止发起新请求，把续传状态刷盘，5 秒内退出。无 `result` 的异常退出按 `INTERNAL` 处理。

### 4.2 准入契约

annotation `traincache.io/checkpoint` 的值是同 namespace 的 ConfigMap 名，空值不启用。Pod 另需 label `traincache.io/checkpoint=enabled`，准入按 label 选 Pod（理由见 Q1）。

| ConfigMap 键 | 默认 | 含义 |
|---|---|---|
| `plugin` | `s3` | 插件名，对应 `/opt/traincache/plugins/<name>/<name>` |
| `backendEndpoint` / `backendBucket` / `backendPrefix` | 前两项必填，前缀为空 | 后端地址、桶名、键前缀 |
| `partSizeBytes` / `concurrency` / `bufferBytes` | 8 MiB / 4 / 32 MiB | 分片大小、在途分片数、进程缓冲上限 |
| `nvmeEnabled` / `nvmeRetention` | `true` / 1 | 节点无 NVMe 时降级；保留份数 |
| `requireCheckpoint` | `false` | 后端无完整版本时是否失败 |
| `worldSize` / `secure` | 0 / `false` | 副本数兜底；后端是否走 TLS |

Secret `traincache-checkpoint` 两个键：`accessKey`、`secretKey`。

准入只写引用不写值：`configMapKeyRef` 指向上表，`secretKeyRef` 指向 Secret。缺键时 Pod 停在 `CreateContainerConfigError`，不静默回退（D2）。

| 卷 | 类型 | 挂载点 | 使用方 |
|---|---|---|---|
| `checkpoint-work` | emptyDir，磁盘 | `/checkpoints-work` | 训练程序写，checkpointd 读并删 |
| `checkpoint-nvme` | emptyDir（本期；local PV 未实现，D17） | `/checkpoints-nvme` | 只有 checkpointd |
| `checkpoint-plugins` | emptyDir | `/opt/traincache/plugins` | initContainer 从镜像复制，checkpointd 读 |
| `checkpoint-run` | emptyDir | `/run/checkpoint` | checkpointd 与插件进程 |

checkpointd 容器另拿 `TASK_ID`、`RANK`、`WORLD_SIZE`、`NVME_DIR`、`PLUGIN`、`BACKEND`、`TRAINCACHE_CHECKPOINT_DIR`、`STATE_DIR`、`PROBE_FILE`、`SOCKET_PATH`，凭证走 `TRAINCACHE_CHECKPOINT_ACCESS_KEY` 与 `TRAINCACHE_CHECKPOINT_SECRET_KEY`（`secretKeyRef`）。`PLUGIN`、`BACKEND`、`REQUIRE_CHECKPOINT`、`NVME_RETENTION` 由准入写成字面量；只有两个凭证是引用。startupProbe 执行 `checkpointd probe`，周期 10s，`failureThreshold: 360`，超时 3s；恢复完成前探针失败，训练容器不启动。

### 4.3 本地目录契约

| 项 | 规则 |
|---|---|
| 归属 | `<task_id>` 由 checkpointd 在恢复前创建（训练容器此时还没启动）；step 目录由训练程序写；NVMe 与状态目录由 checkpointd 创建 |
| 完成标记 | `.done` 由训练程序写完并 fsync 后创建，内容为空 |
| 缓存索引 | `.complete` 由 checkpointd 在复制完成且 fsync 后写 |
| 原子性 | 恢复先写同文件系统临时目录，校验后 rename；软链先建临时名再 rename |
| 权限 | 卷设 `fsGroup`，checkpointd 非 root，只保留读工作卷的权限 |

### 4.4 幂等与并发

同一 rank 的 step 串行上传，队列上限 4，满时不接收并记 `result=skipped`、`reason=queue_full`。去重看「已出队集合」与「NVMe 已有 `.complete`」两层，重启后从目录重建；准入重复执行时已存在的容器、卷、变量不重复追加。

## 5. 数据格式

### 5.1 manifest

插件写，checkpointd 不解析。字段结构：

```json
{"version":1,"task_id":"llm-7b-job-0","step":1200,"rank":3,"world_size":8,"epoch":2,
 "created_at":"2026-11-04T10:00:00Z",
 "files":[{"path":"model.safetensors","size":1073741824,"sha256":"…"}]}
```

`version` 从 1 起只增不改，字段只增可空。`files` 按 `path` 排序后写入，顺序不承载语义。manifest 是后端的提交标记，最后写；它存在且校验通过，该 rank 的该 step 才算完整。

### 5.2 续传状态

`state_path` 是目录。每个待传文件一个 JSON Lines 文件，名为 `<sha256>.jsonl`；首行是上传头，之后一行一个已确认分片：

```json
{"kind":"upload","upload_id":"…","key":"…","file":"model.bin"}
{"part":0,"etag":"9b2cf5…","bytes":8388608}
```

多头记录让 S3 的多分片上传能跨进程续传；local 插件不写这些文件。每写一行先 fsync 再传下一片，末行不完整时丢弃。保存成功后删除该 step 的状态目录。

### 5.3 缓存索引

`<step 目录>/.complete` 内容为空，存在即表示该目录复制已落盘。

### 5.4 配置项

| 环境变量 | 默认 | 校验 |
|---|---|---|
| `TRAINCACHE_CHECKPOINT_LOG_LEVEL` | `info` | 四级之一，非法即启动错误 |
| `TRAINCACHE_CHECKPOINT_SAVE_DEADLINE` / `_RESTORE_DEADLINE` | `15m` / `10m` | 正整数时长 |
| `_POLL_INTERVAL` / `_SCAN_INTERVAL` / `_SCAN_STABLE` | `200ms` / `20s` / `3` | 正整数时长；稳定次数 ≥2 |

运行参数由准入注入：

| 变量 | 默认 | 含义 |
|---|---|---|
| `TASK_ID` / `RANK` / `WORLD_SIZE` | 必填 | 任务标识与 rank；世界大小由 annotation、ConfigMap 或 Job 副本数解析 |
| `TRAINCACHE_CHECKPOINT_DIR` | 必填 | 工作卷下的 `<task_id>`，由 checkpointd 创建 |
| `NVME_DIR` / `STATE_DIR` / `PROBE_FILE` / `SOCKET_PATH` | 无 / `/run/checkpoint/state` / `/run/checkpoint/ready` / `/run/checkpoint/plugin.sock` | 缓存、续传状态、探针标记、插件 socket |
| `PLUGIN` / `PLUGIN_PATH` | `s3` / `/opt/traincache/plugins/<plugin>/<plugin>` | 插件名与可执行文件 |
| `BACKEND` | `{}` | 后端 JSON，原样转交插件 |
| `REQUIRE_CHECKPOINT` / `NVME_RETENTION` / `CHECKPOINT_STEP` | `false` / `1` / 未设置 | 无完整版本是否失败、缓存份数、指定 step |

### 5.5 日志字段

公共字段按 8.1 §3.1，`component=checkpointd`。本模块另加：

另加字段：`task_id`、`rank`、`step`、`plugin`、`bytes`、`bytes_total`、`retry`、`state`（`waiting/ready/uploading/cached/done/failed`）；`file` 只在单文件校验失败时出现，仅 Debug。

`result` 沿用 8.1：`ok/error/requeue/skipped/stale/degraded`。

## 6. 关键流程

### 6.1 启动与配置加载

1. 解析环境变量，非法时写一条 ERROR 并以退出码 2 结束，容器进入 CrashLoop，训练容器不启动。
2. 构造日志器，写入 `component`、`version`、`log_schema_version`。
3. 创建 `<task_id>` 目录并校验工作卷与 NVMe 卷可写（NVMe 不可写时关闭缓存并记 WARN），扫描缓存目录登记 `.complete`，探针置 `restoring`，进入恢复；恢复完成后置 `ready`，转入保存监听。

### 6.2 保存

1. 每 200ms 轮询工作卷，发现新 `.done` 入队；每 20s 全量扫描一次。
2. 扫描判据：目录无被打开的文件，连续 `SCAN_STABLE` 次扫描的字节数与修改时间不变，且文件大小之和与目录登记值一致。第 2 条不成立时记 WARN 并跳过。
3. 出队，按 step 升序串行处理。调插件 `save`，传本地路径、后端配置与续传状态目录。
4. 成功后回填 NVMe：先复制到临时目录，校验后 rename，最后写 `.complete`；回填失败只记 WARN。再按 `nvmeRetention` 从旧到新删 step（被软链引用的不删），删工作卷里该 step 的数据与 `.done`。
5. 没有 NVMe 卷时跳过复制与淘汰，插件返回成功后直接删工作卷数据。

### 6.3 保存失败

插件内按错误码重试 3 次（退避 1s、2s、4s），耗尽后 checkpointd 再重试 5 次（间隔 30s），总时限由 `SAVE_DEADLINE` 封顶，超时即失败（D12）。

失败后保留数据，不再接收新 step，写一条 ERROR（`task_id`、`step`、`retry`、`err`、`err_class`）。训练程序写下一份时遇 ENOSPC 退出，Job 重建 Pod，从上一个完整 step 恢复。正在执行的训练 step 不受影响。

### 6.4 恢复

1. annotation 带 `step` 时用 `policy={"mode":"step"}`，否则用 `latest`。
2. 插件枚举后端，返回最大的完整 step 与 epoch。后端没有完整 step 时，`requireCheckpoint` 为 false 直接放行，为 true 按失败处理。
3. NVMe 有该 step 的 `.complete` 时，在工作卷建只读软链指向 NVMe 目录。
4. 否则调插件 `restore`，写入工作卷的临时目录，逐文件校验后原子 rename。
5. 从后端恢复成功后异步回填 NVMe。最后把探针置为通过。

### 6.5 恢复失败

重试 5 次，间隔 5s 到 25s，每次加 5s。返回 `CORRUPT` 且策略为 `latest` 时重新 `resolve`，最多换 2 个 step。仍失败时进程不退出，探针持续失败，训练容器不启动；`RESTORE_DEADLINE` 到达后转为每 5 分钟一轮，每轮写一条 ERROR（D14）。

### 6.6 取消与退出

收到 SIGTERM 后停止接收新 step，给在途插件发 `cancel` 并等 5 秒，超时终止子进程。续传状态在退出前刷盘，退出码 0。Pod 删除时工作卷随之删除，NVMe 副本保留。

## 7. 日志与可观测

### 7.1 日志点

| 位置 | 级别 | 字段 |
|---|---|---|
| 配置加载完成 | Info | `plugin`、桶名、`nvme`，值来自默认时也写 |
| 配置校验失败 | Error | `err`、`err_class=invalid_spec` |
| 发现 `.done` / 入队 | Info / Debug | `task_id`、`step`、`state=ready`、`queue_depth`；队满改 Warn |
| 上传开始、进度、完成 | Info / Debug | `step`、`bytes_done`、`bytes_total`、`retry`、`duration_ms`、`result`；进度只记 Debug，默认 1/100 采样 |
| 保存或恢复失败 | Error | `err`、`err_class`、`retry`，两者成对 |
| 扫描参数不一致 | Warn | `path`、`reason=size_mismatch` |
| 恢复选版本与完成 | Info | `step`、`epoch`、`bytes`、`duration_ms`；未找到时 `result=skipped` |
| 软链命中、缓存回填、探针切换、收到信号 | Info | `step`、`state`、`bytes`、`reason`、`signal`、`inflight` |

逐步事件的消息里带 step，探针切换的消息里带状态：core 的采样器按 `(component,event,task_id,reason)` 去重 60 秒，同名消息会把下一个 step 的记录吞掉（D18）。脱敏交给 `core/logging` 的处理器，业务代码不逐处调用 `Redact`。

### 7.2 不发的指标与事件

本期不注册指标、不写 Event（D4、D5）。原来要用指标回答的三个问题改由日志回答：上传总量按 `step` 汇总 `bytes`；恢复耗时看 `duration_ms` 与阶段字段；重试趋势统计 `retry>0` 的行数。

### 7.3 排障路径

1. 训练容器没起来，先看 Pod 的 `Init:Checkpoint` 状态与探针失败次数，再看 checkpointd 最近一条 `state`。
2. 按 `task_id` 与 `step` 过滤日志找最近 ERROR，到后端核对 manifest 与文件数。

## 8. 风险与约束

| 风险 | 缓解 |
|---|---|
| 工作卷与 NVMe 写满 | 保留份数默认 1；写前检查剩余空间，低于单份大小时记 WARN |
| 训练在多 rank Pod 内运行 | 一期不支持（D7），目录留扩展位 |
| `task_id` 与预热链路不同源；副本数推不出真实 rank 数 | Q2、Q3，指标合并推迟，只支持固定副本数 |
| 恢复失败一小时无出口 | `RESTORE_DEADLINE` 加每 5 分钟日志（D14） |
| 组件名不在 8.1 枚举内 | Q4，实现前补一行并写 ADR |
| NVMe 卷实际是 emptyDir，落在节点磁盘 | 本期按磁盘工作，未提供 local PV（D17）；NVMe 收益需后续装置验证 |
