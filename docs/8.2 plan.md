# 9.2 日志与可观测性 · Plan

> 状态：2026-10-21。落地契约与字段定义见 `9.1 design.md`，选型与取舍理由见 `9.3 decisions.md`。

这份文档回答一个问题：日志与监控这块还缺什么、按什么顺序补、每补完一块怎么算过关。

读法建议：先看 §1 了解三层（控制平面、Agent、DataLoader）各自的日志现状；再看 §2 的六大缺口，每条都是后面要补的事；最后看 §3 的落地清单，P0 到 P3 按优先级排列，表里写清每个阶段做什么、怎么验收。

先混个脸熟，后面小节会细说：slog 是 Go 标准库的结构化日志包，JSON 是它的一种输出格式；fluent-bit 是跑在每台节点上的日志采集器；Loki 存日志，Prometheus 存指标，Grafana 把两者画成图；kind 是用容器在本机模拟 K8s 集群的工具；DaemonSet 是 K8s 里"每台节点各跑一个副本"的部署方式。

## 1. 背景（一句话现状）

三层各自的日志现状：

- 控制平面（controller-manager、webhook、scheduler 这些组件）：基线已经能用。slog JSON 输出、context logger（带上下文的 logger，打日志时自动附上 request_id 这类字段）、8.1 §9.3 规定的十六个日志点、M12 的日志断言测试（断言关键路径确实打了日志），都齐了。
- Agent：`agent/internal/logging` 已建，component/version/level/context 基本统一；逐块下载与缓存命中的汇总日志、采样限流仍缺。
- DataLoader：既没有生产实现，也没有日志契约。三层贯通（同一次请求的日志能在控制平面、Agent、DataLoader 三段里串起来查）真正的断点在这里。

所以当前最该补的是四件事：公共字段、关联 ID、采样限流、采集链路。日志数量本身够用，缺的是"查得到、串得起、撑得住"。

小结：控制平面能用，Agent 没契约，DataLoader 是空白，三层贯通的断点在 DataLoader。

## 2. Backlog（六大缺口）

下面六条缺口，每条都对应 §3 落地清单里要做的事。

1. **DataLoader 无生产日志契约**。DataLoader 是训练进程里真正读数据的库，它该打哪些字段、用什么级别，目前没有约定。三层里的最后一段无法关联，日志串到 Agent 这一层就断了。
2. **无采集链路**。JSON 日志只落在节点本地的容器运行时（节点上的容器引擎）里，没有往外送。节点一故障，日志跟着丢。
3. **无关联 ID 贯通**。控制平面的 `request_id`（一次请求的追踪编号）不出进程，只在自己内部用；Agent 根本没有 `request_id`；钩子帧（训练进程发给 Agent 的通知消息）也不带任务身份。同一次任务在三处留下的日志对不上号。
4. **无采样/限流**。Debug 级别一旦打开，逐块、逐帧都打日志，量可以打满节点磁盘。需要采样（按比例丢）和限流（超速率丢）兜底。
5. **无保留与轮转策略**。容器日志在节点上的上限（单文件多大、留几个文件）和中心存储的 TTL（日志留多久就删），都还没定义。
6. **Agent 日志字段未纳入契约**。字段名没有冻结。以后想改字段，没法判断改动会不会破坏已有的查询、看板和告警。

小结：六个缺口分四类——契约缺（第 1、6 条）、链路缺（第 2 条）、关联缺（第 3 条）、保护缺（第 4、5 条）。

## 3. 落地清单（P0 -> P3）

P0 到 P3 是优先级，P0 最急。先用大白话把四个阶段过一遍，逐格细节看后面的表。

- **P0 契约与字段补齐**：先把"写什么"定死。冻结 `9.1 design.md` §3.1 的字段表和 §3.2 的级别约定；Agent 引入一个与控制平面 `logging` 等价的包；把 `agentd/main.go` 里用错的 `error` 字段统一成 `err`；写脱敏函数（把 Secret 这类敏感值抹掉）和哨兵测试（故意打一个假 Secret，断言它不出现在任何日志里）；DataLoader 的日志契约先落成文档。截至 2026-10-22：`agent/internal/logging`、`err` 统一、脱敏函数与单测已完成；调用点接线、DataLoader 日志契约与哨兵负向断言未完成，P0 只能算部分完成。
- **P1 采集链路**：解决"日志放哪"。fluent-bit 按 DaemonSet 部署，把各节点日志采进 Loki；Prometheus 定期抓各组件的 `/metrics`；Grafana 接入 Loki 和 Prometheus 两个数据源；顺带把容器日志轮转配上。这一阶段已于 2026-10-21 在 kind 集群实测通过，四个工作负载全部 Ready。
- **P2 DataLoader 与关联 ID**：打通"三段怎么串"。DataLoader 库写入上下文与分位日志；webhook 注入环境变量；钩子帧补上任务身份字段；Controller 通过 gRPC metadata（gRPC 请求自带的键值对，用来跨进程传数据）把 `request_id` 传给 Agent；Agent 用拦截器（gRPC 请求的统一入口钩子）建 context logger，有 `request_id` 就继承、没有就新生成；同时落地采样限流。
- **P3 告警与看板**：补上"出问题怎么知道"。针对门控 Hold 超时、Agent 不可达、读 stall 超阈值、磁盘危险线、日志采集断流这些情况配告警；Grafana 建覆盖三层的看板；每条告警附 runbook（故障处置手册）链接。
