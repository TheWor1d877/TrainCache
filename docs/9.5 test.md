# 9.5 日志与监控 · 测试说明书

> 术语第一次在出现处有一行解释。

## §1 这份文档在说什么

9.x 是跨模块横切关注点，不是单一目录。日志测试分布在三处生产代码目录外加 M12 里程碑里的日志断言：`core/logging` 管脱敏（一份包），`controller/internal/logging` 和 `agent/internal/logging` 各管自己进程的 slog 初始化与 context 传递，M12 在 warmup/scheduler/webhook/dataset 四个业务包里各放一份 `m12_logs_assert_test.go` 逐行断言 9.1 设计文档里的十七个控制平面日志点；Agent 端也补了一份 `agent/svc/m12_logs_assert_test.go`，覆盖 preheat 任务生命周期、陈旧 generation 拒绝、evictor 淘汰轮次、hooksock 收端就绪与帧错误四条主线。指标测试分布在 `agent/metrics`（registry + families + capacity 三份）、`controller/internal/metrics`（metrics + m12_metrics 两份）、`agent/svc` 的 wiring，外加 warmup/scheduler/dataset 三个业务包里的 `m12_metrics_emit_test.go`。总共 **17 个 `_test.go`** 文件，约 **4480 行**，**64 个 `func TestXxx`** 入口。这份文档就是一张清单：每个文件测什么、跑哪些命令、覆盖了 9.1 里哪些已声明条目、还有哪些没覆盖。

## §2 怎么跑

所有命令都在仓库根目录执行，模块路径见 `go.work`：

```bash
# 日志核心三包
go test ./core/logging/... -v -count=1
go test ./controller/internal/logging/... -v -count=1
go test ./agent/internal/logging/... -v -count=1

# 指标核心
go test ./agent/metrics/... -v -count=1
go test ./controller/internal/metrics/... -v -count=1
go test ./agent/svc/... -run Metrics -v -count=1

# M12 日志断言（四个业务包各一份 + Agent 端一份）
go test ./controller/internal/controller/warmup/... -run M12 -v -count=1
go test ./controller/internal/scheduler/... -run M12 -v -count=1
go test ./controller/internal/webhook/... -run M12 -v -count=1
go test ./controller/internal/controller/dataset/... -run M12 -v -count=1
go test ./agent/svc/... -run M12 -v -count=1

# M12 指标 emit
go test ./controller/internal/controller/warmup/... -run "Metrics|Emits" -v -count=1
go test ./controller/internal/scheduler/... -run "ScoreNodeEmits" -v -count=1
go test ./controller/internal/controller/dataset/... -run "ReconcileNotFoundEmits" -v -count=1
```

- `-count=1` 禁止缓存，任何时候改了被测代码都应该加。
- 业务包测试里除了 `m12_*` 还会跑各自的其它测试，要只跑 9.x 相关的必须用 `-run M12` 或按函数名过滤。
- 这些测试全是**单元/轻集成**：没有 K8s APIServer、没有 Prometheus 真实 HTTP 抓取，用 `prometheus.NewRegistry()` 或内存 `slog.Handler` 替身。

## §5 已知未覆盖的点

这一节**不写将来打算补什么**，只列客观事实。

### (a) 低优先级（功能已在、测试暂缺、不会漏信号）

1. **dataset reconcile 入口/出口日志**：warmup 有完整生命周期断言，dataset 只测了 NotFound 和存储不可达，入口/出口那条 Info 存在但未单独断言字段。
2. **候选筛选结果日志**（9.1 第 4 点）：生产代码里有 `candidates=0` 的 Info 日志，字段含 `nodes/accessible/agent_ready/reason`，目前只靠 placement RPC 日志侧证候选为 0 的情况。
3. **GWAA 分配变化/未收敛日志**（9.1 第 9 点）：指标测了（`gwaa_unassigned` gauge），日志没单独断言 `assign/rounds/actions/unassigned/reason` 字段。
4. **门控判定日志**（9.1 第 11 点 `logGateDecision`）：函数存在，字段 `state/reason/rates/required/gap/slope` 未单独断言；目前只靠 gate gauge 的生命周期测试侧证。

### (b) 技术困难（功能没在当前代码里、补测试会卡住）
