# Controller & Scheduler 测试说明

reconcile 跑在 controller-manager 进程，打分跑在 kube-scheduler 进程；单元与集成用例全部在进程内完成，只有端到端需要 kind 集群。

## 命令

```bash
# controller 模块靠仓库根 go.work 解析 core 与 agentpb，换过依赖后先在仓库根跑一次 go work sync；GOWORK=off 构建失败属于预期
# 进程内驱动：k8s 对象用 controller-runtime 的 fake client 与 interceptor，gRPC 用 bufconn，对象存储用 core 的 mock Store，不需要本地 API Server 与 setup-envtest
make verify-controller
cd controller && go test ./... -race -count=1
cd controller && go test ./internal/gwaa ./internal/gate ./internal/scorefmt -count=1
cd controller && go test ./internal/gwaa -run 'TestCompute' -v
cd controller && go test ./internal/controller/warmup -run 'MinUnmet' -v
cd controller && go test ./internal/webhook -run TestManifestParity -v
cd controller && ./e2e/run.sh
```

## e2e：kind 端到端

`controller/e2e/run.sh` 演练一条完整成功链路：创建 DataSet、WarmupTask 与训练 Pod，断言 webhook 注入调度门与两个注解，scheduler 按 Pod 注解取分，门控放行后调度门移除、Pod 由 traincache-scheduler 调度到 Running，以及落点偏离时发 NodeDeviation 事件并回填 actualNode。脚本子命令 clean、setup、run、assert；exit 0 全部断言通过，1 断言或部署失败，2 用法或工具缺失；setup、run、assert 会把全局 kubectl context 切到 kind 集群且不切回，机器上还有其他集群时先导出私有 KUBECONFIG 副本。预热 RPC 的 Agent 服务端实现由 `docs/6.3-test.md`《svc：装配层、生命周期与探针》覆盖，本模块只测客户端一侧。
