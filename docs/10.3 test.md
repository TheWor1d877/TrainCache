# S3 合并回源网关测试说明书

## 1. 测试范围

覆盖四块：

1. 网关进程：路由、错误响应、探针、排水、配置、日志。
2. 合并核心：在途表、环形缓冲、订阅者、踢出、准入与公平调度。
3. Agent 侧：后端选择、失败判断标准、降级状态机、指标注册。
4. 集成：真实 minio-go 客户端经网关读数据；kind 集群里的部署与更新。

不覆盖：真实云端 COS/OSS/S3 的签名差异（用 MinIO 代）；内核级网络故障（丢包、半开连接）；跨机房拓扑。

## 2. 测试分层

| 层 | 范围 | 依赖 | 运行时间 |
|---|---|---|---|
| 单测 | 单个包内的函数与方法 | 无外部进程 | 秒级 |
| 契约测试 | 网关对 minio-go 的 HTTP 契约 | `httptest` 假源站 | 秒级 |
| 集成测试 | Agent S3Store → 网关 → 假源站；SIGTERM 排水 | 进程内起网关 | 十秒级 |
| 回归 | 现有 core/agent 全部用例 | 无 | 分钟级 |
| 集群 e2e | kind 里 Deployment、Service、ConfigMap、更新 | docker + kind | 十分钟级 |

覆盖程度分三档。「已覆盖」表示有确定性断言且覆盖正常与至少一个异常分支；「部分覆盖」表示只覆盖主路径或只覆盖单点；「缺失」表示没有用例。

## 3. 运行命令

### 3.1 单测与静态检查

```bash
cd gateway && go build ./... && go vet ./... && go test ./... -race -count=1
cd core    && go build ./... && go vet ./... && go test ./... -race -count=1
cd agent   && go build ./... && go vet ./... && go test ./... -race -count=1
```

仓库根另有聚合入口：

```bash
make verify-gateway     # 新增，等价于上面第一条
make verify-core
make verify-agent
make verify             # 三条全跑
```

前置条件：Go 1.26，`go.work` 已包含 `./gateway`。

### 3.2 元数据门禁

```bash
make verify-metadata
```

这条命令包含四项检查：镜像引用、文档链接、配置落位、发布物清单。配置落位检查覆盖 ConfigMap 的 17 个键与五份工作负载引用的一一对应关系。网关 Deployment 未加入 `hack/verify-config-placement.sh` 的 `WORKLOADS` 时，`gatewayBucketConcurrency` 会被判为无引用的孤立键。

### 3.3 契约与集成

```bash
cd gateway && go test ./internal/server/... -run 'Contract|Integration' -count=1 -v
cd core    && go test ./objectstore/... -run Gateway -count=1
cd agent   && go test ./svc/... -run 'Backend|Gateway' -count=1
```

默认不连真实 S3。要连真实后端时设 `TC_S3_ENDPOINT`、`TC_S3_ACCESS_KEY`、`TC_S3_SECRET_KEY`、`TC_S3_BUCKET`，未设置时相关用例跳过。

### 3.4 集群 e2e

```bash
make kind-up
make ctrl-up
make e2e-k8s
```

前置条件：本机 docker 可用，五个镜像已 `kind load`。改动清单类改动只跑 `make verify-metadata`，不要为了验证清单去起集群。

网关集群演练是独立脚本，不并入 `make e2e-k8s`（它要求 MinIO 桶里已有可读对象）：

```bash
# 前置：kind 集群可达；MinIO 在 minio namespace；traincache namespace 已有
#       ConfigMap traincache-config 与 Secret traincache-objstore；
#       traincache-gateway:dev 与 busybox:latest 已 kind load。
bash gateway/e2e/run-k8s.sh
E2E_KEY='compare-data-8m/blocks/shard-00000.tar#0' bash gateway/e2e/run-k8s.sh
TC_E2E_AGENT=1 bash gateway/e2e/run-k8s.sh   # 追加 Agent 降级联动（步骤 5）
```

脚本按步打印 `[OK]/[FAIL]/[SKIP]`，退出码 0/1；未设置 `E2E_KEY` 时先用 MinIO 内的 `mc` 找对象，找不到则步骤 3/4/5 记 SKIP 而不判 FAIL。脚本不删除 Deployment/Service；步骤 5 的 ConfigMap、副本数与 agentd 改动由 `trap` 兜底恢复。

### 3.5 CI

`verify.yml` 的模块矩阵增 `gateway`；`release-candidate.yml` 与 `release.yml` 的镜像循环增 `traincache-gateway`。CI 不跑 kind e2e 的网关用例，由 `e2e.yml` 手动触发。

### 3.6 长时稳态（T28）

```bash
cd gateway && go test ./internal/server/... -run Soak -race -count=1 -timeout=120s
GATEWAY_SOAK_DURATION=20s GATEWAY_SOAK_CONCURRENCY=8 \
  go test ./internal/server/... -run Soak -race -count=1 -timeout=180s
```

`TestSoakSteadyState` 默认跑 30s、8 并发；`testing.Short()` 时跳过。用例每 5s 打印一次 `HeapInuse`、`HeapAlloc` 与 `NumGoroutine`，结束时断言堆不随请求数增长、goroutine 回到基线、在途表清空。

4 小时版本由运维执行（同一用例，只改环境变量）：

```bash
cd gateway && GATEWAY_SOAK_DURATION=4h GATEWAY_SOAK_CONCURRENCY=32 \
  go test ./internal/server/... -run Soak -count=1 -timeout=5h
```

## 6. 覆盖缺口与补充计划

| 缺口 | 现状 | 优先级 | 补充方式 |
|---|---|---|---|
| 长时间运行的内存稳态 | 已覆盖（缩短版）；4 小时由运维执行 | 高 | 缩短版：`gateway/internal/server/soak_test.go`，默认 30s / 8 并发，每 5s 采样 `HeapInuse` 与 goroutine；4 小时：同用例 `GATEWAY_SOAK_DURATION=4h GATEWAY_SOAK_CONCURRENCY=32`，由运维执行 |
| SIGTERM 期间的真实长连接 | 部分覆盖 | 高 | kind e2e 在 100MB 对象传输中删除 Pod，断言 Agent 侧无降级、无截断 |
| 内核级网络故障（丢包、半开） | 缺失 | 中 | 用 `tc netem` 注入 5% 丢包与 30s 半开，断言超时判断标准与降级 |
| 多 dataset 真实并发 | 部分覆盖 | 中 | 三个 dataset 同时预热，断言份额分布与 60s 汇总的 `datasets` |
| 大块（64MiB）的踢出边界 | 部分覆盖 | 中 | 用 64MiB 假对象，订阅者刻意慢读，断言 `written - pos > cap` 的边界值 |
| 池复用下的数据串台 | 部分覆盖 | 高 | 连续两个不同内容的对象共用同一缓冲，断言第二个对象的字节前缀不含第一个对象的内容 |
| 真实云端签名差异 | 缺失 | 低 | 有 COS/OSS 环境时补一条冒烟测试，比较 ETag 与状态码 |
| 60s 汇总的时钟漂移 | 缺失 | 低 | 注入可控时钟，断言窗口边界不重不漏 |
