# Checkpoint 异步 Sidecar 测试说明书

## 1. 测试范围

覆盖 `checkpoint/` 全部包、`controller/internal/webhook` 新增的注入规则、以及两者与现有控制面清单的配合。不在本期范围：指标、Event、多 rank、第三方插件、弹性训练。

## 2. 测试分层

| 层 | 内容 | 依赖 | 时机 |
|---|---|---|---|
| 单元 | 纯函数、编解码、状态判断 | 无 | 每次提交 |
| 契约 | 插件协议、manifest、注入后的 Pod spec | 假插件、fake client | 每次提交 |
| 集成 | S3 读写、子进程管理 | MinIO | CI |
| 回归 | 现有 warmup 注入路径 | fake client | 每次提交 |
| 集群 | kind 内保存与恢复 | kind、MinIO | PR 到 main |
| 稳态 | 连续多 step、缓存淘汰 | kind | 发布前 |

## 3. 运行命令

```bash
cd checkpoint
go build ./... && go vet ./... && go test ./... -race -count=1
test -z "$(gofmt -l .)"
make verify-checkpoint    # 同上，并入根入口
make verify               # 六路一起跑，含 controller 回归
```

契约测试：

```bash
cd checkpoint && go test ./internal/plugin/... -run 'TestProtocol|TestManifest' -count=1
cd controller && go test ./internal/webhook/... -run 'TestCheckpointInject' -count=1
```

集成测试前置 MinIO 在 127.0.0.1:9000、桶已建：

```bash
cd checkpoint
TC_S3_ENDPOINT=127.0.0.1:9000 TC_S3_ACCESS_KEY=traincache \
TC_S3_SECRET_KEY=traincache-probe TC_S3_BUCKET=traincache \
go test ./internal/plugin/s3 -run TestS3 -count=1
```

未设置 `TC_S3_*` 时该用例跳过，普通 `go test ./...` 仍通过。改准入代码后跑满 controller 全量，不只看 webhook 包。

集群测试：

```bash
cd checkpoint && ./e2e/run.sh          # setup + run
cd checkpoint && ./e2e/run.sh assert   # 只跑断言
cd checkpoint && ./e2e/run.sh clean    # 删除 kind 集群
```

前置：docker 可用；`traincache-checkpointd:dev` 与 `busybox:latest` 已 `kind load`；namespace `traincache` 存在；MinIO 有桶。CI 在 `verify.yml` 的 matrix 加 `checkpoint`，并在 `s3-integration` job 加一个跑 checkpoint 包的步骤。

| `controller/internal/webhook/pod_mutator_test.go` | 现有 warmup 路径 | 改动前后行为一致 |

## 6. 覆盖缺口

| 项 | 状态 | 说明与补充 |
|---|---|---|
| 保存与恢复正常路径 | 已覆盖 | 单测加集群测试 |
| 重试与总时限 | 部分覆盖 | 单测只覆盖次数，补 30 秒慢后端用例 |
| 续传跨进程 | 部分覆盖 | 补「写状态后杀进程再跑」用例 |
| 容量写满 | 已覆盖 | `checkpoint/e2e` 的 `enospc` 模式：状态卷是 1 MiB tmpfs，训练程序写满后 sidecar 落状态报 ENOSPC，断言最终保存失败、工作目录保留、step 未上传、sidecar 存活 |
| NVMe 缓存跨容器重启 | 缺失 | 本期 NVMe 是 emptyDir（D17），缓存命中只在同 Pod 内验证 |
| webhook 注入的集群端到端 | 已覆盖 | `checkpoint/e2e` 的 `run` 模式：Pod 只带 label 与 annotation，sidecar 由集群里的 webhook 注入，断言 init 容器、工作卷与 TASK_ID 注入结果 |
| 时间与序 | 已覆盖 | `.done` 时间戳、乱序 step |
| 并发上传与淘汰竞争 | 部分覆盖 | 补 `-race` 下的并发淘汰用例 |
| 凭证脱敏 | 部分覆盖 | 补「后端返回体含凭证」用例 |
| 多 rank、弹性训练、第三方插件、指标与事件 | 缺失 | 一期不做，不补 |
| 长时间运行 | 已覆盖 | `checkpoint/e2e` 的 `loop` 模式：连续 100 步保存，断言上传 100 次、工作目录清空、NVMe 缓存按保留份数收敛、sidecar 打开的文件数不随步数增长 |
