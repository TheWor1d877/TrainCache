# Checkpoint 异步 Sidecar 测试说明

## 命令

```bash
make verify-checkpoint
make verify
cd checkpoint && go build ./... && go vet ./...
cd checkpoint && go test ./... -race -count=1
cd checkpoint && go test ./internal/plugin ./internal/manifest -count=1
cd controller && go test ./internal/webhook -run 'TestCheckpoint' -count=1
```

```bash
# 集成用例需要本机 127.0.0.1:9000 有 MinIO 且桶 traincache 已建；
# 不设 TC_S3_* 时该用例跳过，普通 go test 仍通过。
cd checkpoint
TC_S3_ENDPOINT=127.0.0.1:9000 TC_S3_ACCESS_KEY=traincache \
TC_S3_SECRET_KEY=traincache-probe TC_S3_BUCKET=traincache \
go test ./internal/plugin/s3 -run TestS3 -count=1
```

```bash
# 集群用例需要 docker 可用、镜像 traincache-checkpointd:dev 与 busybox:latest 已 kind load、
# namespace traincache 存在、MinIO 有 traincache 桶；
# 并行跑两次要用 CLUSTER= 与 LOG_DIR= 分开集群与日志目录，否则会互相覆盖。
cd checkpoint && ./e2e/run.sh
cd checkpoint && ./e2e/run.sh assert
cd checkpoint && ./e2e/run.sh enospc
cd checkpoint && ./e2e/run.sh loop
cd checkpoint && ./e2e/run.sh restore-giveup
cd checkpoint && ./e2e/run.sh clean
```

## 覆盖缺口

| 缺什么 | 优先级 | 怎么补 |
|---|---|---|
| `cmd/checkpointd` 把恢复放弃错误映射成退出码 3 只有两行代码，没有单测。 | 高 | 把错误到退出码的映射抽成可测函数，断言放弃错误返回 3 而不是 1。 |
| checkpoint 的 S3 集成用例要设 `TC_S3_*` 才跑，CI 的 MinIO job 只跑核心库的 objectstore 包，这个用例在 CI 里没有入口。 | 高 | 在 s3-integration job 里加一个步骤，跑 checkpoint 包的 `TestS3`。 |
| `cmd/checkpointd` 的 `probe` 子命令按探针文件内容定退出码，没有单测。 | 中 | 写临时探针文件分别写 `ready` 与其它内容，断言退出码是 0 与 1。 |
| `JOB` 的注入只断言到单测层，裸 Pod 的空串在集群侧没有断言。 | 中 | 在集群用例里加一个裸 Pod，断言容器环境里 `JOB` 是空串而不是没有这个键。 |
| 集群用例没有断言多 rank 与弹性副本数下的行为。 | 低 | 加一个副本数与声明值不一致的 Job，断言该 step 判不完整并记下多余 rank 的告警。 |
