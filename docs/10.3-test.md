# Checkpoint 异步 Sidecar 测试说明书

## 1. 测试范围

覆盖 `checkpoint/` 全部包、`controller/internal/webhook` 新增的注入规则、以及两者与现有控制面清单的配合。不在本期范围：指标、Event、多 rank、第三方插件、弹性训练。

## 2. 测试分层

| 层 | 内容 | 依赖 | 时机 |
|---|---|---|---|
| 单元 | 纯函数、编解码、状态判断 | 无 | 每次提交 |
| 契约 | 插件协议、manifest、注入后的 Pod spec | 假插件、fake client | 每次提交 |
| 集成 | S3 读写、子进程管理 | MinIO | CI |
| 回归 | 现有 warmup 注入路径 | fake client | 每次提交 |
| 集群 | kind 内保存与恢复 | kind、MinIO | PR 到 main |
| 稳态 | 连续多 step、缓存淘汰 | kind | 发布前 |

## 3. 运行命令

```bash
cd checkpoint
go build ./... && go vet ./... && go test ./... -race -count=1
test -z "$(gofmt -l .)"
make verify-checkpoint    # 同上，并入根入口
make verify               # 六路一起跑，含 controller 回归
```

契约测试：

```bash
cd checkpoint && go test ./internal/plugin/... -run 'TestProtocol|TestManifest' -count=1
cd controller && go test ./internal/webhook/... -run 'TestCheckpointInject' -count=1
```

集成测试前置 MinIO 在 127.0.0.1:9000、桶已建：

```bash
cd checkpoint
TC_S3_ENDPOINT=127.0.0.1:9000 TC_S3_ACCESS_KEY=traincache \
TC_S3_SECRET_KEY=traincache-probe TC_S3_BUCKET=traincache \
go test ./internal/plugin/s3 -run TestS3 -count=1
```

未设置 `TC_S3_*` 时该用例跳过，普通 `go test ./...` 仍通过。改准入代码后跑满 controller 全量，不只看 webhook 包。

集群测试：

```bash
cd checkpoint && ./e2e/run.sh                    # setup + run
cd checkpoint && ./e2e/run.sh assert             # 只跑断言
cd checkpoint && ./e2e/run.sh enospc             # 状态卷写满
cd checkpoint && ./e2e/run.sh loop               # 连续 100 步稳态
cd checkpoint && ./e2e/run.sh restore-giveup     # 恢复放弃与 Job Failed，预算约 40 分钟
cd checkpoint && ./e2e/run.sh clean              # 删除 kind 集群
```

并行的两次运行要用 `CLUSTER=` 与 `LOG_DIR=` 分开集群与日志目录，否则会互相覆盖。

前置：docker 可用；`traincache-checkpointd:dev` 与 `busybox:latest` 已 `kind load`；namespace `traincache` 存在；MinIO 有桶。CI 在 `verify.yml` 的 matrix 加 `checkpoint`，并在 `s3-integration` job 加一个跑 checkpoint 包的步骤。

## 6. 覆盖缺口

| 项 | 状态 | 说明与补充 |
|---|---|---|
| 保存与恢复正常路径 | 已覆盖 | 单测加集群测试 |
| 重试与总时限 | 已覆盖 | `retry_deadline_test.go` 注入每次尝试都慢的后端，锁住总时限终止重试与终态日志的字段；真实预算按比例缩到毫秒级，形状保持慢尝试吃掉预算与 30 秒间隔叠加慢尝试两种（D12） |
| 续传跨进程 | 已覆盖 | `checkpoint/internal/plugin/s3/resume_after_kill_test.go` 的 `TestResumeAcrossProcessKillSkipsConfirmedParts`：子进程写完分片状态后被 SIGKILL，第二次运行复用同一 multipart upload id，断言已确认的第 1 片不再重传、manifest 仍可读出、状态文件被清掉。`checkpoint/internal/plugin/resume_after_kill_test.go` 的 `TestResumeStateSurvivesProcessKill` 锁住状态文件本身的追加语义：子进程被杀后已写入的分片记录仍能读出，后续追加继续往后写。`checkpoint/internal/plugin/local/resume_after_kill_test.go` 的 `TestLocalResumeAfterProcessKill` 覆盖 local 后端：复制中途被杀时后端目录里只有临时文件、目标文件与 manifest 都不出现（local 不写续传状态文件，见 10.1 §5.2 与 10.2 D16），下一次运行保存出与源文件逐字节一致的内容 |
| 容量写满 | 已覆盖 | `checkpoint/e2e` 的 `enospc` 模式：状态卷是 1 MiB tmpfs，训练程序写满后 sidecar 落状态报 ENOSPC，断言最终保存失败、工作目录保留、step 未上传、sidecar 存活 |
| webhook 注入的集群端到端 | 已覆盖 | `checkpoint/e2e` 的 `run` 模式：Pod 只带 label `traincache.io/checkpoint=<ConfigMap 名>`，sidecar 由集群里的 webhook 注入，断言 init 容器、工作卷与 `TASK_ID` 的注入结果（D24）。`JOB` 的注入只在单测层断言：集群侧的 jsonpath 取不到值时分不清「没这个变量」与「值是空串」，裸 Pod 的表现待实跑确认 |
| 时间与序 | 已覆盖 | `.done` 时间戳、乱序 step |
| 并发上传与淘汰竞争 | 已覆盖 | `checkpoint/internal/sidecar/evict_race_test.go` 的 `TestConcurrentUploadAndEvictKeepsInFlightAndLinked` 与 `TestConcurrentRestoreBackfillAndEvict`：在 `-race` 下让上传回填与保留期淘汰同时跑，断言在途回填的目录不被淘汰、被软链引用的缓存不被删、缓存与链接表始终自洽 |
| 凭证脱敏 | 已覆盖 | `redact_backend_test.go` 注入一条回显 AK、SK 与预签名 URL 的后端错误，覆盖 `err` 属性、消息文本、结构化字段三条路径 |
| 恢复放弃后的 Job 状态 | 已覆盖 | sidecar 层「到点返回 `ErrRestoreGiveUp`、放弃前写一条 ERROR」有单测；`cmd/checkpointd` 把它映射成退出码 3 只有两行、无单测。`checkpoint/e2e` 的 `restore-giveup` 模式用 local 后端留一份数据与 manifest 的 sha256 不符的已提交 step，每次恢复都判 CORRUPT，到点写 ERROR 并退 3。2026-11-05 在 kind 1.37 上实跑：Job 以 `BackoffLimitExceeded` 判 Failed、Pod 删除、占用随之释放。每次放弃记成 init 容器的一次重启、计入 `backoffLimit`；`status.failed` 是 1，记的是失败的 Pod 数，不是重启次数（D14）。 |
| 长时间运行 | 已覆盖 | `checkpoint/e2e` 的 `loop` 模式：连续 100 步保存，断言上传 100 次、工作目录清空、NVMe 缓存按保留份数收敛、sidecar 打开的文件数不随步数增长 |
