# 6.4 core 测试说明书

> 配套 design.md `6.1`、plan.md `6.2`、decisions.md `6.3`。读者懂 Go 和 K8s/存储基础就能跟下来，新名词第一次出现顺手解释。

## §1 这份文档在说什么

core 是缓存核心库（纯 Go 库，编译进 Agent，不单独跑进程）。当前共有 **27 个 `*_test.go` 文件**、**约 8700 行测试代码**、**约 98 个 `Test` 函数**，覆盖 objectstore、cas、fetch、index、publish、internal/digest、logging 共 **7 个包**。测试框架用 Go 标准库 testing + testify/assert + mockey/gomonkey 做打桩；对象存储层用内存 mock（`objectstore.NewMock()`），CAS 层用临时目录 `t.TempDir()`，两者配合实现"不需要 S3 真实后端也能跑绝大部分测试"。少数集成测试（`s3_integration_test.go`、`selfopen_test.go`、`multitar_e2e_test.go`）会探测环境变量、缺了就 skip。

一句话：覆盖了库的全部 7 个包，以单元测试为主、集成和并发为辅，核心接口的冻结契约都有测试。

## §2 怎么跑

```bash
# 全量（含竞态检测）
cd core && go test ./... -race -count=1
# 示例输出摘要
# ?    traincache/core/cmd/trainpublish  [no test files]
# ok   traincache/core/objectstore  0.4s
# ok   traincache/core/cas           1.1s
# ok   traincache/core/fetch         0.6s
# ok   traincache/core/index         3.2s
# ok   traincache/core/publish       0.9s
# ok   traincache/core/internal/digest 0.3s
# ok   traincache/core/logging       0.3s

# 按包跑
go test ./index/... -race -count=1

# 只跑某个测试函数（-run 支持正则）
go test ./cas/... -run 'TestStore_Put_Concurrent' -v

# 跑集成测试（需要环境变量，缺了会 skip）
TC_S3_ENDPOINT=... TC_S3_ACCESS_KEY=... TC_S3_SECRET_KEY=... TC_S3_BUCKET=... \
  go test ./objectstore -run TestS3_ConditionalWrite -v
```

`-count=1` 禁用 Go test 的结果缓存；`-race` 开启数据竞争检测（部分并发测试依赖 race 才能抓到问题）。

## §5 已知未覆盖的点

以下为当前版本（core 6.x）尚未覆盖或不打算覆盖的功能。分三类：

**(a) 低优先级不打算补**

| 未覆盖项 | 理由 |
|----------|------|
| `cas.Store.Open` 过程中进程崩溃（临时文件残留场景） | §9 验收要求的"写半崩溃"已通过注入 + 预置孤儿临时文件的方式覆盖了 Put 路径。Open 本身是只读操作，中途崩溃不会产生新文件，恢复逻辑无差别测试价值 |
| `objectstore.S3Store` 的实际网络超时与重试策略 | S3Store 内部用 minio-go SDK，重试由 SDK 负责。core 这层的接口契约就是 Store 的 6 个方法，网络层策略不属于 core 的冻结约定范围 |
| `publish` 对 tar 文件内部目录结构的处理 | publish 只关心"ReaderAt + Size + Path"，不解析 tar 内部布局。真实 tar 文件的处理由上层 CLI（`cmd/trainpublish`）负责，core 库的测试只需要 Source 这个抽象输入 |

**(b) 暂时技术困难**

| 未覆盖项 | 困难在哪 |
|----------|----------|
| `s3_integration_test.go` 在 CI 环境自动跑 | 当前 CI（GitHub Actions / Jenkins）没有预置 MinIO 或 S3 凭证。想在 CI 上开这个测试，需要先把对象存储的测试基础设施容器化并注入到 pipeline。这是运维层面的事，不是写测试代码的问题 |
| `fetch.Fetcher` 的网络超时语义模拟 | Fetcher 不直接持有 net.Conn，它的 `store.Get` 走 objectstore.Store 接口。在 mock Store 里模拟"下载到一半卡住"需要 goroutine + time.After 注入，构造复杂且容易 flaky。当前策略是依赖 CAS 层的 Verify 失败重试和竞态检测间接覆盖 |
