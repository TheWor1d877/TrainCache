# core 测试说明书

本文记录 core 库的测试版图：怎么跑、每个文件测哪条冻结契约。接口定义见 `5.1 design.md`，里程碑见 `5.2 plan.md`，决策见 `5.3 decisions.md`。

## §1 测试范围

core 是缓存核心库（纯 Go 库，编译进 Agent，不单独跑进程）。当前共 **27 个 `*_test.go` 文件**、**约 8800 行测试代码**、**133 个 `Test` 函数**，覆盖 objectstore、cas、fetch、index、publish、internal/digest、logging 共 **7 个包**，以单元测试为主、集成和并发为辅，核心接口的冻结契约都有测试。

测试框架只有 Go 标准库 `testing`：core 的测试不引第三方断言库，也不打桩——替身全部是手写实现。对象存储层用内存 mock（`objectstore.NewMock()`），CAS 层用临时目录 `t.TempDir()`，所以绝大部分测试不需要 S3 真实后端。需要外部服务的只有 `objectstore/s3_integration_test.go`：它探测 `TC_S3_ENDPOINT`/`TC_S3_ACCESS_KEY`/`TC_S3_SECRET_KEY`/`TC_S3_BUCKET` 四个环境变量，缺了就 skip。`fetch/selfopen_test.go` 与 `publish/multitar_e2e_test.go` 是内存内跑完的集成测试，不探环境变量。

## §2 运行方式

```bash
# 全量（含竞态检测）
cd core && go test ./... -race -count=1
# 示例输出摘要
# ?    traincache/core/cmd/trainpublish  [no test files]
# ok   traincache/core/objectstore  0.4s
# ok   traincache/core/cas           1.1s
# ok   traincache/core/fetch         0.6s
# ok   traincache/core/index         3.2s
# ok   traincache/core/publish       0.9s
# ok   traincache/core/internal/digest 0.3s
# ok   traincache/core/logging       0.3s

# 按包跑
go test ./index/... -race -count=1

# 只跑某个测试函数（-run 支持正则）
go test ./cas/... -run 'TestStore_Put_Concurrent' -v

# 跑集成测试（需要环境变量，缺了会 skip）
TC_S3_ENDPOINT=... TC_S3_ACCESS_KEY=... TC_S3_SECRET_KEY=... TC_S3_BUCKET=... \
  go test ./objectstore -run TestS3_ConditionalWrite -v
```

`-count=1` 禁用 Go test 的结果缓存；`-race` 开启数据竞争检测（部分并发测试依赖 race 才能抓到问题）。
