# traintrace 接口与实现契约

`traintrace` 是一个单机、只读、全 C 的 eBPF 观测二进制。它用 libbpf 加 CO-RE 把块 I/O 延迟、major fault、filemap 预读三类探针装进内核，在用户态循环里收事件、配对、算指标，把结构化指标文件写进指定目录，并在终端打印本轮摘要。二进制内部完成采集、事件配对、指标计算和输出，节点上不需要 Python，也不需要预装 libbpf。

## 交付形态与构建

源码落顶层目录 `ebpfobs/`：`src/traintrace.bpf.c` 是内核侧程序，`src/main.c` 是用户态，`src/shared.h` 是两侧共用的 map 键值结构、事件结构与枚举，`Makefile` 是构建入口，`build/` 存生成物与最终二进制，`vendor/libbpf/` 以 git submodule 引入。

构建分四步：`bpftool btf dump file /sys/kernel/btf/vmlinux format c` 生成 `vmlinux.h`（目标内核的类型镜像，CO-RE 靠它做字段重定位）；`clang -target bpf -g -O2 -c` 把 `.bpf.c` 编成带 BTF 的 eBPF 对象；`bpftool gen skeleton` 把该对象包成可在 C 里直接装载的骨架头文件；用户态与骨架、与静态 libbpf 一起链接成一个 ELF。

产物是一个静态链接的 `traintrace`，eBPF 对象内嵌其中，运行时不加载任何外部 `.o`，也没有动态库依赖。构建期用的 `vmlinux.h` 来自编译机内核，交付物靠 CO-RE 在运行机内核上重定位，所以编译机和目标机内核版本不必相同，目标机需要有 `/sys/kernel/btf/vmlinux`。

### Makefile 目标

`ebpfobs/Makefile` 分四步串起构建，产物固定落 `build/`。

```make
# ebpfobs/Makefile
VMLINUX_H := build/vmlinux.h
BPF_OBJ   := build/traintrace.bpf.o
SKEL_H    := build/traintrace.skel.h

all: build/traintrace

$(VMLINUX_H):
	bpftool btf dump file /sys/kernel/btf/vmlinux format c > $@

$(BPF_OBJ): src/traintrace.bpf.c $(VMLINUX_H) src/shared.h
	clang -target bpf -D__TARGET_ARCH_x86 -Ibuild -g -O2 -c $< -o $@

$(SKEL_H): $(BPF_OBJ)
	bpftool gen skeleton $< > $@

build/traintrace: src/main.c $(SKEL_H) vendor/libbpf/output/libbpf.a
	$(CC) -Ibuild -Ivendor/libbpf/src src/main.c \
	      vendor/libbpf/output/libbpf.a -lelf -lz -static -o $@

vendor/libbpf/output/libbpf.a:
	$(MAKE) -C vendor/libbpf/src BUILD_STATIC_ONLY=1 DESTDIR=$(CURDIR)/vendor/libbpf/output install
	rm -f $(CURDIR)/vendor/libbpf/output/libbpf.so*
```

`-static` 要求静态 `libelf` 与 `libz` 在构建机上就位（`libelf-dev:static-libs`、`zlib1g-dev`）；缺静态库时这一步链接失败，交付前在构建机确认。

## 内核侧程序与挂载点

每个程序只做一件事：把事实写进聚合 map 或压进 ringbuf，配对与归因留给用户态。tracepoint 的原始记录只带展平后的字段，`struct request` 与 `struct folio` 指针不进记录，字段一律用 `bpf_probe_read_kernel` 从展平结构里读。

- `do_blk_issue` 挂 `SEC("tracepoint/block/block_rq_issue")`，从 ctx 读 `dev`、`sector`、`rw`，只受理 `watch_dev` 里的读写请求，以 `{dev, sector}` 为键、`bpf_ktime_get_ns()` 为值写进 `rq_start`。`block_rq_issue` 与 `block_rq_complete` 的展平记录都不带 `struct request` 指针，配对键用（设备、起始扇区），与 11.4 的实测一致。
- `do_blk_complete` 挂 `SEC("tracepoint/block/block_rq_complete")`，读 `dev`、`sector`、`rw`，用 `{dev, sector}` 在 `rq_start` 取回起始时刻，算差值 `dt`，按 log2 落进 `blk_hist` 的桶，命中后删表项。`rw` 的操作位 `rw & REQ_OP_MASK` 取 `REQ_OP_READ`/`REQ_OP_WRITE` 定读写维度。
- `do_fault_enter` 挂 `SEC("kprobe/handle_mm_fault")`，把进入时刻以 `bpf_get_current_task_btf()` 为句柄存进 task 本地存储 `mmf_ts`。
- `do_fault_return` 挂 `SEC("kretprobe/handle_mm_fault")`，返回值在 x86-64 的 `pt_regs` 里是 `ax`，读 `VM_FAULT_MAJOR`（`0x4`），置位才按（cgroup id、pid）在 `fault_agg` 上累加 major 次数与该次耗时（返回时刻减 `mmf_ts`），随后清掉 `mmf_ts`。
- `do_add_to_cache` 挂 `SEC("tracepoint/filemap/mm_filemap_add_to_page_cache")`，读 `s_dev`、`ino`、`index`、`order`，压一条 `EV_ADD` 进 ringbuf。
- `do_filemap_fault` 挂 `SEC("tracepoint/filemap/mm_filemap_fault")`，读 `s_dev`、`ino`、`index`，压一条 `EV_FAULT` 进 ringbuf。
- `do_get_pages` 挂 `SEC("tracepoint/filemap/mm_filemap_get_pages")`，读 `s_dev`、`ino`、`index`、`last_index`，压一条 `EV_GETP` 进 ringbuf。

filemap 三个程序在压事件前先比对 `watch_cgroup`：事件发起进程的 cgroup id 不在集合里就返回，不压 ringbuf。块两个程序在入口比对 `watch_dev`：不是被观测缓存盘就返回。这样进 ringbuf 的量只跟被观测负载有关，与整机其它 I/O 隔离。

## BPF map 契约

维度键、单位与默认值是实现要照抄的部分，缺省值在命令行没覆盖时生效。

- `rq_start`：`BPF_MAP_TYPE_LRU_HASH`，键是结构 `{u32 dev; u64 sector;}`，值是 `u64` 起始时刻，`max_entries` 默认 1048576。配对表的上界靠 LRU，bpf 侧没有廉价的全表定时扫描：条目数逼近上限时内核按最近未用淘汰最旧的一条，issue 出去迟迟没 complete 的请求最终被挤出，代价是那笔延迟不计入直方图。
- `blk_hist`：`BPF_MAP_TYPE_PERCPU_HASH`，键是结构 `{u32 dev; u8 rw; u8 bucket;}`，`bucket` 是延迟纳秒的 log2 下标，范围 0 到 31，值 `u64` 计数。per-CPU 摊开写入避免热路径抢同一缓存行；用户态拉取时跨 CPU 求和还原全局直方图，读毕清零。
- `blk_issue_cnt`、`blk_complete_cnt`：两个 `BPF_MAP_TYPE_PERCPU_ARRAY`，单元素 `u64`，不清零。`blk_issue_cnt` 在每笔被观测设备的 issue 写表前自增；`blk_complete_cnt` 只在 complete 于 `rq_start` 查到对应起始时刻、配对成功时自增，查不到起始时刻的 complete 不计。用户态收尾跨 CPU 求和，配合 `rq_start` 残留数推导淘汰数。
- `fault_agg`：`BPF_MAP_TYPE_HASH`，键是结构 `{u64 cgroup_id; u32 pid;}`，值是结构 `{u64 major_cnt; u64 major_ns;}`。`major_ns / major_cnt` 给出该进程平均 major fault 耗时，读毕清零。comm 不进键，用户态在拉取时按 pid 查 `/proc/<pid>/comm` 补上。
- `mmf_ts`：`BPF_MAP_TYPE_TASK_STORAGE`，值 `u64`，随进程生命周期自动回收，不需要清理逻辑。
- `rb`：`BPF_MAP_TYPE_RINGBUF`，大小默认 33554432 字节（32MB），承载 filemap 三条事件。
- `rb_drop`：`BPF_MAP_TYPE_PERCPU_ARRAY`，单元素，ringbuf 交付失败时自增，是丢事件计数器。
- `watch_cgroup`：`BPF_MAP_TYPE_HASH`，键 `u64` cgroup id，值 `u8`，装载后由用户态从被观测 Pod 的 cgroup 路径批量写入。
- `watch_dev`：`BPF_MAP_TYPE_ARRAY`，键 `u32`（0 到 7），值结构 `{u32 encoded_dev;}`，存被观测缓存盘的编码设备号集合，块程序在入口与之比对。同一块盘有两个设备号：块 tracepoint 上报整盘（`nvme0n1`），文件系统上报分区（`nvme0n1p2`），用户态把解析出的号、所属整盘号与各分区号一起写进本表，块侧两种上报都能匹配上。

### map 与共享定义的声明

`src/traintrace.bpf.c` 里这些 map 声明形态固定，LRU 与 ringbuf 的 `max_entries`、`key_size`、`value_size` 直接照抄，编译器按 `SEC(".maps")` 收进 BTF 供骨架生成访问器。

```c
// src/traintrace.bpf.c
struct {
    __uint(type, BPF_MAP_TYPE_LRU_HASH);
    __type(key, struct rq_key);      // { u32 dev; u64 sector; }
    __type(value, __u64);            // issue 起始时刻
    __uint(max_entries, 1048576);
} rq_start SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_HASH);
    __type(key, struct blk_key);     // { u32 dev; u8 rw; u8 bucket; }
    __type(value, __u64);            // 命中计数
    __uint(max_entries, 4096);
} blk_hist SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __type(key, struct fault_key);   // { u64 cgroup_id; u32 pid; }
    __type(value, struct fault_val); // { u64 major_cnt; u64 major_ns; }
    __uint(max_entries, 4096);
} fault_agg SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_TASK_STORAGE);
    __uint(key_size, sizeof(void *)); // 固定为 struct task_struct * 大小
    __type(value, __u64);            // handle_mm_fault 进入时刻
    __uint(max_entries, 4096);       // 预分配的 task 槽数
} mmf_ts SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 33554432);   // 32MB
} rb SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_ARRAY);
    __uint(key_size, sizeof(__u32));
    __uint(value_size, sizeof(__u64));
    __uint(max_entries, 1);          // 丢事件计数
} rb_drop SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __type(key, __u64);              // cgroup id
    __type(value, __u8);
    __uint(max_entries, 256);        // 被观测 cgroup 上限
} watch_cgroup SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(key_size, sizeof(__u32));
    __type(value, struct dev_val);   // { u32 encoded_dev; }
    __uint(max_entries, 1);          // 被观测缓存盘
} watch_dev SEC(".maps");
```

`mmf_ts` 的 `key_size` 固定为指针大小、`max_entries` 是预分配槽数，装载时内核按在线 task 数占位，进程退出即回收，不需要用户态清理。

`src/shared.h` 放两侧共用的键值结构与事件枚举。

```c
// src/shared.h
struct rq_key    { __u32 dev; __u64 sector; };
struct blk_key   { __u32 dev; __u8 rw; __u8 bucket; };
struct fault_key { __u64 cgroup_id; __u32 pid; };
struct fault_val { __u64 major_cnt; __u64 major_ns; };
struct dev_val   { __u32 encoded_dev; };

enum tev_kind { EV_ADD = 1, EV_FAULT = 2, EV_GETP = 3 };

// struct tev 见「事件结构」一节，两侧共用同一份
```

## 事件结构

内核侧压进 ringbuf、用户态取出配对，两侧共用 `shared.h` 里这一个结构。

```c
struct tev {
    __u64 nsecs;      // bpf_ktime_get_ns，配对与时间窗对齐用
    __u64 cgroup_id;  // 发起进程 cgroup，归因用
    __u64 ino;        // filemap 展平字段 ino，文件标识
    __u64 index;      // 起始页索引（folio 首页）
    __u64 last_index; // 仅 EV_GETP 有效，消费覆盖的末页索引
    __u32 dev;        // s_dev 编码设备号
    __u32 pid;        // 发起进程 tgid
    __u8  kind;       // EV_ADD / EV_FAULT / EV_GETP
    __u8  order;      // 仅 EV_ADD 有效，本次进缓存是 2^order 个连续页
};
```

一条 `EV_ADD` 代表从 `index` 起的连续 `2^order` 个页进入页缓存。多页 folio 由实测确认：128MB 冷读只有 1063 条进缓存事件，`Σ2^order` 等于全量 32768 页。用户态配对时把每条 `EV_ADD` 展开成它覆盖的索引区间。

## 用户态主流程

`traintrace` 启动后先解析命令行，确定被观测缓存盘与被观测 Pod 的 cgroup 集合；装载 skeleton，把设备编码号写进 `watch_dev`、cgroup id 逐个写进 `watch_cgroup`；背靠背读一次 `/proc/uptime` 与 `clock_gettime(CLOCK_REALTIME)`，把差值 `epoch_ns − uptime_ns` 存进本轮记录，用于把事件 `nsecs` 换算成 epoch；随后进入 `ring_buffer__poll` 循环收 filemap 事件，同时按 `--poll-interval`（默认 1s）拉取 `blk_hist`、`fault_agg` 并清零，把直方图快照与 fault 快照按时间窗落进指标文件。

到 `--duration`（默认 60s，0 表示常驻直到收到 SIGINT）或被 SIGINT 终止时，循环退出，`traintrace` 停止收 filemap，做一次全量拉取，然后进入配对与计算阶段。配对阶段它按（设备、inode）把展开后的进缓存索引集合，与 `EV_FAULT` 单页、`EV_GETP` 的 `index` 到 `last_index` 区间构成的消费索引集合做差，得出进缓存页数、被消费页数、以及从未被消费的无效预读页数与比例。归因阶段它比对 filemap 两类事件的发起者：一条 `EV_FAULT` 缺页消费的页若是由另一个 pid 的 `EV_ADD` 进缓存的，把这条标为疑似预读归因偏移，计数累加进 major_fault 段，不改记到别的进程名下。块侧是直方图、不带逐事件发起者，归因只能落在 filemap 事件上。最后它把指标文件、本轮 manifest 写到 `--out-dir`，把摘要打到终端。

异常分支就地处理：装载逐个程序 attach，某个失败不影响其余，失败的程序名与 `libbpf` 报错进 stderr，`traintrace` 继续跑已装上的探针，摘要与 manifest 注明哪类没出数。`rb_drop` 非零时在摘要里报出丢事件条数，指标文件 readahead 段的 `complete` 置 false、manifest 的 `filemap_complete` 置 false。内核不暴露 LRU 逐 map 淘汰计数，`rq_start_evicted` 按 `issue 总数 − complete 配对成功数 − 收尾表内残留` 推导：插进表却既没配对删除、收尾也不在表里的请求就是被淘汰没计进直方图的，进 manifest 与 run 段，作为延迟直方图可能少计的提示。

### 用户态函数分解

`src/main.c` 按固定顺序调这几个函数，每个函数职责单一，失败只记 stderr 并继续，不中断其余探针。

| 阶段 | 函数 | 输入 | 动作与写出 | 输出落点 |
|---|---|---|---|---|
| 参数 | `parse_args` | argv | 解析 `--dev/--cgroup/--pid/--duration/--poll-interval/--out-dir/--json/--verbose`，校验 `--dev` 必填且过滤源至少一个 | 内存里的配置结构 |
| 设备解析 | `resolve_caching_dev` | `--dev` 值 | 块设备名直读 `/sys/class/block/<name>/dev` 的 `major:minor`；挂载点走 `stat` 取 `st_dev` 再 `major()`/`minor()` 拆；两者统一成内核 dev_t `major<<20|minor`；再按 `/sys/class/block` 补上所属整盘号与各分区号，一起写进 `watch_dev` | `watch_dev` 值 |
| cgroup 枚举 | `enumerate_cgroup_ids` | `--cgroup` 路径列表、`--pid` 列表 | 每个路径 `stat` 取 `st_ino`；每个 pid 读 `/proc/<pid>/cgroup` 的 `0::` 行拿相对路径，拼 cgroupfs 根后 `stat` 取 `st_ino` | 写进 `watch_cgroup` 集合 |
| 装载 | `open_load_attach` | skeleton | `skeleton__open()`、回填 `.data` 过滤器、`skeleton__load()`、`skeleton__attach()`；单个程序 attach 失败记录程序名继续 | 装载好的 skeleton |
| 时钟 | `sample_clock_offset` | 无 | 背靠背读 `/proc/uptime` 首项（秒，换纳秒）与 `clock_gettime(CLOCK_REALTIME)`，取 `offset = epoch_ns − uptime_ns` | run 记录 |
| 采集 | `poll_loop` | skeleton、`poll_interval` | `ring_buffer__poll` 收 filemap 事件存进用户态数组；每 `poll_interval` 用 `bpf_map_lookup_and_delete` 系迭代拉 `blk_hist`、`fault_agg` 并清零，按时间窗快照 | 内存事件缓冲与快照 |
| 配对 | `pair_readahead` | filemap 事件缓冲 | 见下「预读配对算法」 | readahead 指标结构 |
| 归因 | `attribute_faults` | filemap 事件缓冲 | `EV_FAULT` 消费页的进缓存 `EV_ADD` 发起者 pid 与之不符的标为疑似预读归因偏移，只计数不改记 | major_fault 指标结构 |
| 输出 | `emit_outputs` | 全部指标结构 | 序列化 `metrics.json`、写本轮 manifest | `--out-dir` |
| 摘要 | `emit_summary` | 全部指标结构、`rb_drop`、LRU 淘汰差值 | 终端打印四类头部数字各一行加丢事件与淘汰计数 | stdout |

`poll_loop` 的周期拉取靠 `clock_gettime(CLOCK_MONOTONIC_COARSE)` 记上次拉取时刻，到 `poll_interval` 触发一次拉取，不单独起定时器线程。`pair_readahead` 与 `attribute_faults` 只在 `poll_loop` 退出后跑一次全量。

### 预读配对算法

按（设备、inode）分组，`nsecs` 只做时间窗排序、不参与索引集合。

1. 建 added 集合：遍历 `EV_ADD`，每条把 `[index, index + 2^order − 1]` 并进该 inode 的进缓存索引区间表，页数累加 `2^order`。
2. 建 consumed 集合：`EV_FAULT` 把单个 `index` 并进消费区间表；`EV_GETP` 把 `[index, last_index]` 整段并进，页数累加 `last_index − index + 1`；read() 路径只出 `EV_GETP`，缺页路径只出 `EV_FAULT`，两者并集就是消费集合。
3. 求差：`consumed_pages` 取 consumed 与 added 的交集页数；`invalid_pages` 取 added 里不落在 consumed 的页数；`invalid_ratio_pct = invalid_pages / added_pages × 100`。consumed 里超出 added 的部分是本轮采集开始前已在缓存的页，不计入无效预读。

区间表用有序不重叠区间（interval set）实现，插入时合并相邻与重叠区间，配对阶段只在这张表上做集合运算，不逐页展开成位图。

## 命令行接口

参数名与语义固定，默认值在参数缺省时生效，用户手册按同一套写。

- `--dev PATH`：被观测缓存盘，可给块设备名或挂载点，`traintrace` 解析成编码设备号。必填。
- `--cgroup PATH`：被观测 Pod 或容器的 cgroup 路径，可重复，`traintrace` 对路径 `stat` 取 `st_ino` 作 cgroup id 填进过滤集合。与 `--pid` 二选一至少给一个。
- `--pid PID`：被观测进程 pid，`traintrace` 读其 `/proc/<pid>/cgroup` 反推 cgroup id，可重复。
- `--duration SEC`：采集时长，默认 60，0 表示常驻到 SIGINT。
- `--poll-interval SEC`：拉取聚合 map 的周期，默认 1。
- `--out-dir DIR`：指标文件与 manifest 落盘目录，默认当前目录下的 `traintrace-<起始epoch>-<pid>/`。
- `--json NAME`：指标文件名，默认 `metrics.json`。
- `--verbose`：每个采集周期往 `--out-dir/snapshots/` 追加一个快照文件，记累计头部数字供看走势，默认只打印最终摘要。

## 输出契约

指标文件是 JSON，字段与指标清单一一对应，是对外承诺，别人要照它解析，键名固定。

```jsonc
{
  "run": { "start_epoch_ns": 0, "uptime_epoch_offset_ns": 0,
           "dev": "nvme1n1", "duration_s": 60,
           "ringbuf_dropped": 0, "rq_start_evicted": 0 },
  "block_io": { "by_dev_rw": { "nvme1n1.read": { "bucket_ns_lo": 0, "bucket_ns_hi": 0, "count": 0 } } },
  "major_fault": { "readahead_agnostic": true, "readahead_attribution_offset": 0,
                   "by_cgroup_pid": { "12345/6789": { "pid": 6789, "comm": "reader", "count": 0, "mean_us": 0 } } },
  "readahead": { "complete": true, "by_dev_ino": { "nvme1n1:6588130": { "added_pages": 0, "consumed_pages": 0,
                         "invalid_pages": 0, "invalid_ratio_pct": 0 } } }
}
```

`block_io` 的桶是 log2 边界，`bucket_ns_lo` 是 `1<<k` 纳秒、`bucket_ns_hi` 是 `1<<(k+1)` 纳秒，指标里换算成 µs 展示。`major_fault` 带 `readahead_agnostic: true`，提醒这个计数是在被观测进程开着 fault-around 的前提下取的小值，关掉预读才会逐页成 major；`readahead_attribution_offset` 是疑似预读归因偏移计数，只标不改记。`readahead.complete` 在 ringbuf 丢事件时置 false，表示这一段不完整；`added_pages` 按 `Σ2^order` 算，`consumed_pages` 按 fault 每页计 1、get_pages 按 `last_index − index + 1` 计，`invalid_ratio_pct` 等于 `invalid_pages / added_pages × 100`。终端摘要打印四类各一行头部数字，加丢事件、淘汰与归因偏移计数，异常时另起注意行。

每轮另写一份 `manifest.json` 到 `--out-dir`，记本轮的身份与过滤集合：`start_epoch_ns`、`end_epoch_ns`、`uptime_epoch_offset_ns`、`duration_s`（按起止 epoch 差算出的实测采集时长）、`duration_configured_s`（`--duration` 给的秒数，0 表示常驻）、`dev`、`raw_dev`、`watch_devs`（这轮收的整盘号与各分区号）、`poll_interval_s`、`cgroups`、`pids`、`ringbuf_dropped`、`rq_start_evicted`、`filemap_complete`、`probes_attached`、`attach_failures`、`metrics_file`。两次同参数运行靠它核对是否可比。事件 `nsecs` 加 `uptime_epoch_offset_ns` 换算成 epoch 后应落在 `start_epoch_ns` 到 `end_epoch_ns` 之间，残差在采样间隔量级。

## 关键取舍

- 块延迟与 fault 计数在内核按维度聚合、filemap 走 ringbuf 到用户态配对。延迟和 fault 是纯计数与直方图，内核聚合能扛住每秒数万次的热路径而不把事件全量搬到用户态；预读判定要按页索引做集合差，放用户态实现更清楚，且进缓存事件按 folio 触发，一次 128MB 读只有千级条事件，ringbuf 扛得住。
- 配对表用 `LRU_HASH`，不写自建定时器。bpf 侧没有廉价的全表定时扫描，靠 LRU 的条目上限限制住 issue 无 complete 的泄漏，代价是压力下先淘汰最旧未配对项，那笔延迟不计入直方图。内核没有逐 map 淘汰计数可读，用 `issue − complete 配对成功 − 残留` 推导出被淘汰数记进 manifest。
- libbpf 以 submodule 引入并静态链接。构建机上的 libbpf 只有运行时库没有头文件，目标节点上没有包管理器，vendor 加静态链接才能出单一自包含二进制，也锁死 libbpf 版本与骨架匹配。
- comm 在用户态按 pid 查 `/proc`，不进内核 map 键。comm 是高基数字符串，塞进内核哈希既占空间又要定长截断，poll 时补一次成本可忽略。
- 归因偏移只标注不改判。一条缺页消费的页若由别的 pid 预读进缓存，标为疑似预读归因偏移、计数留在原进程名下，内核与用户态都不做猜测性改记，避免把预读的代价错算到某个消费者头上。块侧直方图不带逐事件发起者，这个比对落在 filemap 的 `EV_ADD` 与 `EV_FAULT` 之间。
- 设备匹配统一走内核 dev_t。块 tracepoint 的 `dev` 是内核 `dev_t`，打印按 `major = dev>>20`、`minor = dev & 0xfffff` 解码，`watch_dev` 存同一 dev_t，块程序入口直接比 dev 字段，两侧都比 dev 值，不拿名字字符串比。同一块盘上块层报整盘号、文件系统报分区号，两个号都写进 `watch_dev`，manifest 的 `watch_devs` 记下这一组号。

## 常见错误

- 把 `mm_filemap_add_to_page_cache` 事件条数当页数。这台内核按多页 folio 触发，页数要 `Σ2^order`，数事件会低估几十倍，无效预读比例会整体失真。
- 把 major fault 少当成没冷读。fault-around 开着时一次 128MB 冷 mmap 可能只报个位数 major，报数必须带被观测进程有没有关预读这个前提。
- 只收 `mm_filemap_fault` 当消费。read() 路径只触发 `mm_filemap_get_pages`、不触发 `mm_filemap_fault`，缺页路径反之，消费集合要两个都并进。
- 拿设备名直接比。块与 filemap 事件里是编码设备号，与 `--dev` 传入的名字要先同一方式编码再比，否则一条都匹配不上。
- cgroup id 与 pid namespace 混用。事件里的 cgroup id 是宿主机级、与命名空间无关，对 cgroupfs 里该 cgroup 的目录 `stat` 取 inode，不用容器内 pid 去比。
