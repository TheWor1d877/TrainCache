# traintrace 使用手册

`traintrace` 是放在被观测节点上直接跑的单个静态二进制，只读，挂上块 I/O、major fault、filemap 三类探针，采一轮数据后写出 `metrics.json` 并在终端打印本轮摘要，不出图、不生成额外报告。每台机器各跑各的，采本机内核事件，不做跨机聚合。

## 前置条件

被观测负载和 `traintrace` 在同一台 Linux 机器上，共享同一个内核，`traintrace` 从这台机看到的块 I/O 与缺页事件即覆盖该内核上所有进程。机器需要满足：内核导出 `/sys/kernel/btf/vmlinux`（CO-RE 靠它重定位，缺装载会失败并在终端逐程序报错）；`traintrace` 以 root 运行，或进程具备 `CAP_BPF` 与 `CAP_PERFMON`；机器上不需要 Python、不需要预装 libbpf。

运行前准备好两样东西：被观测缓存盘的块设备名或挂载点，以及被观测容器或进程的 cgroup 路径或 pid。cgroup 路径末段是一个十六进制 inode，`traintrace` 取它做过滤键，覆盖该容器内全部进程；给 pid 时它从 `/proc/<pid>/cgroup` 反推同一个值。

## 运行

把二进制拷到目标机加执行权限，给一条最小命令：

```sh
traintrace --dev /dev/nvme1n1 \
           --cgroup /sys/fs/cgroup/kubepods.slice/.../podUID \
           --duration 60 --out-dir /var/log/traintrace
```

`traintrace` 装载探针后采 60 秒，到点或被 Ctrl-C 打断都收尾：做最后一次全量拉取，把事件配对算出指标，写 `/var/log/traintrace/metrics.json`，终端打印摘要。`--dev` 可给块设备名或挂载点，`--cgroup` 与 `--pid` 至少给一个、都可重复，用来界定归因范围。

## 参数

| 参数 | 含义 | 默认 |
|---|---|---|
| `--dev PATH` | 被观测缓存盘，块设备名或挂载点，解析成编码设备号 | 必填 |
| `--cgroup PATH` | 被观测容器或 Pod 的 cgroup 路径，可重复 | 与 `--pid` 至少给一个 |
| `--pid PID` | 被观测进程 pid，反推其 cgroup，可重复 | 与 `--cgroup` 至少给一个 |
| `--duration SEC` | 采集秒数，0 表示常驻到 Ctrl-C | 60 |
| `--poll-interval SEC` | 拉取内核聚合表的周期 | 1 |
| `--out-dir DIR` | 指标文件落盘目录 | 当前目录下 `traintrace-<起始epoch>-<自身pid>/` |
| `--json NAME` | 指标文件名 | `metrics.json` |
| `--verbose` | 每个周期额外把快照追加写进 `--out-dir/snapshots/` | 关闭 |

## 输出

终端摘要一行一类指标，最后一行给运行元信息：

```text
block I/O   nvme1n1 read p50≈48µs p99≈110µs max≈2ms (1017 pairs)
major fault cgroup .../pid 6789 reader: count=32768 mean=?  (readahead on: 计数随预读摊薄)
readahead   nvme1n1:6588130 added=32768p consumed=21952p invalid=10816p (33.0%)
ringbuf dropped=0  rq_start evicted=0  run 60s
```

`metrics.json` 是完整指标，字段与三类观测一一对应，是给人或脚本解析的稳定格式。`block_io` 存每个设备读/写的 log2 延迟桶边界与计数；`major_fault` 按 cgroup、pid 存次数和平均耗时，并带 `readahead_agnostic` 标记说明这个次数是在被观测进程开着预读时取的值；`readahead` 按设备、inode 存进缓存页数、被消费页数、无效页数与比例；`run` 段记录本轮的时钟偏移、运行时长、ringbuf 丢事件数、配对表淘汰数与生效的过滤集合，跑两次同参数可用它核对是否可比。`--verbose` 下 `snapshots/` 里每个周期一个文件，看指标随时间的走势。

## 三类数读法

块 I/O 延迟是内核把请求发给块层到请求完成的耗时，读/写分开，单位 µs，看 p50/p99 判断缓存盘的响应分布。它统计的是所有被过滤设备命中的请求，与哪个进程发起无关，进程级归因靠时间戳对齐到 `major_fault` 与 `readahead`。

major fault 次数只有在被观测进程关掉预读（`madvise(MADV_RANDOM)` 一类）时才接近冷读的页数；内核默认的 fault-around 会把相邻页一次带进来，后续访问算 minor fault，major 计数因此偏小，`readahead_agnostic` 标出这个前提。预读产生的 major fault 有时记不到真正消费它的进程名下，指标把这类标为疑似归因偏移、留在原进程名下不改记。

预读无效比例是进缓存的页里最终没被消费的比例，按 `Σ2^order` 换算页数（进缓存事件按多页 folio 触发，数事件条数会严重低估）。顺序读到文件尾常有最后一窗预读越界，计入无效预读，量级正常。

## 读数异常

`ringbuf dropped` 非零说明 filemap 事件来得比用户态消费快，`readahead` 段的页数偏小、该轮不完整，缩小过滤范围或调低 `--poll-interval` 再采。`rq_start evicted` 非零说明大量请求 issue 后没等到 complete、被 LRU 挤出，块延迟直方图会少计这一部分，算一条采集提示。某一类终端报「未出数」且伴随装载失败，多为该机内核无 BTF 或权限不足，`traintrace` 跳过失败程序、其余探针照常工作。`--dev` 给的名字解析不到编码设备号会立刻报错退出，不静默采空盘。

## 停止

`traintrace` 收到 SIGINT 或 `--duration` 到点即退出，退出前完成最后一次拉取与配对并落盘。`--duration 0` 常驻时它一直采到被信号打断。工具全程只读，不改动被观测进程、文件或缓存盘，任何时候 kill 都不留下需要清理的内核侧状态。
