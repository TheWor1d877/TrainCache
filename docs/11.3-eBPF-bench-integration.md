# bench 接入

bench 在这套工具里只承担一个角色：提供被观测的读负载，给出一轮跑分的产物目录。工具本身不依赖实验装置，装到任何一台跑 Linux 的机器上都能采数；在 bench 这边它是挂在负载旁边的独立进程，与负载并行运行，通过时间戳对齐，不写进 TrainCache 内部日志。

## 接入点

`bench/experiments/run.py` 的 train 形态流程：第 2 步冷态、第 3 步挂 tc、第 5 步跑 `load_train.py`。工具在第 5 步之前拉起，负载结束发 SIGINT 收尾，拉起与收尾的代码在 `bench/experiments/probe.py`。

探针在冷态与 tc 之后才拉起，冷态本身写下的页不进这轮的块延迟直方图。

工具的产物落进同一个 run 目录：`metrics.json`、`manifest.json`、`traintrace.log` 与负载侧的 `per_step_<seed>_w<workers>.jsonl`、`epochs_meta.json`、`run.json` 并排。

## 探针开关不进 COND

COND 的字段有白名单校验，探针开关写进 COND 会让两遍的负载配置不再逐字相同，差值里就混进了配置差异。开关走运行参数，同一个 COND 跑两遍，一遍挂探针一遍不挂。

## 运行参数

| 环境变量 | 含义 | 默认 |
|---|---|---|
| `TRAINTRACE_PROBE` | 挂不挂探针，`1`、`true`、`yes` 为挂 | 不挂 |
| `TRAINTRACE_BIN` | traintrace 二进制路径 | `ebpfobs/build/traintrace` |
| `TRAINTRACE_DEV` | 被观测缓存盘，块设备名或挂载点 | 必填 |
| `TRAINTRACE_CGROUP` | 被观测容器的 cgroup 路径，逗号分隔 | 与 `TRAINTRACE_PID` 至少给一个 |
| `TRAINTRACE_PID` | 被观测进程 pid，逗号分隔 | 与 `TRAINTRACE_CGROUP` 至少给一个 |
| `TRAINTRACE_DURATION` | 采集秒数，0 表示采到收到 SIGINT | 0 |

工具要 root 或 `CAP_BPF` 与 `CAP_PERFMON`。runner 不是 root 时，`bench/.sudo-pass` 存在就经 `sudo -S` 拉起。

## 开销主口径

主口径是两遍 `wait_s` 的 P99 差值，单位 ms。`wait_s` 是取数等待时长，`load_train.py` 把它写进 per_step jsonl 的每一行；探针挂在块 I/O 与缺页路径上，代价落在这项上。

load 侧不改，统计在 bench 侧补：

```sh
python3 bench/experiments/probe_overhead.py --off <run_dir_off> --on <run_dir_on> --out probe_overhead.json
```

口径细节：只取非 warmup 步，与 `load_train.py` 的 stall 统计同口径；P99 用 numpy percentile 的线性插值；目录里有多个 `per_step_*.jsonl` 时合并。

交叉核对两项：`metrics.csv` 的 `full_makespan_s` 差值、全轮 `median_stall` 差值。

不变量两项：`total_fetch_bytes` 与 `hit_ratio_steady`。探针只读，这两项两遍之间应当基本一致；变了说明两遍不可比，开销数据作废。这两列来自 TrainCache 的 Prometheus 计数器，train 形态没有 TrainCache 时 `collect.py` 写空值，此时输出「不可核对」，不当作通过。

## 两种形态的 cgroup 口径

train 形态：训练进程经 HTTP 从源站容器取数，文件页缓存的消费方是源站容器里的 nginx 进程，不是训练进程。`TRAINTRACE_CGROUP` 与 `TRAINTRACE_PID` 指源站容器里的进程。块 I/O 按设备过滤，统计的是这块盘上的全部请求，与哪个进程发起无关。

dataset 形态：消费方是消费者 Pod 里的进程。Pod 会被重建，cgroup id 跟着变，取 Pod 当前进程的 pid 反推。

## 最小实验

宿主上跑的最小实验，不占集群：数据集用 `bench/scripts/synth_train.py` 生成小分片，源站用独立 nginx 容器，负载用 `load_train.py` 短跑，两遍差别只在挂不挂探针。跑法与产物在 `~/tcd/traintrace-mini/`。

一轮的实测数字（`iter4/`，数据集 2 分片 × 400 张，负载 50 个非 warmup 步）：

| 项 | 关探针 | 开探针 |
|---|---|---|
| `wait_s` P99 | 6.518 ms | 6.206 ms |
| 全轮 `median_stall` | 0.020 | 0.016 |

差值：P99 −0.312 ms，`median_stall` −0.004。开探针那遍更快，说明这一轮里探针的代价落在取数等待的噪声以下；这轮负载跑在本地 nginx 上、步数只有 50 步，量不出探针的代价。

开探针那遍探针自己的数：采集 9.193 s，filemap 事件 3715 条，ringbuf 丢事件 0，配对表淘汰 11；块延迟直方图 `nvme0n1.read` 9675 笔、`nvme0n1.write` 579 笔；预读侧两个分片的 inode 各进缓存 1288 页，一个全被消费（无效 0 页），一个消费 1260 页、无效 28 页（2.17%）；major fault 记到 4 个 (cgroup, pid) 组合。

## 验收状态

- 探针在负载旁路拉起、随负载结束收尾，产物落进 run 目录：已验证。
- 三类观测在同一轮负载里同时出数：已验证。
- 开/关两遍给出 `wait_s` P99 差值：已验证。
- 不变量两项在容差内：train 形态拿不到这两列，输出「不可核对」；要判这一项得在 dataset 形态的集群里跑两遍。

## 自检

```sh
python3 bench/experiments/probe.py --selftest          # 拉起、SIGINT 收尾、进程组信号
python3 bench/experiments/probe_overhead.py --selftest  # 差值口径与不变量判定
python3 bench/experiments/stats.py --selftest          # P99
```

`probe.py` 的自检用假二进制跑，不需要 root，也不碰集群。
