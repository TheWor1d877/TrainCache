# bench 接入

bench 在这套工具里只承担一个角色：提供被观测的读负载，给出一轮跑分的产物目录。工具本身不依赖实验装置，装到任何一台跑 Linux 的机器上都能采数；在 bench 这边它是挂在负载旁边的独立进程，与负载并行运行，通过时间戳对齐，不写进 TrainCache 内部日志。

## 接入点

`bench/experiments/run.py` 的 train 形态流程：第 2 步冷态、第 3 步挂 tc、第 5 步跑 `load_train.py`。工具在第 5 步之前拉起，负载结束发 SIGINT 收尾，拉起与收尾的代码在 `bench/experiments/probe.py`。

探针在冷态与 tc 之后才拉起，冷态本身写下的页不进这轮的块延迟直方图。

工具的产物落进同一个 run 目录：`metrics.json`、`manifest.json`、`traintrace.log` 与负载侧的 `per_step_<seed>_w<workers>.jsonl`、`epochs_meta.json`、`run.json` 并排。

## dataset 形态的接入点

集群内跑分的 COND 用 `bench/experiments/probe_dataset.py` 驱动：`--cond` 给 COND 名，`--reps` 给重复次数，`--out-root` 给产物根。加 `--probe` 时另起一个 watcher 盯测量 Pod（`traincache` 命名空间的 `train-job-0`），Pod 起来就往它所在的 kind 节点里挂探针，Pod 结束发 SIGINT 收尾，产物落 `<格子>/probe/rep-NN/`。

kind 节点用私有 cgroup 命名空间，宿主上看不到测量 Pod 的 cgroup 树，探针只能进节点容器里跑。watcher 拿 Pod 的容器 id 到节点上找 cgroup 目录，按节点磁盘的块设备名过滤块 I/O。节点容器的 `/tmp` 与 `/run` 是 noexec 的 tmpfs，二进制落在 `/var/tmp`。

## 探针开关不进 COND

COND 的字段有白名单校验，探针开关写进 COND 会让两遍的负载配置不再逐字相同，差值里就混进了配置差异。开关走运行参数，同一个 COND 跑两遍，一遍挂探针一遍不挂。

## 运行参数

| 环境变量 | 含义 | 默认 |
|---|---|---|
| `TRAINTRACE_PROBE` | 挂不挂探针，`1`、`true`、`yes` 为挂 | 不挂 |
| `TRAINTRACE_BIN` | traintrace 二进制路径 | `ebpfobs/build/traintrace` |
| `TRAINTRACE_DEV` | 被观测缓存盘，块设备名或挂载点 | 必填 |
| `TRAINTRACE_CGROUP` | 被观测容器的 cgroup 路径，逗号分隔 | 与 `TRAINTRACE_PID` 至少给一个 |
| `TRAINTRACE_PID` | 被观测进程 pid，逗号分隔 | 与 `TRAINTRACE_CGROUP` 至少给一个 |
| `TRAINTRACE_DURATION` | 采集秒数，0 表示采到收到 SIGINT | 0 |

工具要 root 或 `CAP_BPF` 与 `CAP_PERFMON`。runner 不是 root 时，`bench/.sudo-pass` 存在就经 `sudo -S` 拉起。

## 开销主口径

主口径是两遍 `wait_s` 的 P99 差值，单位 ms。`wait_s` 是取数等待时长，`load_train.py` 把它写进 per_step jsonl 的每一行；探针挂在块 I/O 与缺页路径上，代价落在这项上。

load 侧不改，统计在 bench 侧补：

```sh
python3 bench/experiments/probe_overhead.py --off <run_dir_off> --on <run_dir_on> --out probe_overhead.json
```

口径细节：只取非 warmup 步，与 `load_train.py` 的 stall 统计同口径；P99 用 numpy percentile 的线性插值；目录里有多个 `per_step_*.jsonl` 时合并。

交叉核对两项：`metrics.csv` 的 `full_makespan_s` 差值、全轮 `median_stall` 差值。

不变量两项：`total_fetch_bytes` 与 `hit_ratio_steady`。探针只读，这两项两遍之间应当基本一致；变了说明两遍不可比，开销数据作废。这两列来自 TrainCache 的 Prometheus 计数器，train 形态没有 TrainCache 时 `collect.py` 写空值，工具此时输出「不可核对」，不当作通过。

dataset 形态的这两列在跑分产物的 `summary.csv` 里，列名分别是 `fetch_bytes_run` 与 `hit_ratio_steady`。`probe_overhead.py --form dataset` 按格子目录读 `runs/*/per_step_*.jsonl` 与 `summary.csv`，取这两列做核对：

```sh
python3 bench/experiments/probe_overhead.py --form dataset --off <格子_off> --on <格子_on> --out probe_overhead.json
```


## 两种形态的 cgroup 口径

train 形态：训练进程经 HTTP 从源站容器取数，文件页缓存的消费方是源站容器里的 nginx 进程，不是训练进程。`TRAINTRACE_CGROUP` 与 `TRAINTRACE_PID` 指源站容器里的进程。块 I/O 按设备过滤，统计的是这块盘上的全部请求，与哪个进程发起无关。

dataset 形态：消费方是消费者 Pod 里的进程。Pod 会被重建，cgroup id 跟着变，取 Pod 当前进程的 pid 反推。

## 开销实测

宿主上的一次对照跑：数据集是 `bench/scripts/synth_train.py` 生成的 2 个分片共 800 张 512px JPEG，源站是独立 nginx 容器，负载是 `load_train.py` 跑 50 个非 warmup 步，两遍差别只在挂不挂探针。

| 项 | 关探针 | 开探针 |
|---|---|---|
| `wait_s` P99 | 6.518 ms | 6.206 ms |
| 全轮 `median_stall` | 0.020 | 0.016 |

探针挂在负载旁时 `wait_s` P99 反而低 0.312 ms，`median_stall` 低 0.004，差值落在这一轮负载的噪声以内，这轮 50 步的本地负载量不出探针的代价。

开探针那遍探针自己的数：采集 9.193 s，filemap 事件 3715 条，ringbuf 丢事件 0，配对表淘汰 11；块延迟直方图 `nvme0n1.read` 9675 笔、`nvme0n1.write` 579 笔；预读侧两个分片的 inode 各进缓存 1288 页，一个全被消费（无效 0 页），一个消费 1260 页、无效 28 页（2.17%）；major fault 记到 4 个 (cgroup, pid) 组合。

dataset 形态的一次对照跑：kind 集群 `tcprobe`（1 个 control-plane 加 2 个 worker），COND `compare-traincache-cold-rho1-1000`，traincache-cold 组，16 个分片共 4 GiB，块 8 MiB，3 个 epoch，每个 epoch 400 步。同一个 COND 跑两遍，各 3 轮，一遍不挂探针，一遍挂节点内探针。

| 项 | 关探针 | 开探针 |
|---|---|---|
| `wait_s` P99 | 0.018 ms | 0.019 ms |
| 参与统计的步数 | 3570 | 3570 |
| `total_fetch_bytes` | 4239267840 | 4239267840 |
| `hit_ratio_steady` 均值 | 0.9865 | 0.9906 |
| `full_makespan_s` 均值 | 269.767 | 266.950 |

主口径差值 `wait_s` P99 为 +0.001 ms，交叉核对的 `full_makespan_s` 差值为 -2.817 s。不变量两列都在容差内（`total_fetch_bytes` 相对差 0.0%，`hit_ratio_steady` 绝对差 0.0041，容差分别是 1% 与 0.02），工具判定两遍可比，开销数据成立。

这轮负载的取数等待由 agentd 预取供给，训练侧几乎不等块，`wait_s` P99 落在 0.02 ms 量级，这一列的分辨率低于探针的代价。关探针那遍三轮的全轮 makespan 自差 7.6 s，开关探针的差 2.8 s 在轮间噪声以内。这个负载量下看不出探针对被观测负载的影响。

挂探针那三轮探针自己的数：采集 267.0、269.9、267.0 s，ringbuf 丢事件 0、0、0，配对表淘汰 1304、1455、1659；块 I/O 读事件 105072、188435、214152 笔，写事件 123850、121537、123631 笔；major fault 分别记到 94、245、257 个 (cgroup, pid) 组合，共 7409、10181、10742 次；预读侧 16 个分片的 inode 各进缓存 2048 到 2049 页，全部被消费，无效 0 页。

产物在数据层：`~/tcd/bench/results/probe-overhead/` 下 `off3`、`on3` 两个格子目录与 `overhead-dataset.json`。


## 自检

```sh
python3 bench/experiments/probe.py --selftest          # 拉起、SIGINT 收尾、进程组信号
python3 bench/experiments/probe_overhead.py --selftest  # 差值口径与不变量判定
python3 bench/experiments/stats.py --selftest          # P99
```

`probe.py` 的自检用假二进制跑，不需要 root，也不碰集群。
